## 3. 真实入口与输入输出契约

当前有限模型拟合CLI为：

```bash
python -m experiments.cat_auto_protocol_cmcc_20261104.search \
  --request <frozen-request.json>
```

它一次在一张卡顺序执行1–4个**显式候选**。不同卡可各跑独立request，但每批都绑定实际资源／共同deadline，不因此创建自动重试服务。没有`--full20`、`--full8`、`--resume-search`等顶层参数；`--worker`是内部子进程参数。

request由真实对象生成，不能照抄CPU fixture授权、费用或无限cap。字段权威定义是[search.validate_request](../experiments/cat_auto_protocol_cmcc_20261104/search.py)：

| 字段 | 绑定内容 |
| --- | --- |
| `schema,phase` | `cat_auto_explicit_candidates_v0`；`technical_validation`或`formal` |
| `inventory_receipt,inventory_receipt_sha256,data_plan,data_plan_sha256` | 实际文件及SHA |
| `run_identity,parent` | 完整身份；当前有限runner只允许`parent={kind:"BF16",path,uuid,weights_digest}` |
| `candidates[]` | 1–4项`candidate_id,recipe,purpose,complete_dependency_gpu_hours,cost_basis`；purpose为`profile/offline` |
| 离线候选附加 | `class_cap_bits`；formal还要真实`class_cap_evidence={path,sha256}` |
| 预算／输出 | 新`output_dir`、`authorized_start_epoch,absolute_deadline_epoch,authorized_gpu_hours,physical_GPU,authorization_reference,shared_overhead_gpu_hours` |
| `source_sha256` | 本包所有Python文件及实际相关消费者的绝对路径／SHA；实际fit／consumer身份也独立核对 |
| 技术／正式分支 | 技术为`technical_steps=1/2`；正式为null并提供`required_model_path_evidence={path,sha256}` |

`authorization_reference`引用真实已确认指示，不是填了字符串就取得授权。当前实现硬限制1/3/4/5、保护0/2/6/7；这是当次实现边界而非空闲检测或未来永久卡表，须查最新源码与实际占用。调用者设置准确`CUDA_VISIBLE_DEVICES`及`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`，不能抢占其它任务。

实际输出：批目录`request.json,process.json,worker.log`，成功有`completed.json`，正常退出有`exit.json`；每候选有`fit_report.json,category_bank/,raw_model/,result.json`。超时不保证有exit文件，不能仅凭文件缺失或PID消失判断成功／质量。

formal成功scope为`actual_model_GPU_complete_fit_proxy_not_full8`，`complete_full8_evaluated=false`；含fit、packed bank、512 KL、逐层功能读出、actual ledger及fresh证据，**不含完整八项**。technical实际scope为`actual_model_GPU_fixed_schedule_technical1/2`；CPU／technical产物永不进入正式排名。

现有接线顺序为：复用／生成自身BF16收据→`results`核原worker→`evaluate --component prepare`冻结评测plan→在已确认费用／卡／deadline内`evaluate --component run`→`results --summary … --evaluation …`回填真实八项→控制器按本协议决定下一块。完整模块名、必需路径／SHA和实际命令只维护于[接线包使用说明](../experiments/cat_offline_execution_cmcc_20261104/README.md#使用实际收据)，不把这些子入口写成不存在的全流程开关。CPU准备不等于GPU启动；现有profile不会自动追加评测。

当前Qwen历史BF16收据能核模型／tokenizer来源及完整任务指标，明确`quality_reference_verified=true`、`ordered_pairing_verified=false`：原逐题未保存，不能声称与新候选逐题配对，也不为补日志自动重评。新候选间保留真实有序输入身份；迁移另一模型必须取得它自身的基线／协议收据，不能沿用Qwen的固定来源路径。该收据和两个CPU核证的范围／来源见[现有证据](../experiments/cat_offline_execution_cmcc_20261104/README.md#实际cpu证据)，没有调用完整八项计算新分数。

## 5. 搜索推进的状态机

下表是已确认20配置标准要求的逻辑步骤，不是现有CLI／schema已经完整支持的声明；也不更改另一批已批准的19点执行器。旧S0–S13固定槽图已归入[历史](experience/history/w25_transfer/2026-11-05_cat_static_slots.md)，旧槽名不能直接解释为新步骤。

每次选择在同一持久状态内记录：规则和输入身份、完整冻结候选集合、各自有效／复用／未覆盖／未完成状态、原精度八项与真实费用、比较键、当前赢家、允许执行的下一步、实际预算及未完成依赖。生成候选后先冻结再分发，不按GPU完成先后重抽。此为执行要求，不虚构已有接口字段。

| 步骤／依赖 | 动作与完成条件 |
| --- | --- |
| S0 输入冻结 | 绑定模型、统一数据、评测、源码／消费者、种子、预算及共同BF16对照；缺必要对象只暂停受影响依赖 |
| S1 单类码率粗查 | 各类按统一anchor分别完成r=2／2.5／3的真实完整拟合、费用与八项，适用已有结果直接复用 |
| S2 联合方案与类别预算 | 按主协议§4完成两轮至多4＋4个真实联合方案的八项选择，按已选实际费用与Nc分配并冻结类别预算，不跨类借额 |
| S3 类别起点 | 将该类选定码率下的合法anchor设为当前配置；完整身份匹配时复用profile bank及八项 |
| S4 保护 | 按主协议§3.2生成保护候选，逐层确认实际数量为`codebook_dim`整数倍并满足当前几何／费用；与当前配置的八项齐备后选优 |

| S10 优化器 | 使用已选压缩与网络设置比较AdamW／Muon，按各自既定更新倍率定义，完整八项选优 |

| S12 类别关闭 | 核所有实际有效候选八项齐备，最多20配置；按主协议§2.1从全轮次不同配置确定第一／第二名，另保留基准记录、覆盖和成本 |

S3–S12按类别独立运行。同类当前轮候选可并行；下一参数等本轮完整结果，不以fit完成、代理分数或先完成者提前晋级。已有适用指标不重评；数学非法／超预算点保留未覆盖原因，技术失败或未完成八项不能装作终态排除，也不能释放名额追加新变量。缺失八项继续处理原artifact；修复重跑仍是同候选，另计实际成本，按§7记录和接续。

每轮统一按`(-S8, logical_bits, packed_bits, 非当前配置标记, stable_config_id)`选优：最高八项优先，精确同分先省空间，再保留当前。无提高不提前停止整个类别；完成预定顺序及必要逐层混合比较才关闭，不自动加种子、回访或BSQ对照。独立`selection`已有完整集合／八项及未完成依赖检查组件，但旧19点限制和其它比较键仍须按该标准核对，不能假定写入文档就已完成适配。

proposal KL只作已有诊断及已定类别精确同分读出，不参与参数筛除。五源权重已用于固定512记录的抽样，不再次乘source权重；每token沿原top100＋outside-mass、T1、response权重1／prompt权重.3，最后累计总numerator／有效token权重。逐层转置选择使用同一固定512条的完整样本；每层按总SSE／有效输出元素数计算MSE，不沿用两半偏好一致门槛，也不套用KL的token权重。旧读出若分前后256条保存，须合并SSE与有效元素数，不直接平均两个MSE；缺计数按未完成处理。输出误差与KL分别记录，不混作同一指标。权威实现：[proposal_readout.py](../experiments/cat_auto_protocol_cmcc_20261104/proposal_readout.py)。

## 6. 完整八项与逐层转置选择必须可核对

新标准有效完整拟合候选每类至多20个（含1个逐层混合），均有自身完整八项；当前已选配置及适用指标直接复用。旧第16空槽／第20槽交互的分配不再定义标准名额；另一批已批19点实验仍按自己的范围验收。评测失败／不完整不是0分，不据此另挑配置替代；指标按原始精度比较，不新增显著性阈值或自动seed搜索。

共同`protocol_identity`只含任务／版本／metric／样本／prompt及执行条件，不含候选UUID、checkpoint metadata SHA、候选计划路径／SHA或结果路径；后者逐候选另建artifact证据绑定。不能把`load_complete_eight_score`整个候选专属manifest一起hash成共同协议，否则相同评测条件也会被误判不一致。

逐层混合以[主协议§8](sc_cat_protocol.md#layerwise-transpose)为唯一规则：每层使用原BF16产生的相同输入比较A／B的真实输出MSE，较小者决定C中该层方向；权重误差仅记录，精确同分保留进入转置轮时的方向。新的合法C重新完整拟合，三份配置完整八项选优后再进入旋转；重复则复用，不适用则记原因。A／B可并行，C拟合只依赖其拟合和逐层读出，可与A／B八项评测并行。真实实现须保持全类别M和BSQ训练语义；旧浅／中／深稳定性规则退出，现成逐ref字段不代表新流程已跑通。

核心`freeze_class_order`只核各类内部协议，BF16还是裸分数输入；独立`results.freeze_order`已有跨类别及BF16共同protocol、模型／tokenizer与512教师身份检查的封装，须走这条真实绑定路径，不能直接绕回裸分数接口。完整全类关闭／排序正例仍待核证。类别顺序保留原已选`(d_c,同512教师KL,稳定ID)`；只有d_c完全同分才用KL，不能让它推翻八项差异。需要KL破同分而证据缺失时补相同合同的读出，不用任意数补位。函数返回值不替代最终summary／order的持久保存。

## 7. 失败、暂停、复用与恢复

运行状态和六类覆盖状态分开：`tested/matched_reuse/math_invalid/impl_blocked/budget_deferred/v0_fixed`描述覆盖；fit／八项是否完成、错误原因和可选资格另存，不能把worker完成当作完整测试。

| 情况 | 下一动作与结论边界 |
| --- | --- |
| 几何非法／预算预测超cap／实现受阻 | 固定原因和未覆盖项，不启动该候选、不自动改K／保护／B／dtype，不算低质量分数 |
| 实际账本超cap | 不入排名；核预测／实际合同差异，不向其它类别借额度，修明影响前保留其它独立结果 |
| 数值非有限 | 停止该候选并保留真实失败；无有效分数，不加clip／改精度掩盖，也不以NaN排序。anchor不可用则本类受阻 |
| 运行异常／fresh不一致／冻结字段受损 | 暂停共享异常路径的依赖，定位实现并按规则隔离修复；无自动重启。其它独立路径可继续，失败不能当质量淘汰 |
| 八项少叶／协议或UUID不匹配 | `evaluation_pending/invalid`，补失败的评测依赖，不重训已完整验证的fit，不填零或借别候选分数 |
| GPU／磁盘／期限或剩余预算不足 | 不启动无法完成全部依赖的候选；记录预算递延／实际消费，保留在途已授权任务，不占卡等待、不抢其它任务 |
| KL差、八项好或反之 | 质量选型按完整八项，KL仅诊断及原跨类八项完全同分用途；不临时改主指标／追加臂。诊断异常查明实际影响，不能直接记质量淘汰；真实模型数值异常仍按数值失败处理 |

数学非法／超cap可按明确原因终态排除；已定位为该配置自身的数值失败可关闭，但无质量分数。原因未明且可能影响共享路径时暂停相关依赖，不把它当“该超参不好”继续选。必选能力`impl_blocked`须补能力或按协作规则明确缩小范围，不能自动升级为完整协议完成。

补评绑定原候选、原协议和剩余预算，不自动无限重试。新标准每类离线最多20个不同配置（19基础＋1逐层混合），未使用的逐层混合名额不转用；另一批已批准的19点实验保留自身上限。同配置补缺不增加配置数，但失败／补评实际GPUh全部计费。profile拟合／八项各另≤3C、joint八项另≤8（两轮各≤4），不挤入HPO额度后漏费。预算不足保留pending／incomplete，不能以“还没成功一次”为由把已花费用清零。

重启时先读持久槽表及真实进程身份；已冻结槽不重生成，完成的fit／读出／评测按身份复用，只执行未完成且依赖齐备的工作。旧VAE loop没有通用中途exact-resume，不能拿短包或raw模型冒充optimizer续训；确需重跑用新输出，计入实际GPUh，原失败记录保留。源码／父／数据变化必须新身份，不能继续混合旧分数。

接续说明写明“当前S状态→已冻结但尚未完成的原槽／任务→缺失证据或待答规则→下一项可执行动作”，并附原进程／产物引用；复用现有持久状态，不每次另建交接文件。有正在运行的原任务时先确认其状态，不重复启动同候选。全部fit已完成而full8未齐时，下一动作是接原artifact评测；某块已闭合而下一块生成规则未审时，下一动作是确认该规则，不重新搜索上游。

产物清理按真实依赖执行：待八项／joint安装／全类关闭核证／live接续引用的bank、raw与节点不能因当前分数低就删除；末类两个入围端点须保留到各自LB及九项选品完成。已有选择证书不自动解除它仍引用的实际文件依赖，先核后继reader／校验器是否还需读取。依赖关闭后按AGENTS保留配置、核心日志、原始指标及复现信息，权重仅保留已安排用途；不为本协议另建清理器或长期监控服务。

未知单价与完整图预算分开：已有适用实测直接复用；缺模型／资源路径证据时先形成明确有界成本pilot，技术1/2步仅验证路径，完整profile才能提供相应实际费用。正式恢复按[两批预算规则](sc_cat_protocol.md#recovery-budget-batches)先确定首类完整范围及额度，首类完成后再讨论剩余类别；不能因整链总价尚未确定否定已获批的首类，也不能据首类授权自动运行后续。离线完整图unknown不准自动全搜索；新标准C=7最多140离线＋21profile＋14live＝175拟合，全部固定S2；另行批准的19点批次保持原上限，不自动扩额。有限pilot也必须有真实范围、费用上限和期限，不能复制fixture预算。总预算到顶是研究停止，不是找到最优的证明。

### 8.1 LLM按表执行的固定流程

用户2026-11-05明确要求：LLM拿到模型与仓库后先读规范，再逐项记录各类别、各设置的效果，按结果得到入选配置，接正式一阶段压缩。执行时维护本批一份持久状态、一份结果记录；下面三张表是同一记录的明细／汇总视图，不另建三套手工状态。原始配置和指标是事实来源，表格据其更新，不由LLM估分或填造结果。

1. **建立本批记录。** 按§1读取规范与当前计划，核对模型适配、既定数据与评测、资源预算。记录共同BF16成绩、模型／tokenizer／数据／代码版本、种子与评测条件；已有适用结果直接引用。按§5先完成三档码率粗查、实际联合比较与类别预算分配，结果分阶段保存，不混作类别HPO或正式CAT成绩。
2. **逐轮列出候选。** 每类按固定顺序推进。当前参数开始前，写明本轮参数基底、全部待比取值和既定联动项；只在上轮选优后生成下一轮完整配置，不提前拼出所有组合。不同类别可独立推进，同类当前参数候选可并行。
3. **完成一个就回填一个。** 依次记录真实拟合、部署、完整八项、费用和状态。拟合完成但八项未齐时，成绩仍标未完成；复用行指向原候选，不重复计一次拟合。失败、超预算或不适用均保留原因，不填成0分。
4. **本轮齐备后选赢家。** 按主协议既定比较规则，从当前配置和本轮有效候选中选择；保存本轮赢家、是否替换当前以及下一动作。后续用赢家的完整超参重新拟合，不能从不同基底的历史行各摘一个最高分设置拼成未测配方。

首类完成后，按[主协议分批约定](sc_cat_protocol.md#recovery-budget-batches)在同一结果记录中汇总本批实际费用与第二批预算建议，保留首类已选配置、接续checkpoint及来源、各搜索项短筛校准状态、全模型长程名额和累计费用。范围等价等未适用项仍记未校准，不能用“首类完成”替代逐项通过。第二批未确认前下一类别记待预算，不派发任务；获确认后复用同一run记录与真实边界，继承配额／校准／费用，继续下一类，不重做首类搜索，也不取消最后独立BF16重放。该分批规则只划分原任务图，不新增训练或改变候选表。

每类选完后汇总一行最终采用的live配方、恢复步数和接续checkpoint。末类两份入围分别记录自己的八项、LongBench、九项均分及最终选择；附最终位宽、九项相对BF16分差、固定recipe重放入口和实际验收状态。最终交付配方来自这张表，离线赢家不保证在live恢复后仍胜出。

持久状态和结果表复用仓库现有输出：[19点执行包](../experiments/cat_sequential_search_cmcc_20261105/README.md)已有`search.json`和`selected_settings.json`，后者含候选coverage、当前设置与指标引用，并汇入[该批结果记录](experience/records/w25_transfer/2026-11-05_cat_selected_settings.md)。这是可复用基础，尚未证明已满足新标准全部明细、更新和正式链要求；不修改其活动源码／在途结果，也不重新维护一份同批表。后续新批次的位置及命名按§8.5，接线须对照真实接口，不将规范路径写成已实现的CLI能力。

只有所有类别及规定依赖闭合、共同协议成立、计数未超、候选证据有效，才能标本次离线搜索完成并交接正式顺序。缺关键证据则输出`incomplete`及可继续的具体动作；可以报告“当前最好已观测”，不得把它当完整搜索验收。合法／能力排除项必须明确披露，不称全候选／全交互最优；正式采用缩小协议范围仍按既有协作规则处理。

算法结果无增益可以正常关闭，不擅自增加21槽、第三种optimizer或20K。未达到最终压缩目标时，代理基于真实证据提出下一批有界假设、变量、费用和停止条件，再按当前计划的阶段讨论规则推进。

### 8.5 表格存储位置、命名与更新

**后续新建SC-CAT批次统一采用下列约定。** 规范正文位于`docs/sc_cat_protocol.md`及本文；各模型实际搜索和压缩结果存入实验记录。每次完整流程只有一份结果文档，三张表是其中的固定章节，不按类别或参数另建多份人工表格。

| 内容 | 仓库根目录下的固定位置 | 用法 |
| --- | --- | --- |
| 人与LLM阅读的结果文档 | `docs/experience/records/sc_cat/<model_tag>/<run_id>_results.md` | 从码率粗查、类别搜索到正式链及验收原位更新 |
| 本次产物目录 | `artifacts/sc_cat/<model_tag>/<run_id>/` | 保存实际配置、状态、指标、核心日志与仍有用途的模型产物；已有可复用产物引用原路径 |
| 输入与运行配置 | 产物目录内`manifest.json` | 记录真实模型／数据／协议／源码身份及本次输出根，并绑定上面的唯一结果文档 |
| 搜索状态 | 产物目录内`search.json` | 保存当前轮次、候选状态、已作选择及接续位置，是搜索接续的机器记录 |
| 配置汇总 | 产物目录内`selected_settings.json` | 从实际结果汇总各类别设置、覆盖和指标引用，供结果文档展示 |
| 候选原始证据 | 产物目录内`candidates/<candidate_id>/` | 每个候选独立写入；使用执行器的真实ID、配置和评测文件名，不为表格另起一套候选编号 |

上述机器文件沿用已有接口语义。正式恢复、最终评测与BF16重放按各自实际入口保存状态和产物，并从同一结果文档直接链接；离线搜索完成与正式链完成分别记录。接口尚不支持的输出绑定列为§9接线工作，不把文档约定写成实现已完成。

**命名规则：**

- `model_tag`取模型完整来源名并转小写：来源名的`/`用`--`连接，每一段内除ASCII字母和数字外的连续字符变成`-`，去掉段首尾`-`。例如`Qwen/Qwen3-8B`对应`qwen--qwen3-8b`。只有本地目录而无来源名时用目录名称按同一规则生成；实际来源路径、revision及权重身份始终记录在配置中，简称不作为结果复用依据。
- `run_id`固定为`YYYY-MM-DD_HHMMSS_s<seed>`，使用本次流程建立时的北京时间（Asia/Shanghai）。例如`2026-11-05_160000_s31`。同名的新独立任务按`_02`、`_03`递增，不覆盖已有目录；同一任务续跑仍使用原ID，不按重启日期改名。
- 同一次搜索、正式压缩及配方重放沿用本次记录，分阶段写清来源；重新启动独立搜索，或改变模型来源、数据、协议及根搜索条件时建立新run_id并引用旧批次。
- 文件名不含分数、是否赢家、`best`、`latest`或“最终版”等易变化标签；完成状态、选中配方和更新时间写在文档及实际状态中。

以下仅是路径示例，不代表已创建或运行该批次：

```text
docs/experience/records/sc_cat/qwen--qwen3-8b/2026-11-05_160000_s31_results.md
artifacts/sc_cat/qwen--qwen3-8b/2026-11-05_160000_s31/
    manifest.json
    search.json
    selected_settings.json
    candidates/<candidate_id>/
```

结果文档标题固定为`SC-CAT结果：<model_tag> / <run_id>`。篇首写本批条件和当前状态，至少包含模型完整来源、协议版本、种子、BF16对照及数据／评测引用、产物目录和机器记录链接；同一信息已有manifest时直接链接，不手抄第二份完整配置。三张表的章节固定为`候选明细`、`类别配置汇总`、`正式压缩与恢复`，分别使用显式锚点`candidate-results`、`category-settings`、`cat-recovery`。码率粗查与联合方案列在候选明细的对应阶段，最终九项与重放结论列在正式链章节。

**更新和接手：** 每次获得有效候选结果、完成本轮选择或确定正式接续节点后，从原始结果更新机器汇总及同一份结果文档，保留各候选行及历史轮次决定。并行worker只写自身候选产物，共同状态和结果文档由本批主执行器或负责汇总的LLM单独写入，避免多个类别互相覆盖。接手者从当前计划的本批链接进入结果文档，再读取实际机器状态与原始证据；表格尚未刷新时据有效原始记录补齐，不据旧表重跑已完成候选。

当前计划每批只保留一个结果文档入口；完整表格不复制到计划、首页或通用规范。归档和权重清理仍按AGENTS执行，原始指标与复现证据保留。已有19点批次继续原目录和结果文档；其`report.py`目前绑定该批Markdown路径，新标准实施时须解除这一批次绑定并核对真实写入位置，本次只明确约定，不修改活动执行器。
