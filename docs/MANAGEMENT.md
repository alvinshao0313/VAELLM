# 文档管理规范

适用范围：整个 VAELLM 项目。项目文档主源在服务器，Windows 副本用于阅读；`AGENTS.md` 按运行位置保留适用条款，具体同步规则见下文。运行、代码和结论以服务器工作区为准。入口：[文档导航](README.md)。

## 组织粒度：统一导航，按主题保存

采用分层检索：**入口 → 相关主题 → 需要时读取原始证据或历史**。不把所有正文合成巨型文件，也不为每次命令、每个步骤建立零碎文件。

- 一篇文档回答一个完整问题，或管理同一生命周期。优先更新已有主题的小节。
- 同一实验的设计、进展、最终结果写在一篇记录中；同组 A/B 共用一篇，列出 run_id。复现实验只有新增证据时才新增独立记录。
- 接口说明与模块代码同放；跨模块教程归 `guides/`。导航只链接，不复制正文。
- 一篇主题大约 100–300 行便于阅读，这是参考而非硬限制。超过约 400 行且包含独立任务/不同维护周期时拆分；不足一屏且总是一起使用的说明可合并。长历史原件不为凑行数拆碎。
- 对同一事实只维护一个权威正文。其他文档写适用上下文并引用；核心指标只在结果记录留必要摘要，完整表留原始指标文件。

## 分类和位置

| 类别 | 位置 | 内容边界 |
| --- | --- | --- |
| 协作规则 | [AGENTS.md](../AGENTS.md) | 两端各自只保留一份完整 `AGENTS.md`；共用规则以服务器为主，客户端连接和平台限制只在客户端保存 |
| 导航 | `docs/README.md`、经验库 `README.md` | 任务→主题链接；无重复数值、无相互矛盾的进度追加 |
| 使用说明 | `docs/guides/`、模块 `README.md` | 当前接口、适用范围、入口与最小命令 |
| 可复用经验 | `docs/experience/lessons/` | 条件、证据、解释、下次动作、边界 |
| 实验记录 | `docs/experience/records/` | 设计、run_id、实际配置、结果、决定、经验和证据链接 |
| 历史材料 | `docs/experience/history/` | 旧设计/审查/被替代说明；不等于现行接口、实测或执行授权 |
| 产物说明/生成报告 | 原始结果目录 | 与模型加载、评测文件或生成器绑定，保持原位并进入总目录 |
| 展示材料 | 对应实验记录目录 | 人工汇报 HTML/PDF 等附件，链接结果来源；不承担当前状态入口 |
| 工具状态 | `.ai-bridge/` | 工具拥有的计划、交接、上下文快照；不默认全文加载 |
| 上游与许可证 | 上游模块原位 | 保留来源与许可证，不合并改写成项目规范 |

配置、原始 JSON/CSV、日志、数据集、tokenizer、模型权重不是知识文档，不搬进 docs。扫描覆盖 Markdown、mdc、RST、TXT、HTML、PDF、DOCX、notebook、ORG、AsciiDoc 和许可证；忽略缓存/依赖目录、目录符号链接、已知 tokenizer 文本/运行时间标记。总目录的自动分类按路径推断，只代表位置，不认证结论。

## 写入与命名

1. 新写之前，按关键词查入口和主题，确认没有同义正文。
2. 使用简短稳定的英文路径。经验按问题命名；新结果按主题与 `YYYY-MM-DD_slug.md` 命名，日期取实际事件日期。只知道整理日期时明确标注，不能伪造运行时间。
3. 已迁移的 `records/docs/`、`records/experiments/` 等路径保留。同主题沿用其目录，不为改命名再搬一遍全部历史。
4. 使用 UTF-8、相对 Markdown 链接。新链接直达权威正文；移动时同步修复引用。既有外部使用的路径可保留指向正文的符号链接，不再维护重复内容。
5. 修改前读取最新文件，保留其他任务未提交的更新。普通文档的 Windows 阅读副本只能服务器→本机按需刷新，不从旧镜像反向覆盖服务器。`AGENTS.md` 按条款合并共用规则，保留各自适用的执行条款，禁止整文件互相覆盖；Windows 的连接/跳板/本地能力限制只在本机保存，服务器版本面向直接在服务器工作区运行的代理。

## 状态、证据和过时内容

- 经验注明最后核查日期、适用模型/实现/数据/预算、证据状态和结果链接。未证实原因写成假设；单次冒烟不代表质量提升。
- 实验运行状态和结论状态分别记录；具体字段和最小模板唯一维护在 [实验流程](experience/WORKFLOW.md)，这里不再复制。
- 指南修改接口/命令时，同步检查对应代码与正式脚本；没有运行过的命令不能标“已验证”。历史配置不因整理变成当前推荐。
- 发现旧入口误导时，先在首页标明历史范围并指向新入口。历史结果保留当时事实，用修订日期/替代链接解释新结论，不悄悄改成新结果。
- 不把“文件久未修改”直接当成过时；由接口变更、矛盾证据或被替代方案触发复核。没有定时全库审查，也不建立后台监控。

## 索引与检索：避免人工维护重复目录

`docs/README.md` 是人工维护的短导航；`docs/INDEX.md` 由 `tools/docs.py` 从文件树自动生成。只有新主题/新入口才修改导航；新增、移动、改标题或归档后刷新自动目录。

`experience/CATALOG.md` 固定为 2026-09-23 首次归档的来源快照，保留追溯价值；以后不在这里另建第二套实时目录。新实验自动进入 INDEX。

```bash
# 当前 bitvae shell，远程项目根目录；无需安装包。
python tools/docs.py index
python tools/docs.py index --check
python tools/docs.py check
python tools/docs.py search '关键词|英文标识符' --scope lessons
python tools/docs.py search '关键词' --scope records
```

默认检索范围是规则/指南/模块说明＋经验。仅需要证据时增加 records，仅追溯历史时使用 history；`--scope artifacts` 搜生成报告，`--scope bridge` 搜交接状态，`--scope all` 才覆盖全部分类。别名不会重复命中；大型索引不会混入正文搜索。PDF/DOCX 仅登记路径，需要时用对应阅读工具，搜索命令不宣称能检索其正文。

`check` 只检查项目内文档别名及 Markdown 相对链接的目标存在性；不验证标题锚点、互联网链接、正文里的命令、指标真伪、HTML 脚本或实验状态。临时证据若按授权删除，更新引用为明确的清理说明，不能留下指向不存在文件的“有效证据”链接。

## 每次任务的最低维护动作

- 协作中或收尾时：按 [AGENTS.md](../AGENTS.md) 的持续总结规则维护已确认的工作偏好；技术经验与单次结果仍分别归档，不为每次对话新建偏好记录。
- 设计实验前：先检索经验，记录适用内容、条件差异、规避动作和待验证假设。
- 改接口后：更新对应指南/模块说明；不复制一份“最终版”。
- 实验结束后：结果总结 → 经验增量检查 → 必要导航更新 → 刷新目录/检查链接 → 按既有授权清理产物。无新认识时注明原因，不强造经验。
- 普通文档变更：只做索引/链接/引用检查，不因此启动 GPU 训练。
- 收尾：报告更新入口、实际验证和限制，检查本任务临时文件与磁盘空间。删除遵守项目既有授权和保护范围；文档分类不是额外删除模型/数据的授权。

以上规范同时写入项目代理入口，后续会话按同一流程执行。
