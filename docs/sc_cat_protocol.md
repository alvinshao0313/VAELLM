## 适用范围与职责

目标：给定一个待压缩的原始模型、仓库及资源预算，让LLM使用统一的数据配方和评测协议，按明确搜索表完成各类别逐参数搜索、固定S2／平均约2.5bit的一阶段CAT构建，交付模型、结果和复现方法。用户已确认本标准覆盖搜索、结果驱动的分配、并行、探索接入正式链、验收及复现；核心规则已确认，接手时按现行搜索表及执行规范落地；历史批次只约束各自范围。

**迁移原则：固定搜索和选择方法，允许不同模型得到不同配置。** 不把Qwen／Llama名称、层数、投影形状或某个旧checkpoint写成算法前提；每个模型使用自身BF16对照，重算模块映射、费用、压缩敏感性和搜索结果。例如相同转置比较规则可为Qwen的Q选择转置，为另一个模型的Q选择不转置；类别位宽、保护比例和恢复步数也由固定规则读取各自实验结果确定，不照搬前一个模型的赢家。仓库尚不支持的模型需显式补适配，不能把协议可迁移写成实现已支持所有架构。

**固定比较条件：** 数据使用已探索选定的最优配方，固定来源版本、split、混合比例、采样和训练用途；具体清单及证据须绑定到执行配置，不默认旧稿中的某份数据就是已证实最优，也不在新模型压缩搜索中重新搜索数据。评测固定当前九项及其现行计分方式；目标为相对该模型自身BF16的九项均分最多下降1个百分点；平均位宽约2.5、原已定logical bpw≤2.6及费用口径继续保留。S2保持不变。

**目标和评测口径已确认：** 最终九项平均分相对该模型自身同协议BF16最多下降1个百分点，允许等于1；例如BF16为70分，成品须至少69分。按未舍入百分制分数判断`S9(BF16) - S9(成品) <= 1.0`，替代本标准旧稿的严格<0.9pp，不使用相对百分比或绝对值。全部实际离线候选、单类码率粗查、联合码率方案及恢复节点继续测完整八项；最终两份入围补LongBench后按九项选品与验收，不给全部搜索候选追加LongBench。其它已单独批准实验不追溯改判。

| 标准必须说明的部分 | 本部分要回答的问题 |
| --- | --- |
| 1. 模型适配与固定比较条件 | 支持不同模型，绑定其自身BF16和类别／层映射；统一使用已选数据及当前九项，不固定某个模型路径或层数 |
| 2. 单类别逐参数搜索表 | 固定参数顺序、候选范围、各项名额、逐层混合转置规则、选优／同分规则、设置继承和结束条件；搜索结果随模型变化 |
| 3. 结果驱动的位宽与费用安排 | 固定怎样根据实测结果选择各类主码率、保护比例及预算；总平均约2.5bit，明确实际开销与搜索费用，不预设各模型相同分配 |
| 4. 并行与任务接续 | 同一类别只并行当前参数候选，不同类别独立推进；如何利用空闲资源、复用已有结果、中断后继续，避免重复运行 |
| 5. 正式CAT基线构建 | 如何将离线设置带入真实逐类链、确定类别顺序、在当前模型上重拟合；按已定类别蒸馏保存／比较节点并接下一类 |
| 6. 基线验收、复现及迁移 | 最终怎样测质量与实际位宽，何时冻结一阶段基线；如何从BF16重放，迁移新模型时哪些统计重算、哪些规则不变 |
| 7. LLM执行与交付约定 | 实际调用哪个入口、读哪个结果、如何比较和记录；失败／无改善／预算不足怎样处理；交付每类参数、恢复步点、模型及复现命令 |

一阶段基线规范不展开：S4／自适应残差阶数及其它新压缩表示；复杂BSQ编码诊断及专门的自动调参机制；二阶段的新数据／训练目标／恢复算法；逐层全组合穷举、无限回访及通用调度平台。现成BSQ系数若要搜索，只在参数表中作为普通可选项讨论，不把其专项诊断变成完成本标准的前提。

一阶段对二阶段只定义衔接：以哪份已冻结一阶段模型为起点、单独记录新增费用和收益、沿用什么验收口径；具体针对性恢复标准另行制定。本标准区分“规则已定”“仓库已有执行能力”“真实模型已验证”，不把文档写完等同整链跑通。

**二阶段讨论边界（2026-11-09，按用户最新决定修订）：** 从已冻结的完整压缩基线出发，按“短文蒸馏恢复→普通长文蒸馏→根据结果决定是否做长文OPD”渐进接续。先完成通用指令、知识题及其它七任务的短文恢复，再在该阶段选定checkpoint上做普通长文蒸馏；完成普通长文全部常规搜索及已触发的256步对照后，按[已确认进入条件](#stage2-opd-entry)分支：九项下降不超过1个百分点就转入验收，仍未达标才进入OPD；实际预算另行落实，不自动启动。这里的短文阶段是数据／训练流程区分，不新增一个未确认的长度筛选阈值。此前“知识配方选完后，从原压缩基线重新做短长文混训”的衔接已被替代；旧10%／20%混合占比及11份训练计数不再作为当前执行规则。

**2026-11-10最新推进顺序：** 更新范围同时包含“训练哪些参数”和“训练哪些模块”，只在短文阶段确定一次：D／P／B七种参数组合→仅给组合赢家比较全模型／注意力／MLP模块范围→短文数据→超参数→优化器→阶段最佳步点。普通长文固定短文选出的参数组与模块范围，按长文数据→超参数→优化器→阶段最佳步点推进；不再搜索参数组合或模块范围。条件性OPD同样固定该范围，重新比较[三份纯长文数据](#stage2-opd-data)，再搜超参数、优化器及最佳步点；不直接沿用普通长文的数据赢家。普通长文保留一次90%长文＋10%短文数据对照，OPD保持纯长文。各轮仍按已确认节点评分规则比较配置，阶段末在全部已测合法节点与0步中确定最终checkpoint；不把本顺序理解为取消中间评测或先固定末步。

各阶段仍只使用有来源记录的合法开源train／auxiliary_train，沿用当前九项、相对自身BF16最多下降1个百分点及平均约2.5bit／logical≤2.6目标，不按测试逐题表现选训练样本。一阶段及其它已批任务不变，首版不新增LoRA。B采用现有敏感度版本；更新范围按[统一范围表](#stage2-main-code)在短文阶段搜索，普通长文与OPD继承该结果。各阶段保留原已确认数据／目标／训练长度与节点评测，普通长文的全模型／注意力／MLP范围轮移至短文，后两段范围搜索取消。超参数与优化器的具体规则见各阶段正文，D／P／B已绑定AdamW／Muon两套配方，B采用下文三档学习率及分阶段日程；B已确认更新选定模块内的全部编码，不搜索活动比例或轮换子集；B已确认不参与联合梯度范数裁剪，也不单独做范数裁剪；其余执行设置按下文落实，不能直接套用D／P。是否进入OPD继续按[达标分支](#stage2-opd-entry)判断，本次只改规范，不启动实验。


<a id="stage2-main-code"></a>

**更新范围只在短文阶段搜索（2026-11-10最新确认）：** D表示解码器，P表示已有INT8保护通道的整数代理与scale联合QAT，B表示主BSQ编码。先在全模型目标模块中比较以下七种非空组合；只给赢家继续比较全模型／注意力／MLP三种模块范围。后两段继承短文最终选出的活动参数组与模块清单，不再做范围搜索，也不新增独立编码训练阶段。P不拆成只调整数或只调scale；S2、编码长度、保护数量／索引／存储格式保持。

| 组合 | 参与更新的对象 | D／P／B中保持冻结者 |
| --- | --- | --- |
| D | 解码器 | P、B |
| P | 保护整数与scale | D、B |
| B | 主BSQ编码 | D、P |
| D＋P | 解码器、保护整数与scale | B |
| D＋B | 解码器、主BSQ编码 | P |
| P＋B | 保护整数与scale、主BSQ编码 | D |
| D＋P＋B | 三组一起 | 无；其它非候选参数仍冻结 |

例如D＋P＋B胜出，再比较三组一起更新全模型、注意力或MLP；不为七种组合各开一轮模块搜索，也不将三组分配到各自不同模块族。模块名称映射到实际模型结构，不固定为七类。各候选从同一冻结压缩基线独立训练、固定本轮原数据及目标／预算，按短文完整八项选优；相同全模型控制复用。没有保护等情况排除空候选并合并等价配置，不能重复凑七份。范围选好后才进入短文数据搜索；后续阶段保留该范围，分别搜索自己的数据与优化设置。B在所选模块内开放全部主编码，模块外编码冻结，不另搜活动比例或轮换子集；只有B参与训练时仍比较上述模块范围。矩阵组织见下文，其余B优化设置和新增GPUh待确认，本决定不启动实验。

**方法已确认：仅使用现有敏感度版本。** 首版固定`bit_proxy_coordinates=decoder_sensitivity`，不增加`unit`版本的方法对照。复用[现有敏感度标定](../sparse_bit_tuning/coordinates.py)与[测量定义](../litebsq/bit_sensitivity.py)：每个模块／stage／part的码库，依据当前训练起点decoder的实际解码结果，测量单bit变化引起的重建权重变化RMS，得到该库固定尺度s。沿现有实现使用FP32代理`p=s(b−0.5)`，以零阈值决定实际硬码；训练前向及部署仍使用硬编码，最终按原生packed格式导出，不把临时代理加入成品位宽。尺度在同一轨迹内固定，精确续训读取已保存尺度与状态，不按续训时的decoder重新标定。代理、梯度及优化状态增加的训练内存与标定计算据实计费。该选择控制方法数量，不表示敏感度版本已被证明优于unit；码位优化器、学习率及日程按下文已确认规则，活动范围按下文选定模块内全部编码执行，其余待定优化设置不照搬旧值或unit默认学习率。

<a id="stage2-code-optimizer"></a>

**二阶段优化器绑定：D／P／B统一比较AdamW与Muon（2026-11-10最新确认）：** 替代此前“主编码固定Adam”的选择。短文、普通长文与条件性OPD都只比较两套：所有实际活动组采用AdamW，或共同采用Muon配方；D矩阵／辅助参数沿原分工，P整数与scale均真正用Muon，B也须真正使用Muon，不能在Muon配方中继续用Adam。缺失组跳过，不重新开放未选范围；只有B活动时仍比较AdamW与Muon。各组学习率及优化器状态独立，不将D／P／B展开为混合类型的组合网格。一阶段D／P与LoRA的既定搭配不变。

范围／数据搜索和后续学习率轮先采用共同AdamW参照，B沿现有`bit_optimizer=adamw`路径，`betas=(0.9,0.999)`、`eps=1e-8`、权重衰减0；后续优化器轮再比较绑定的两套配方。B三档参照及分阶段日程保持；主编码Muon已按下文确认单独对齐初始更新量；参数组织已按[完整编码向量成行](#stage2-code-row-sampling)确认；已取消活动比例搜索、子集轮换及同轨迹中途状态重置；B梯度范数不裁剪，D／P沿各阶段自身规则；连续状态、Muon与保存／恢复适配仍待实现验证。现有[配置](../sparse_bit_tuning/config.py)及[码位更新](../sparse_bit_tuning/optimizer.py)尚无Muon路径，不把已确认设计写成已实现。已有B-Adam与AdamW在权重衰减0且其余条件相同时使用相同更新公式，可作为参照依据，不据此自动认定历史轨迹可复用。

D或P参与训练时，优化器轮通常仍为两套，新增B绑定不额外增加训练候选，但单条成本会改变；只有B活动时，相比旧固定Adam规则新增一条Muon对照及四次节点评测。短文每条500步／四次完整八项，普通长文或OPD每条128步／四次完整九项。适配验证及实际GPUh另计，仍须完整条件匹配才能复用AdamW控制；不增加RMS-SGD、第三套混搭或新阶段，不由本决定启动实验。

<a id="stage2-code-lr"></a>

**主编码学习率三档（2026-11-10已确认）：** 所有启用B的阶段，范围／数据比较先采用AdamW、`bit_lr=2e-5`作为共同起点；随后在该阶段超参数搜索中，比较`1e-5／2e-5／4e-5`三档，即参照值的0.5／1／2倍。短文、普通长文及OPD各自选优，不直接继承前阶段胜出的B学习率。B不活动则跳过；不增加五档扩展或全组合网格。三档先在共同AdamW条件下比较，随后再比较D／P／B绑定的两套优化器；主编码Muon按[独立初始更新对齐](#stage2-code-muon-lr)换算，沿用已选倍率，不直接套用AdamW数值或D／P换算倍率。

同一轮固定本阶段父checkpoint、数据、活动参数组与模块清单、其余优化设置及训练预算；每份从共同父模型重新训练，只继承前轮胜出设置。同轮三档可并行，完整条件相同的原值轨迹直接复用。短文仍每份500步、125／250／375／500评完整八项；普通长文与OPD每份128步、32／64／96／128评完整九项，按各阶段已确认节点规则比较，不用训练loss或翻码数量代替任务成绩。B日程按下文分阶段规则执行；学习率顺序按[三阶段统一规则](#stage2-lr-order)执行；每份都更新所选模块内的全部编码，不比较活动比例。

<a id="stage2-lr-order"></a>

**二阶段学习率顺序（2026-11-11已确认）：** 短文、普通长文和OPD均按主编码B→解码器D→保护P依次搜索，未活动组直接跳过；P整数与scale仍共用一个搜索倍率。各轮先在共同AdamW条件下比较三档，下一轮继承前轮胜出的设置，尚未搜索的组保持该阶段参考值；每份训练都从本阶段共同父checkpoint独立开始，不接续前轮已训练权重。全部活动组学习率选完后，再比较绑定的AdamW／Muon，后者独立换算各组起点并沿用已选倍率，不回访学习率。同轮不同倍率可并行，下一轮须等本轮选优完成。本次只固定顺序，不增加候选或评测，不改变一阶段decoder→保护→LoRA规则；顺序的效果优势尚无当前条件下的实测证明。

| 启用B的阶段 | 原值可复用时新增训练 | 新增参数更新 | 新增节点评测 |
| --- | ---: | ---: | --- |
| 短文 | 2条500步 | 1000次 | 8次完整八项 |
| 普通长文 | 2条128步 | 256次 | 8次完整九项 |
| 条件性OPD | 2条128步 | 256次 | 8次完整九项 |

短文两条新增训练共4000次样本呈现；普通长文两条新增训练共2048次题目呈现；OPD两条新增训练共2048次题目呈现、8192份学生回答及对应教师指导／裁判评分。若无完整匹配的原值轨迹，则三档都需训练，按实际去重后的条数计费；不得为省一次控制而复用不同数据、范围或日程的结果。以上只计B学习率轮，不是全阶段预算，GPUh另核，也不授权启动实验。

参照[旧单层Adam步幅对照](experience/lessons/post_recovery/codes.md#liftquant-recovery--完整score统计与adamrms步幅对照)：旧400步条件下2e-5比4e-5回退小，但没有超过冻结码对照；1e-5曾全程没有实际改码。它们仅为搜索范围提供已有依据，不能证明新模型／范围／目标／训练长度下2e-5最优，也不保证三档均发生改码。

<a id="stage2-code-row-sampling"></a>

**主编码在选定模块内全部更新（2026-11-11最新确认）：** B与D／P共同跟随短文阶段选定的全模型／注意力／MLP模块范围。只要B参与训练，就开放该范围内每个实际投影、残差stage及part的全部主编码；不搜索活动比例，不抽取部分行或部分bit，也不轮换子集。模块范围之外的编码保持冻结。只有B参与训练时仍进行模块范围比较，普通长文和OPD继承短文选定范围。

例如选中了“注意力部分的解码器＋保护＋主编码”，就训练注意力中所有主编码，MLP编码冻结。某个纳入范围的码库有1000个编码向量，则全部1000行参与，而不是只取其中5%或25%。全部开放表示每个位都允许更新，不要求它们全部实际翻转；最终仍保存原生硬码，S2／编码长度／部署存储格式保持。

**Muon继续按完整编码向量成行。** 沿现有[BankSpec](../sparse_bit_tuning/module.py)的`logical_shape=[N,1,K]`，每个编码向量的K位作为一行，整个码库形成`[N,K]`浮点代理矩阵。K取该库实际latent_dim，不用权重向量长度代替；每个投影／stage／part独立，不把S2两阶或不同码库拼成一张Muon矩阵。实际存储可继续分块，矩阵计算须保留上述逻辑边界。AdamW与Muon使用相同全集及原编码行列对应关系；库内逻辑位索引为`row_id×K+k`（索引从0开始），更新后按原位置写回。

现有[逐bit采样](../sparse_bit_tuning/sampler.py)即使设置全覆盖，也可能按置换后的bit顺序组织代理；[packed索引消费](../sparse_bit_tuning/triton_kernels.py)须与真实行列位置对应，不能直接把任意散bit缓冲区reshape为Muon矩阵。Muon逐码库计算，初始更新对齐汇总全部活动B的更新求一个κ_B；保存／重载与续训保持编码映射、代理和优化状态。旧[训练管理器](../sparse_bit_tuning/manager.py)还会在达到轮长或满足连续无翻码条件时重置代理与优化器状态；全覆盖本身不会取消这一行为，新标准须按下述连续优化规则适配。

**取消同轨迹中途重置（2026-11-11已确认）：** 同一条短文500步、普通长文128步或OPD轨迹持续保留B浮点代理、AdamW步数及矩状态／Muon动量等优化状态，不因旧轮长到期、连续无翻码、保存或评测而重新初始化。OPD条件续到256步以及正常中断续跑都恢复原完整状态、日程位置、随机状态与数据进度；第128步不清空B状态。独立候选、跨阶段接续以及普通长文从共同短文父独立重跑256步时，才从该次父模型的实际硬码初始化代理并重建优化器，敏感度尺度按既定规则取得。写出硬编码用于保存、评测或部署不等于重置仍需继续训练的浮点代理；只含硬码的导出模型不能替代精确续训状态。

本次固定连续优化方式，不另加重置与不重置的训练对照。当前只改规范，Muon、日程与连续状态适配尚未实现验证，不修改已批准批次；旧逐bit实验不能直接证明本配方效果。

本次不增加训练候选或节点评测，取消原待定的行比例、行数取整、抽取顺序及换批规则。全部编码的浮点代理、梯度和优化器状态以及Muon计算成本按实际模型重新核算；不能用成品bit数替代训练内存，也不能为适配资源自行改回部分编码更新。

<a id="stage2-code-gradient"></a>

**主编码不做梯度范数裁剪（2026-11-11已确认）：** 短文、普通长文和OPD的活动B均排除在D／P联合梯度裁剪之外，也不另做B组、逐库或逐行的范数裁剪。D／P保持各阶段自己的裁剪规则；普通长文与OPD在累计完整8题后，仅将活动D和P的梯度合在一起按全局L2上限1.5裁剪，B不计入该范数，也不乘它产生的缩放系数。只有B活动时跳过D／P裁剪；短文按[共同优化起点](#stage2-short-optimizer)在完整4条样本梯度累计后，同样仅对活动D／P联合裁至1.5。本规则不增加裁剪对照或阈值搜索。

各组先完成正确的损失归约与梯度累积，需要AMP反缩放时仍正常执行；B不做范数裁剪不等于跳过这些必要步骤，也不等于取消代理更新后的取值约束。AdamW／Muon正式训练与初始更新量换算使用相同分工：κ_D／κ_q／κ_scale使用按本阶段D／P规则处理的梯度，κ_B使用未做范数裁剪的B梯度。不能为了换算而把B临时并入D／P范数，或把训练与换算的处理规则分开。

该分工沿现有[Sparse Bit裁剪过滤](../sparse_bit_tuning/amp.py)排除主编码的做法；[旧覆盖率对照](experience/lessons/post_recovery/codes.md#liftquant-recovery--e2e覆盖率对照区分更新坐标和梯度裁剪)记录的是旧decoder／编码路径，不能直接证明本次全编码、联合保护及Muon配方的效果。当前仅确认规则，尚未适配或运行新路径。

<a id="stage2-code-muon-lr"></a>

**主编码Muon的步长参照（2026-11-10已确认）：** B单独对齐初始更新量，不复制D、保护整数或scale的换算倍率。沿[既有初始更新匹配口径](#recovery-muon-scale)，在本阶段共同父checkpoint的参数／优化状态副本上，用同一份真实初始梯度，分别计算fresh AdamW与未标定Muon对活动B浮点代理的未舍入更新提议；采用非零参考基础学习率`η_B=2e-5`，搜索倍率先取1，不把预热起点的0学习率用于换算。

汇总本候选全部实际活动B参数的更新，计算一个`κ_B=||ΔAdamW_B||F / ||ΔMuon_B||F`；不逐层／逐码库分别定倍率，也不把其它参数组的范数混入。这里比较浮点代理的更新提议，不用硬码翻转数、重建权重变化或下游分数代替。B矩阵组织沿[完整编码向量成行](#stage2-code-row-sampling)，梯度按[不做范数裁剪](#stage2-code-gradient)处理；更新约束的实现细节仍须明确并绑定到校准记录，本规则不提前替待定项选方案。

前一轮在AdamW下已经选定`m_B∈{0.5,1,2}`后，优化器比较中B的实际学习率为：AdamW使用`2e-5×m_B×s(t)`，Muon使用`2e-5×κ_B×m_B×s(t)`，其中`s(t)`沿已确认分阶段日程。例如同一参考学习率下Muon更新量为AdamW的5倍，`κ_B=0.2`；原值档的Muon基础学习率为4e-6，若前轮选中半值档则为2e-6。不为Muon重新搜索三档或增加优化器后回访。

换算使用当前阶段父模型、胜出数据和实际活动范围。短文与普通长文使用各自已定目标的初始梯度；OPD使用当前父学生按既定方式生成回答后的真实教师／奖励目标梯度，不能用普通长文参考答案蒸馏梯度替代。测量不改变正式父模型、优化器或训练数据／随机进度；同一轨迹固定κ_B，正常续训读取原κ_B和完整状态，跨阶段或父模型／数据／活动范围等相关条件改变时重新取得，不能照搬旧模型的κ_B。组整体无法取得有限、非零比值时按既有初始匹配规则处理，不默填1。

记录真实输入／梯度来源、活动B参数组织、两种更新范数、κ_B、m_B与实际学习率，随候选状态保存。计算和必要OPD生成／教师／裁判成本据实计入；不新增完整训练候选或节点评测，也不代表B的Muon实现或恢复效果已验证。对齐提供初始步长参照，最终仍按短文八项、普通长文及OPD九项选优。

<a id="stage2-code-schedule"></a>

**主编码学习率日程（2026-11-10已确认）：** B在短文及普通长文阶段采用线性预热后半周期余弦下降，OPD无预热、保持恒定；固定日程，不增加日程对照。三档学习率表示各候选的基础学习率，实际每步学习率为基础值乘日程倍率。

| 阶段 | 总更新次数T | B预热次数W | 之后的B学习率 |
| --- | ---: | ---: | --- |
| 短文首轮 | 500 | 5 | 半周期余弦降至0 |
| 普通长文首轮 | 128 | 2 | 半周期余弦降至0 |
| 普通长文已触发的独立长程对照 | 256 | 3 | 从共同短文父重建完整256步日程，半周期余弦降至0 |
| OPD首轮及已触发续训 | 128，条件续至256 | 0 | 始终为本候选基础学习率，128步处不重置 |

余弦计数沿[普通长文已确认定义](#stage2-long-schedule)：令u为本轨迹已完成更新数，`s(u)=u/W`（0≤u<W），之后为`0.5×[1+cos(π×(u−W)/(T−W))]`（W≤u≤T）；第k次更新使用`s(k−1)`。例如短文前六次倍率为0／0.2／0.4／0.6／0.8／1，普通长文前三次为0／0.5／1。日程按本轨迹的参数更新计数，不按梯度累积次数或评测次数重新预热；本标准不轮换编码子集。正常中断续跑保留完整训练状态和日程位置；独立候选或跨阶段重建优化器及本阶段日程，不能把已选中间节点的步数作为新的总长度重缩日程。

现有[BitOptimizerManager](../sparse_bit_tuning/optimizer.py)将自身`self.lr`直接传给码位更新核，不会自动跟随解码器scheduler；旧敏感度实验使用的是恒定码位学习率。短文／普通长文须显式适配真实码位更新调用与保存／恢复，不能只修改日志或解码器的学习率。此处是已确认设计，尚未修改或验证该适配；不改变已批准在途批次，短文D／P现已按[统一500步日程](#stage2-short-schedule)使用相同预热／余弦倍率，不扩大训练长度。学习率三档、候选数量、节点评测及费用计数保持。

**现有实现与证据边界：** 仓库[恢复入口说明](../compressed_e2e_fintuning/README.md#sparse-bit-敏感度代理坐标)、[Sparse Bit配置](../sparse_bit_tuning/config.py)及[运行接入](../compressed_e2e_fintuning/runtime_v6_pipeline.py)已有敏感度代理和decoder／编码联合训练路径，但不表示已适配本标准的联合保护QAT、普通长文或QAOPD目标。旧[同预算正向对照](experience/lessons/post_recovery/codes.md#liftquant-recovery--码位联合优化的正向例子要绑定配方与控制2026-10-04)与[更高起点的负向对照](experience/lessons/post_recovery/codes.md#liftquant-recovery--更高起点的bit-lr零翻码与真实更新调用)说明收益依赖起点和配方，不能把梯度、实际翻码或局部loss改善当作完整下游收益，也不能由单个负例排除编码学习。

**已确认范围的工作量与待定部分：** 七种组合都适用、模块比较中全模型结果可复用时，短文范围部分通常7＋2＝9条训练；再复用范围赢家为知识A、增加B／C／D／E四份数据配方，通常共13条500步训练，即6500次更新、26000次样本呈现、52次节点完整八项。这只是范围＋知识数据部分，未包括后续超参数／优化器搜索；不再使用旧六份或仅七组合加数据的十一份计数。普通长文与OPD均不再产生范围对照费用，后文按实际不同轨迹数N_L／N_O计费。D／P／B优化器绑定、B三档学习率及分阶段日程已确认；B的独立Muon步长换算已确认，Muon参数组织已定完整编码向量成行，并更新选定模块内全部编码；同轨迹连续优化、不作中途状态重置已确认；学习率顺序已定B→D→P再比较优化器，B梯度范数不裁剪已确认，连续状态／Muon／日程的实现验证及其余执行设置仍待完成；D／P现有规则不自动扩成B规则，含B的整段可执行配置尚未闭合。

<a id="stage2-long-data"></a>

**后续长文来源与搜索位置（2026-11-10已确认）：** 普通长文蒸馏先比较下表L1／L2／L3三份纯长文配方，按完整九项选优，再对赢家增加下文一次短文保持对照；后续若进入OPD，固定短文更新范围，在同一OPD父模型上重新比较下表三份纯长文配方；两阶段各自选数据赢家，OPD不带入短文份额。全部使用Qasper、HotpotQA、NarrativeQA的原始合法train来源，不使用LongBench评测样本训练。

| 来源配方 | 长文内部组成 | 例子：每8次长文题目呈现 |
| --- | --- | --- |
| L1：论文＋多段 | Qasper : HotpotQA = 2 : 6 | 2条论文问答＋6条多段问答 |
| L2：论文＋故事＋多段 | Qasper : NarrativeQA : HotpotQA = 1 : 1 : 6 | 1条论文问答＋1条故事问答＋6条多段问答 |
| L3：故事＋多段 | NarrativeQA : HotpotQA = 2 : 6 | 2条故事问答＋6条多段问答 |

三份普通长文候选从同一个选定短文checkpoint独立训练，先沿用短文阶段选出的可训练参数范围，共用损失、优化设置、题目预算和评测规则，只比较长文来源配方，可并行执行。记录每份配方、实际曝光、节点及完整九项结果，胜出配方与选定checkpoint分别绑定。若后续进入OPD，接续选定的前阶段checkpoint，按[OPD数据轮](#stage2-opd-data)重新比较三份纯长文配方；由当前学生重新采样回答，不把普通蒸馏的参考答案轨迹当作OPD轨迹。

**长文数据搜索的范围起点（2026-11-10最新确认）：** 直接固定短文选出的活动参数组及模块范围，比较三份纯长文数据，再给赢家补一次短文保持对照，随后进入超参数及优化器搜索。原长文数据后范围细调已取消。例如短文选中注意力D＋P＋B，全部长文候选均保持这一范围。D／P使用本阶段已确认AdamW参考学习率1e-5／0.03／0.001，B也用AdamW、共同起点2e-5；不继承短文优化器状态。跨阶段按[保留模型参数、重置优化器](#stage2-state-handoff)接续；首轮128步、每32步完整九项，各候选均从同一短文checkpoint独立训练，不在前轮赢家训练权重上累积。

**普通长文的短任务保持对照（2026-11-10已确认）：** 三份纯长文配方选优后，只对赢家新增一份90%长文＋10%短文候选。百分比按题目呈现数计算：例如100题中，90题按胜出L1／L2／L3的内部比例抽取，10题按短文阶段选定的通用／知识／其它七任务配方抽取；各来源使用自身已确认目标，按本阶段题目占比合并损失。两份比较均从共同短文父checkpoint独立训练，固定可训练范围、学习率及其它优化设置、总题目数、训练步数和评测节点；纯长文结果直接复用，混合候选不接续其训练权重。以完整九项决定保留纯长文还是90%／10%，随后固定胜出数据及继承范围搜索长文超参数、优化器，不展开额外比例网格。

此对照将部分长题替换为短题，长文曝光和实际算力可能变化，不称为等长文token或等GPUh对照；10%只是本轮候选，不是已验证最优。历史短任务保持有过有限收益，条件边界见[域损失与OPD经验](experience/lessons/post_recovery/objectives.md#kd-and-data--域损失clip和opd保留的真实贡献)。若混合候选胜出，后续OPD仍不继承10%短文；OPD独立重搜L1／L2／L3，例如OPD选中L2时，全部题目按论文∶故事∶多段＝1∶1∶6分配。

普通长文数据部分通常为3份纯长文＋1份90%／10%对照，共4份训练及对应节点的完整九项评测，纯长文赢家结果复用；首轮每份4个节点，共通常16次节点九项评测，GPUh另核。OPD数据轮已确认独立重搜三份纯长文配方，训练及费用按[OPD数据规则](#stage2-opd-data)单列，普通长文结果不能替代该轮。这不是两段全部参数搜索的训练总数或已批准GPUh。上表是题目来源比例，不是实际batch=8；普通长文与OPD首轮均已分别确认128步及四节点；OPD按[自身长度与选点规则](#stage2-opd-length)执行，两段的实际题目量及其它优化设置分别核算。普通长文按[最好已评节点及0步保底](#stage2-long-selection)选成品；同分按下文已确认规则处理，是否进入OPD按[达标分支](#stage2-opd-entry)决定，后续不自动重跑稳定前驱。

**旧混训方案仅作变更记录：** 原L0为通用50%＋任务50%；L1–L3各比较长文10%／20%，其余来源同比缩至45%／45%或40%／40%，长文内按上表分配，共七份混训。原两范围＋三份新增知识＋六份新增混训合计11次训练；若各评一个节点为11套八项＋7套LongBench。这组占比、训练计数及评测计数随新接续方式退出当前规则，不改写成新方案已获批准预算；三种长文来源组成继续保留。

**完整长文入池（2026-11-09已确认）：** 新增长文只从能完整放入本轮窗口的合法train文章／问答中抽取，不截短正文。按目标模型实际tokenizer与模板核算完整正文、问题、模板和回答所需长度；使用现成答案时计入完整监督答案，采用在线生成时预留已确定的生成预算，不能只按正文长度判断。放不下的样本不进入本轮可用池，不以截短文章后保留问答替代；可用池会因此缩小，记录各来源合格文章数／问答数与长度分布。普通长文蒸馏已选train参考答案，其多参考处理、文章／问答抽样单位及覆盖量仍待确定；OPD回答预算沿后文已定设置。本规则不改变一阶段数据处理，不据测试逐题结果挑选文章。

**长文窗口（2026-11-09已确认）：** 首轮上限固定为32K，即32768 token，并受目标模型现有支持长度约束；实际窗口取两者较小值，不为此扩展模型上下文。例如模型支持32K或更长时取32768，模型仅支持8K时取8192。窗口容纳完整模板、正文、问题及回答空间，不能将32768全部当作正文预算。所有长文候选采用同一模型适配后的上限，短文章仍按实际长度使用，不要求每篇达到32K；不另做16K／32K长度搜索；两段的实际曝光与费用另定。具体模型的资源需求及GPUh仍需按实际训练条件核算，历史Qwen长输入可运行不等于所有模型均已验证。

复用[现有三来源配方记录](../experiments/cat_aligned_protection_20261028/README.md#固定配方与数据)和[长文本监督经验](experience/lessons/data/supervision.md#kd-and-data--长文本sft须核对截断后的真实监督2026-10-04)，按目标模型记录实际输入长度、有效监督和费用；旧NarrativeQA的16–32K输入仅是历史条件，本轮没有自动采用16K下限，历史配方也未证明当前基线的最优比例。

<a id="stage2-data-search"></a>

**短文数据搜索前的更新范围比较（2026-11-10修订）：** 在同一冻结压缩基线上，用原数据配方（知识A、无新增长文），按[七种D／P／B组合及赢家模块范围](#stage2-main-code)先选更新范围。固定本轮损失、优化设置、训练预算和完整八项口径；每份完整500步、评125／250／375／500节点。P为整数与scale联合QAT，B固定敏感度版本；活动组在此轮统一采用下文[共同AdamW起点](#stage2-short-optimizer)，后续按绑定规则比较Muon；输入长度等其余执行设置仍待落实。

范围赢家作为知识数据搜索的共同范围，条件完全相同的轨迹复用为知识A。短文最终采用的参数组／模块清单与checkpoint分别记录，普通长文和OPD继承该范围，不将其称为已在所有阶段证明最优。短文知识数据仍只搜一次A–E，不为每种范围重新搜索全部数据配方。

**渐进接续（2026-11-09，用户最新确认）：**

| 阶段 | 输入与本段工作 | 评测与下一步 |
| --- | --- | --- |
| 短文蒸馏恢复 | 同一冻结压缩基线；先比较七种D／P／B组合及赢家模块范围，再比较知识A／B／C／D／E，随后超参数、优化器，最后选阶段最佳节点；范围与数据轮采用已确认共同AdamW起点 | 范围／知识候选沿完整八项选优；选定短文阶段checkpoint补完整LongBench，形成同一模型九项结果 |
| 普通长文蒸馏 | 从同一选定短文checkpoint沿用短文训练范围比较L1／L2／L3，再给赢家补一次90%长文＋10%短文对照，更新范围继承短文、不重搜；选好数据后依次搜索主编码→解码器→保护的半值／原值／两倍学习率，再比较绑定AdamW／Muon，未活动组跳过；回答位置top100＋集合外总概率蒸馏、温度1；每题答案先平均、来源内再按题平均；其它优化设置／预算待确认 | 完成预定训练后，以各候选最好已评节点的完整九项选优；所有恢复节点均更差时保留本阶段训练前模型；不能仅凭LongBench提高认定综合更好 |
| 条件性长文OPD | 普通长文搜索及已触发的256步对照完成后，仍未达到九项下降≤1个百分点才进入；绑定选定的前阶段checkpoint，固定短文选出的更新范围，不混短文；重新比较L1／L2／L3三份纯长文配方 | 达标则转验收；未达标按[OPD进入规则](#stage2-opd-entry)接续，不重新比较训练组合，超参数／优化器按[搜索表](#stage2-opd-optimization)推进，其余训练条件／额度仍待确定，不自动启动 |

短文范围与知识数据候选均从同一冻结压缩基线独立训练：七种组合后只给赢家新增注意力／MLP两份模块对照，范围胜者复用为知识A，再跑知识B／C／D／E，通常共7＋2＋4＝13份。这不是短文全部超参数搜索的总预算，空组／等价配置按真实参数去重。各候选固定本轮目标、优化设置和题目预算，只继承选中的设置，不在不同搜索候选之间累积训练。后续普通长文继承选定的短文模型权重及更新范围，同一后续阶段内仍使用共同真实父checkpoint，重新初始化优化器。

<a id="stage2-short-optimizer"></a>

**短文的共同优化起点（2026-11-11已确认）：** 先固定原数据及下表参数，比较七种更新组合并只给赢家细查模块范围；再固定选定范围及同一套起点，比较知识数据A–E。下表用于建立可比较的训练条件，不提前执行超参数搜索，也不将范围与数据展开为联合网格。范围和数据选定后，才按B→D→P逐组搜索学习率，最后比较绑定AdamW／Muon；每份训练均从本阶段共同压缩基线独立开始，只继承设置。

| 设置 | 共同起点／固定值 | 后续搜索 |
| --- | --- | --- |
| 优化器 | 活动组统一AdamW | 各组学习率选定后，比较绑定AdamW／Muon |
| 主编码B基础学习率 | 2e-5 | 1e-5／2e-5／4e-5 |
| 解码器D基础学习率 | 1e-5 | 5e-6／1e-5／2e-5 |
| 保护P基础学习率 | 整数代理0.03、scale可训练log_delta 0.001 | 共用倍率：0.015／0.0005、0.03／0.001、0.06／0.002 |
| AdamW内部参数 | betas=(0.9,0.999)、eps=1e-8、weight_decay=0 | 固定，不增内部参数对照；Muon配方的辅助AdamW参数也沿此设置 |
| 梯度裁剪 | 累计全任务4条样本的梯度后，仅将活动D／P联合做L2范数裁剪，上限1.5；B不做范数裁剪 | 固定，不增裁剪搜索 |

未活动组跳过；D、P和B各自的学习率及优化器状态保持独立。各学习率轮在共同AdamW条件下比较，继承前轮胜出倍率、未搜索组仍用参考值；同条件原值结果复用。同轮候选可并行，下轮等待本轮选优。Muon对齐使用本阶段共同父、胜出数据与真实4条样本累计梯度，D／P按上述规则裁剪、B不裁剪；各组独立换算且沿用已选倍率，其矩阵组织与内部设置沿已确认绑定规则，不新开搭配或倍率回访。

例如范围选中“注意力D＋P”，知识A–E都保持这一范围，D仍先用1e-5、P用0.03／0.001；数据选优后再搜索D、P学习率，B轮跳过。这些数值是统一参照，不代表已证明最优。500步、每次4条、5步预热后余弦及四次八项评测保持，不增加候选；输入长度、数值精度、短文选点细节及实际GPUh仍须落实，现有在途批次不变。

<a id="stage2-short-batch"></a>

**短文每次更新累计4条样本（2026-11-11已确认）：** 短文阶段范围、数据、学习率和优化器候选的有效batch固定为整个训练任务合计4条；累计这4条样本的梯度后更新一次参数，不按GPU数额外乘4。可以按资源拆分micro-batch并累积梯度，但总样本数、既定数据配方和损失归约保持；不能直接平均不同微批的loss均值而改变原有样本／token权重。本轮固定4条，不增加4／8条的batch对照。

每份完整500步训练共2000次样本呈现，N_S份不同常规训练共500N_S次更新、2000N_S次呈现及4N_S次节点完整八项评测。相同样本再次出现仍计一次呈现，呈现数不等于不同样本数或token量；单独记录来源、重复情况、有效token和实际GPUh。范围＋知识数据通常13份时，对应6500次更新、26000次呈现、52次节点八项，后续调参另计；匹配结果复用不重复计数。这里只固定短文每次更新的总量，抽样细节、输入长度、数值精度及实际费用仍须落实；普通长文和OPD既定每次8题不变。

<a id="stage2-short-schedule"></a>

**短文三组共用5步预热＋余弦日程（2026-11-11已确认）：** 短文阶段的范围、数据、学习率及优化器候选均使用完整500步日程；活动B、D、P共用5步线性预热后半周期余弦下降的倍率。各组保持自己的基础学习率及已选搜索倍率，Muon再按各自κ换算，不能把共用日程解释为共用学习率数值或优化器状态。未活动组跳过，不增加恒定日程对照。

计数沿[主编码已确认公式](#stage2-code-schedule)，取T=500、W=5，第k次更新使用s(k−1)；前六次更新的倍率依次为0／0.2／0.4／0.6／0.8／1，之后按完整500步日程下降。D辅助AdamW参数也跟随该组日程，B的独立更新器须实际应用相同倍率。各候选仍在125／250／375／500步保存并测完整八项，不因选中125步而把训练改成125步日程；评测和正常续跑不重置日程。本次只固定短文共同调度，不增加候选或评测，基础学习率与固定优化参数按[共同起点](#stage2-short-optimizer)，其余执行适配仍待落实；尚未据此修改或运行训练代码。

<a id="stage2-state-handoff"></a>

**阶段间状态接续（2026-11-10已确认）：** 进入新的恢复阶段时，保留选定checkpoint的模型参数，重新建立该阶段的优化器；不继承前阶段的动量、二阶统计或优化器步数。短文→普通长文、普通长文→条件性OPD均执行此规则，新阶段从自己的第0步及独立学习率日程开始；各阶段分别确定日程；普通长文首轮已定128步／2步预热／余弦下降，OPD已定[无预热／恒定学习率](#stage2-opd-schedule)，短文D／P／B已统一[500步／5步预热／余弦下降](#stage2-short-schedule)，各组基础学习率仍独立。参数仍来自选定模型，不重新随机初始化。阶段内部每个独立搜索候选也从共同父checkpoint及新优化器状态出发，仅继承已选超参数。

例如短文第375步入选，普通长文载入这份模型参数、从新优化器及本阶段第0步开始；不会把普通长文第一步记成短文第376步。同一候选因中断而续跑则恢复完整模型、optimizer／scheduler／RNG及数据进度，保持原训练日程，不按跨阶段规则重置。沿[既有checkpoint接续语义](experience/lessons/lifecycle/checkpoint.md#checkpoint-lifecycle--下次怎么做)执行，不新增训练候选；本条不修改一阶段逐类恢复或其它已批准批次。

同轮候选可并行，依赖的搜索轮和恢复阶段顺序接续；不为并行而从不同短文父生成可直接比较的长文结果。各阶段保留实际checkpoint来源、完整指标和新增费用，后续训练可能改变前段已恢复能力，分阶段本身不保证九项提高或能补回全部长文损伤。旧经验已有完整OPD较TF九项微升而LongBench下降的例子，不能外推本三段新方案已经有效，见[域损失与OPD证据边界](experience/lessons/post_recovery/objectives.md#kd-and-data--域损失clip和opd保留的真实贡献)。

**首轮共同训练步数与评测节点（2026-11-09已确认）：** 短文七种参数组合、赢家模块范围与知识A／B／C／D／E数据搜索，每份不同配置均完成500步，在125／250／375／500步保存并评完整八项；十三份不同训练通常合计6500次优化更新、26000次样本呈现、52份节点八项，适用的范围胜者轨迹及其四节点直接复用为A，不重复计数。各节点属于同一500步学习率日程，不能把125节点改成125步独立日程；本轮不沿用一阶段250短筛提前结束候选。三组已采用上述统一500步日程及全任务每次4条的有效batch；共同优化起点已确认，实际抽样／token曝光与输入长度、数值精度、节点选择与同分规则及GPUh仍须定稿，不将短文长度自动延伸到后续长文或OPD。

**阶段评测与预算：** 九项仍为当前八项及完整LongBench21宏平均等权合成。短文搜索使用完整八项的既定口径；短文阶段交接及两段长文的阶段比较用完整九项。短文首轮保存／评测节点已按上段确认；跨阶段已确认保留模型参数、重新初始化优化器并启用本阶段独立日程；普通长文首轮已确认128步、在32／64／96／128步评完整九项，最好已评节点选优及0步保底；是否进入OPD按[已确认达标分支](#stage2-opd-entry)决定；OPD首轮已确认[128步、每32步评九项、最好节点及0步保底](#stage2-opd-length)；OPD日程已定[无预热／恒定学习率](#stage2-opd-schedule)；OPD同分按[已确认规则](#stage2-opd-ties)处理；短文节点选择、D／P日程与同分规则，以及普通长文其余执行条件仍待确认；B日程按[单独确认规则](#stage2-code-schedule)执行。新方案按各阶段单独核训练／评测成本，不沿用旧11份总数，不因本次流程确认启动训练。

<a id="stage2-reference-objective"></a>

**知识题共同训练目标（2026-11-09已确认）：** 短文范围预选及知识数据搜索中的知识子池（原MMLU辅助题、Web、Med）统一采用原始BF16教师四选项概率与标准答案各半的既有混合目标。教师和学生均在该题相同顺序的四个候选内归一化；设教师概率为p_F、合法train标准答案的one-hot分布为y，则目标m=0.5p_F＋0.5y，沿仓库既有前向KL(m∥p_student)训练，只混合一次。目标是四选项内的分布，不是全词表的答案token蒸馏；知识来源及其它数据的抽样份额保持已定配方。

例如原始BF16对A/B/C/D的概率为0.6/0.1/0.2/0.1，而标准答案为C，混合目标为0.3/0.05/0.6/0.05。“各半”是同一道题的目标权重，不是半数题只用教师、半数题只用标准答案。目标模型的选项编码与因果位置按自身tokenizer／模板适配，不照搬其它模型的token ID；复用[混合目标的既有语义与证据边界](experience/lessons/data/teachers.md#kd-and-data--混合gold目标的margin与固定身份读出)，不把旧条件中的效果视为当前模型的普遍最优。

知识题目标仅用于上述知识子池，不自动用于通用指令、其它七任务或长文。通用／其它七任务按下段已确认目标；普通长文蒸馏沿下文已定参考答案及top100＋集合外总概率方式；条件性OPD按后文已确认方法适配。后续独立损失搜索仍待讨论。

**通用与其它七任务共同目标已确认（2026-11-09）：** 短文范围预选及知识数据搜索中，沿用一阶段固定训练问答文本和原始BF16教师的纯蒸馏：`loss_type=kl_top_mass`、`top_k=100`、`temperature=1.0`、`prompt_loss_weight=0.3`，回答token权重为1。师生读取相同的原训练文本前缀，不让学生先生成回答、不为这些数据新增答题裁判或标准答案CE损失。原训练回答仍作为输入前缀的一部分；不加CE不等于丢弃原回答文本。教师最可能的100个词保留各自概率，集合外概率合为一项，沿现有前向KL计算，不在top100内另做条件归一化。

例如PIQA训练题答案为A，仍沿这份训练问答逐位置学习教师概率，不另加一项强制预测A的答案损失。单次此类损失沿[现有实现](../train_utils/distill_loss_core.py)按有效token加权归约：`(回答KL之和＋0.3×问题KL之和)／(回答token数＋0.3×问题token数)`，保留原因果位移、mask与padding处理；0.3不是“问题占总损失30%”。语义见[当前loss公式](experience/lessons/data/supervision.md#kd-and-data--当前loss公式日志窗口与完整ce配方)。同一训练阶段内多来源损失按下段题目占比规则合并；本决定不改变已定知识题混合目标或条件性长文OPD，不增加训练候选，不证明纯教师蒸馏在二阶段最优。

**同一阶段内的来源合并（2026-11-09已确认）：** 先按各自既定方法计算每个来源的平均损失，再按该来源题目占比合并；例如同一阶段抽到45条通用、45条任务、10条长文时，三组外部系数合计为0.45／0.45／0.10，组内继续按各来源份额计算。此例只说明用户已确认的合并规则，不恢复已经退出的10%混训方案。采用新渐进方案后，各阶段只合并本阶段实际存在的来源，不把前后阶段的损失相加。OPD每题4份回答仍先按其内部规则归约，不额外把来源权重乘4；系数不是实际梯度贡献比例，也不代表算力份额。普通长文和OPD的全任务有效batch均已分别确认8题；两段的具体来源组织及OPD内部归约按各自规则执行，不能在按来源抽样后无依据地重复乘权。

接下来确定普通长文其余执行条件、短文节点选用与数据执行细节，以及短文实际预算、普通长文实际费用和OPD数值精度／执行适配与实际预算；裁判提示已确认，首次核对按下文和项目现有规则执行。本次只更新规范，不启动实验或更改既有批次。

<a id="stage2-long-selection"></a>

**普通长文的节点选优与0步保底（2026-11-10已确认）：** 每份候选按事先确定的节点保存并评完整九项，完成统一的预定训练长度后，以自身最好已评训练节点的未舍入九项均分参与本轮配置比较，不只看最后一步。同一普通长文阶段各轮继续共用选定短文checkpoint作为真实训练起点，仅继承前轮胜出的设置；不因中途成绩提前结束候选或跳过已定搜索。此规则覆盖数据、参数范围、优化器及学习率比较，不新增训练候选。

阶段成品在本阶段全部已测合法恢复节点中选优，并保留训练前模型作为0步对照；只有0步九项均分严格高于全部恢复节点时，才保留训练前模型；与最佳恢复节点同分时保留恢复节点。比如0步66.0、中途66.3、终点66.1，应保留66.3；若所有恢复结果都低于66.0，则保留0步。0步的同口径九项结果可复用，不重复评测。搜索胜出的数据配方与最终选定checkpoint分别记录，回到0步不把该原模型标成已应用某份长文配方；是否继续OPD按[已确认达标分支](#stage2-opd-entry)决定。

<a id="stage2-long-ties"></a>

**普通长文精确同分处理（2026-11-10已确认）：** 按原始未四舍五入的九项均分比较，不将表格显示相同或近似相等当作同分；适用于本阶段128步搜索与条件256步对照。

1. 同一训练轨迹先取最高分；多个节点精确同分时取步数较晚者。例如64与96步均为66.3，取96步。
2. 不同配置／训练轨迹的最佳节点同分时，优先保留本轮开始前的已有赢家；它不在并列集合或尚无赢家时，按预先固定的配置ID、再按轨迹ID升序取唯一结果，不按候选完成先后选择。原128步赢家与新增256步对照同分时保留原赢家，不跨轨迹直接按步数大小排序。
3. 最佳恢复结果与共同训练前0步同分时保留恢复结果，0步只在严格胜过所有恢复节点时入选。

本规则不增加训练、复测或费用，不自动用于短文；OPD按[单独确认的同分规则](#stage2-opd-ties)执行。条件长程仍要求128步严格胜过自身前三节点及0步；例如96与128同分虽选择128步，也不会因此触发256步对照。

<a id="stage2-long-length"></a>

**普通长文首轮长度与节点（2026-11-10已确认）：** 数据、学习率和优化器搜索的每份不同候选均完成128次优化器更新，在32／64／96／128步保存并评完整九项；同条件结果复用不重复训练或计费。四个节点属于同一128步训练日程，不各自改成独立的32／64／96步日程，也不套用旧500步日程的前128步。统一使用下文[2步预热的128步余弦日程](#stage2-long-schedule)；本轮不按中途排名提前淘汰候选。

设普通长文常规搜索实际不同轨迹数为N_L，则合计128N_L次参数更新、4N_L次节点完整九项；不再使用取消范围轮前的13／11份计数。实际按合法配置、去重和完整条件复用核算，训练前0步九项可复用。每份相比只评终点增加3次完整九项评测，不增加训练次数。每次更新已固定全任务累计8题，呈现量见下文；实际micro-batch／累积实现、来源曝光及GPUh仍须核算。

128步仅是首轮统一长度，不证明已经充分恢复；满足下文条件时追加一次[256步对照](#stage2-long-extension)。精确同分处理沿上节规则，实际GPUh仍待核算，不把本长度或选点规则自动用于短文／OPD，不据此启动训练。

<a id="stage2-long-schedule"></a>

**普通长文共同学习率日程（2026-11-10已确认）：** 首轮全部候选采用128步总日程、2步线性预热，随后按半个余弦周期下降至0（`num_training_steps=128`、`num_warmup_steps=2`、`num_cycles=0.5`）。2步对应128步的1%向上取整。各活动组共用同一日程倍率，乘各自已确定的基础学习率；B已按[主编码日程](#stage2-code-schedule)确认采用本规则，仍须适配其独立更新调用；Muon先完成各组初始更新量换算，再乘本日程倍率。本轮固定这一日程，不新增恒定学习率或其它日程对照。

沿Transformers现有`get_cosine_schedule_with_warmup`的计数语义：令u为已完成的优化器更新数，`s(u)=u/2`（0≤u<2），之后为`0.5×[1+cos(π×(u−2)/126)]`（2≤u≤128）。初始化时u=0；第k次优化器更新使用`s(k−1)`，完成`optimizer.step()`后再执行`scheduler.step()`。因此前三次更新的学习率倍率分别为0／0.5／1，最后一次使用接近0的正倍率，128次更新完成后日程倍率归零。保存节点仍按已完成更新次数32／64／96／128计，恢复同一候选时保留其日程状态。

初始Muon换算仍用已定非零基础学习率测量更新提议，不使用预热起点的零倍率；不会提前消耗正式训练更新。此处128／2参数用于普通长文首轮；条件长程对照按下文256／3参数重建日程，不自动用于短文／OPD；它不改变128步、每步8题及四次完整九项评测的计数。本次只更新规范，已核现有调度函数定义，未改动或运行训练实现。

<a id="stage2-long-extension"></a>

**普通长文的条件长程对照（2026-11-10已确认）：** 所有常规128步搜索完成并确定最终入选配方后，仅当该配方的128步九项均分严格高于自身32／64／96步及共同训练前0步时，追加一条完整256步对照。任一所比节点与128步同分即不触发；不要求32→64→96之间单调提高。每个模型在本普通长文阶段最多追加一次，不给每轮赢家分别追加，也不因256步仍最高而自动再加512步。

从同一选定短文父checkpoint重新训练，重新初始化优化器；固定入选数据配方、活动参数组／模块范围、损失、优化器选择及学习率搜索倍率，不再展开参数搜索。采用256步半周期余弦日程、3步线性预热（256的1%向上取整）；沿前节相同计数语义，令u为完成更新数，预热倍率`u/3`，之后为`0.5×[1+cos(π×(u−3)/253)]`。不是从已结束的128步模型及日程上续接。Muon起点沿已有初始更新对齐规则确定，所用数据条件变化时按该规则重算并记录κ，不新增倍率搜索。

每次更新仍全任务8题，共2048次呈现；用原固定种子及已确认的来源配额／来源内题序规则，按新总量生成数据安排。90%／10%时为1843次长文＋205次短文，长文内部再按原配方取整。该对照同时增加实际呈现量并改变学习率时域，不能解释为保持全部输入与日程不变的单纯步数效应。在32／64／96／128／160／192／224／256步保存并评完整九项，新轨迹的前四节点不能复用旧128步轨迹的评测结果。

新增费用为一条256步训练、2048次呈现及8次节点九项，实际GPUh另计，不按仅追加128步计费。原有全部已测结果继续参与选优；新对照更差时保留原赢家，0步保底保持。触发后共N_L＋1条轨迹、128N_L＋256次更新、4N_L＋8次节点九项；N_L按实际合法配置与复用核算，B学习率按[三档规则](#stage2-code-lr)计费，其余待定设置不自动扩成搜索。是否进入OPD在上述流程完成后按[已确认达标分支](#stage2-opd-entry)决定；本次仅更新标准，不启动训练或扩大已批准批次预算。

<a id="stage2-long-batch"></a>

**普通长文每次更新的题目量（2026-11-10已确认）：** 首轮各搜索候选的有效batch固定为全训练任务合计8题，不是每张GPU各8题；累计这8题对应的梯度后更新一次参数。可逐题计算或按资源分配micro-batch与梯度累积，保持全任务每次更新的8题总量及下文已确认的按题损失归约，不要求8篇长文同时驻留显存。本轮固定此值，不新增batch大小搜索。

纯长文候选的8题全部来自已选长文配方；90%长文＋10%短文对照仍合计8题，不在8道长题之外额外添加短题。来源比例沿已定配方，来源内部按下文洗牌题序消费；来源间按下文已确认的整段配额与固定洗牌顺序安排。每份128步共1024次题目呈现；N_L份合计1024N_L次，实际随合法候选及结果复用计数。呈现次数不等于不同题目或文档数，也不代表相同token量；数据池、重复次数及实际费用另核。此设置只适用于普通长文阶段，不改变短文或OPD的batch、OPD每题4份回答规则。

<a id="stage2-long-sampling"></a>

**普通长文来源内的抽题规则（2026-11-10已确认）：** 以每个问答为一道题，在各来源符合既定train／完整上下文长度条件的题池内，用固定随机种子打乱题序后依次取题；本轮题池未用尽前，不再次抽取同一题目ID。用完后重新洗牌进入下一轮，整个多轮题序可由固定种子复现。同一篇文章的不同问题仍是不同题目，不将按题抽样另改为按文章均衡。

各来源的题序分别固定；同来源、同题池与同用量的候选复用相同题序，各独立训练从自己的题序起点消费，不接续另一候选的抽题游标。例如题池500道、本轮需要128次呈现，则取第一轮的128道；需要700次时，先用完500道，再从第二轮取200道。记录题池版本、种子、实际题目／文档ID及重复轮次，统计呈现量、不同题目数和不同文档数，不能互相替代。

本条固定普通长文来源内部的抽取方式，来源间按下文整段配额安排；不改变来源配方、128步或训练／评测候选数。90%／10%对照的短文部分仍沿选定短文配方与既定规则；OPD按[独立确认的抽题与续训规则](#stage2-opd-sampling)执行。本次仅改规范，尚未修改或验证采样实现。

<a id="stage2-long-source-quota"></a>

整数计算先分长文／短文两部分，再在长文内部按已选来源比例分配。各层先对理想名额取下整，剩余名额按小数余数从大到小各补1；余数相同按固定source_id字典序取先者（长文ID为`hotpotqa`、`narrativeqa`、`qasper`）。这是落实配额的固定取整方式，不新增比例搜索。纯长文有1024次；90%／10%对照为922次长文与102次短文，实际分别约90.039%／9.961%，记录目标比例与实际比例。

<a id="stage2-long-kd"></a>

**普通长文蒸馏的答案来源与监督位置（2026-11-09已确认）：** 接续选定短文checkpoint，使用合法train中的完整原文、问题和参考答案。师生沿同一参考答案前缀前进，只在回答对应的预测位置学习冻结原始BF16教师的下一token概率；全文及问题提供上下文，不计入本项蒸馏损失。学生不先生成回答，不额外让BF16生成替代答案，也不接入裁判奖励或标准答案CE。参考答案提供固定输入前缀，不将其one-hot标签另加成监督目标。

例如参考答案为“Paris”，师生在相同问题／原文与答案前缀下比较下一词概率；这与条件性OPD先让当前学生采样4份回答、再教师指导及裁判评分不同。此轮不增加“参考答案／教师生成答案”的训练对照。按题归约已按下文确认；来源内抽题已按[固定洗牌题序](#stage2-long-sampling)确认；来源间按[整段整数配额](#stage2-long-source-quota)安排；其它优化设置／预算仍待确认，不把答案来源或损失定义的选择称为恢复效果已验证。现有静态TF长文训练只供参考答案接续方式参考，其全词表KL不作为本轮目标，见[静态QA训练入口](../experiments/mlp_m4096_cmcc_20261101/fit.py)和[同父目标与OPD经验边界](experience/lessons/post_recovery/objectives.md#kd-and-data--域损失clip和opd保留的真实贡献)；不照搬其旧模型父源、数据量或跨域权重。

**目标分布已确认（2026-11-10）：** 普通长文蒸馏采用`loss_type=kl_top_mass`、`top_k=100`、`temperature=1.0`。在每个回答预测位置，以冻结BF16教师选出的前100个词作为共同集合，师生分别保留这100个词在全词表归一化下的概率，并将集合外全部词的概率各自合成一项，再计算教师到学生的前向KL。不是各选各的top100，也不在100个词内部重新归一化；原文／问题位置不计损失（对应`prompt_loss_weight=0`），保持已确认的因果预测位置和有效回答mask。沿用[现有损失实现](../train_utils/distill_loss_core.py)中`compute_kl_top_mass_token_loss`的定义；token／题目间按下文已确认规则归约。本轮只选此起点，不增设全词表KL对照，不改变短文阶段的prompt权重0.3或条件性OPD的k1目标。

<a id="stage2-long-reduction"></a>

**普通长文的按题损失归约（2026-11-10已确认）：** 对每道长文题i，先在其有效回答预测位置取top100＋集合外概率KL的均值：`L_i = sum_t KL_i,t / n_i`，其中n_i为该题有效回答token数。再对同一来源s的题目平均：`L_s = sum_i L_i / N_s`，N_s为该来源参与本次归约的题目数。原文、问题和padding不进入回答损失或分母；原有因果位置与有效回答mask保持。

例如同一来源两题答案分别长2与20个token，来源损失为`(L_1 + L_2) / 2`，不会仅因答案长而给第二题20／22的系数。此处规定的是损失系数，不保证两题实际梯度贡献相等。跨来源仍沿已确认的题目占比规则合并，只加权一次；来源内按已确认题序抽取，来源间按整段配额生成固定标签序列、每8题组成一次更新。90%／10%候选中的短文部分继续使用自身既定目标与归约；不把本条扩展为短文或OPD的损失改动。

实现时复用[现有逐token KL计算](../train_utils/distill_loss_core.py)，按每题回答mask归约后再组合；该文件的`reduce_weighted_token_loss`直接对多题整批调用是按有效token总数归一化，不等于本条的按题平均。micro-batch拆分和梯度累积须保持同一组题目的上述系数，不能因分批方式改变题目权重。本条不增加训练或评测候选；本次仅更新规范，尚未改动或验证训练实现。

<a id="stage2-long-trainable"></a>

**普通长文更新范围（2026-11-10最新确认）：** 直接继承短文阶段选定的D／P／B活动组合与实际模块清单，从该阶段选定checkpoint出发。原普通长文D／P／D＋P组合比较和全模型／注意力／MLP模块范围比较均取消；不补开七组合搜索。长文数据及后续超参数／优化器候选都保持这一范围，只更新已选组，未选组及其它参数冻结。

例如短文选中“注意力的D＋P＋B”，普通长文仍只更新注意力中的这三组；若短文选择只训B，不能因原长文表只列D／P就默默改成只训decoder。数据轮仍比较L1／L2／L3，再给赢家补90%长文＋10%短文对照；随后搜索超参数与优化器、按全部已测合法节点选阶段成品。范围继承不等于优化器状态继承，也不证明该范围是长文阶段独立最优；省去范围对照是已确认取舍。B组的共同优化设置及适配尚待补齐。

<a id="stage2-long-optimizer"></a>

**普通长文的共同优化起点（2026-11-10已确认）：** L1／L2／L3数据比较及赢家90%／10%对照，固定短文已选更新范围；其中活动D／P／B统一使用AdamW及下列调度前基础学习率；不因继承范围而复制短文的优化器状态。只设置实际活动组；不继承短文阶段赢家的优化器或学习率，也不因省略某组而将其学习率转给其它组。

| 参数组 | AdamW基础学习率 | 参数含义 |
| --- | ---: | --- |
| 解码器D | 1e-5 | 活动解码器可训练参数 |
| 保护整数 | 0.03 | 联合QAT的浮点整数代理，部署仍为INT8 |
| 保护scale | 0.001 | 既有正scale参数化的可训练log_delta，不是直接给部署scale加0.001 |
| 主编码B | 2e-5 | 敏感度坐标下的浮点代理，前向及部署仍为硬码 |

这些是已有恢复学习率的统一搜索参照，不是已证明适合当前长文阶段的最优值。选好数据后，按最新顺序先搜索活动组的三档学习率，再比较绑定的AdamW／Muon；按[主编码B→解码器D→保护P](#stage2-lr-order)推进，不新增起点对照。优化器按[阶段接续规则](#stage2-state-handoff)重新初始化；训练日程与预热沿[128步余弦／2步预热](#stage2-long-schedule)；AdamW内部参数、Muon内部设置及联合梯度裁剪按下文[共同固定参数](#stage2-long-optimizer-fixed)执行；本次不自动套用一阶段的全部优化设置或启动训练。

<a id="stage2-long-optimizer-fixed"></a>

**普通长文的共同固定优化器参数（2026-11-10已确认）：** 以下参数作为首版共同起点，适用于128步搜索及符合条件时的256步对照；不增加beta2、裁剪阈值或Muon内部参数搜索，也不宣称这些值已是最优。

| 设置 | 固定值与范围 |
| --- | --- |
| AdamW | `betas=(0.9, 0.999)`、`eps=1e-8`、`weight_decay=0`；所有实际使用AdamW的活动组均采用，包括Muon配方中的辅助AdamW参数 |
| Muon | 沿已确认实现的NS5、`momentum=0.95`、Nesterov及既有shape scale；保留decoder矩阵分组和保护scale每投影一行适配 |
| 梯度裁剪 | 每次更新累计完整8题梯度后，仅对活动D／P参数的联合梯度做一次全局L2范数裁剪，上限1.5，再交给各自优化器更新；B不计入联合范数，也不另做范数裁剪 |

例如D／P联合梯度范数为3，先将D／P梯度整体缩至约1.5，B保持未做范数裁剪的梯度，再由各自优化器计算参数更新；不据此推断AdamW或Muon的参数改变量也恰好减半。梯度按前述损失归约及来源合并规则累计，不先分别按题目、微批或D／P组各自裁剪。D／P初始Muon换算使用同一份8题累计、按此规则裁剪后的D／P梯度与新优化器状态副本，仍按非零基础学习率测量；其分组κ和正式训练更新保持原规则。

本条的D／P固定参数保持，B按[绑定规则](#stage2-code-optimizer)使用AdamW／Muon；B按[统一分工](#stage2-code-gradient)不参与范数裁剪；Muon适配仍待实现验证，绑定类型不改变上述裁剪分工。数值精度、实际实现接线与GPUh等执行条件仍须固化；本次仅更新规范，未修改或运行训练代码。

**普通长文的优化器比较（2026-11-10已确认）：** 完成数据及实际活动组的学习率搜索后，固定已选范围和学习率倍率，比较绑定D／P／B的AdamW与Muon两套配方；不固定继承短文阶段的优化器，也不增加组间交叉搭配。学习率已按B→D→P完成，Muon步长按[主编码独立换算](#stage2-code-muon-lr)执行。

| 配方 | 解码器D | 保护P | 主编码B |
| --- | --- | --- | --- |
| AdamW | 活动解码器使用AdamW | 活动保护整数与scale共同使用AdamW | 活动主编码代理使用AdamW |
| Muon | 活动解码器矩阵使用已确认Muon配方；原辅助参数沿既有AdamW分工 | 活动保护整数与scale都真正使用Muon，scale沿每投影一行适配 | 活动主编码代理按完整编码向量成行使用Muon；实现适配待完成 |

D／P／B的优化器类型按[二阶段绑定规则](#stage2-code-optimizer)共同切换，P整数及scale一起切换；仅任一组活动时仍比较两套，不重新开放未选参数组。沿[已确认的绑定语义](#recovery-optimizer-binding)和[scale每投影一行适配](#recovery-scale-muon-row)，不因名为Muon就把保护scale留在AdamW。绑定类型不等于各组学习率数值相同；AdamW参考学习率已定为上表数值，Muon按下文三组初始更新对齐确定起点，沿用前轮[三档学习率搜索](#stage2-long-lr)选中的倍率，Muon按当前条件换算后应用该倍率；不新增优化器切换后的学习率回访，也不能直接复制一阶段或旧父源的换算值。此处三组换算仅指D矩阵、P整数与scale；B另按[独立κ_B规则](#stage2-code-muon-lr)换算，不能复用其中任一倍率。

两份从共同短文父checkpoint独立训练，固定胜出数据、可训练对象及模块范围、损失、题目预算、训练步数和评测节点，按完整九项均分选优；已有完全匹配的配置和结果可复用。同条件复用一份时通常只新增一份训练及对应九项评测，不再计入原组合／模块范围对照费用；若两套起始设置都不匹配已跑配置，则新增两份，实际计费。这仍不是全部普通长文搜索预算，不扩大数据或模块组合，也不自动应用于后续OPD；本轮只定算法候选，不启动训练。

**普通长文Muon的起始步长（2026-11-10已确认）：** 使用当前共同短文父checkpoint、胜出数据配方、活动参数组与模块范围，从本轮真实训练输入取得初始梯度，分别计算decoder矩阵、保护整数代理、保护scale可训练log_delta三组的换算倍率κ_D、κ_q、κ_scale；未活动组跳过，不合并三组范数，也不逐投影独立定倍率。沿[既有初始更新匹配定义](#recovery-muon-scale)的参数分组、更新范数与scale每投影一行语义，绑定本阶段实际优化条件，不引入LoRA组或一阶段500步／短筛规则。

在参数和优化状态副本上，用相同真实8题累计且仅对D／P联合裁剪的初始梯度、从两套候选各自重新初始化、尚未更新的优化器状态计算AdamW和未标定Muon的未舍入参数更新。取各组`κ_g = ||ΔAdamW_g||F / ||ΔMuon_g||F`，将Muon基础学习率设为`κ_D×1e-5`、`κ_q×0.03`、`κ_scale×0.001`。测量使用非零参考基础学习率，不因日程初始LR为0而计算零比值；不提前更新真实模型或污染正式训练状态。整数组对齐浮点代理更新、scale组对齐log_delta更新，不用INT8翻转数或部署scale差值代替。decoder仍由AdamW处理的辅助参数不乘κ；无法取得有效比值的活动组按既有规则报告并停止受影响候选。

例如相同参考学习率下，Muon整数更新为AdamW的5倍、scale为2倍，则对应Muon起点为0.006和0.0005；decoder单独换算。同一父、数据、范围、初态及其它优化条件下，κ在后续学习率倍率比较及训练轨迹中固定，仅改变倍率不重新计算；这些条件改变时重新换算，不跨模型或旧父源照搬。记录真实输入／梯度来源、分组、两种更新范数、κ及实际学习率，随候选状态保存。换算开销计入实际费用，不新增训练候选；它只对齐初始参数更新大小，不证明后续轨迹或恢复效果相同，最终按完整九项比较。优化器初态沿已确认的重置规则，内部参数及联合裁剪沿[共同固定参数](#stage2-long-optimizer-fixed)；其余执行条件与实际预算另行落实。

<a id="stage2-long-lr"></a>

**普通长文的学习率搜索（2026-11-11顺序确认）：** 选好数据后，按共同AdamW参考起点依次搜索主编码B、解码器D、保护P；每轮比较起点的0.5／1／2倍，完整九项均分选优。后一轮继承前一轮胜出的设置，所有新训练仍从同一选定短文checkpoint独立开始，不接续上一候选训练后的权重。未参与训练的组跳过。

| 顺序 | 本轮候选：共同AdamW下的基础学习率 | 本轮保持固定（仅实际活动组） |
| --- | --- | --- |
| 1．主编码B | 1e-5／2e-5／4e-5 | 解码器1e-5、保护整数0.03、scale 0.001 |
| 2．解码器D | 5e-6／1e-5／2e-5 | 已选B学习率、保护整数0.03、scale 0.001 |
| 3．保护P | 整数／scale成对比较：0.015／0.0005、0.03／0.001、0.06／0.002 | 已选B和D学习率 |

随后优化器轮比较Muon时，将上述已选倍率应用到各组换算起点：解码器矩阵使用`m_D×κ_D×1e-5`，其AdamW辅助参数使用`m_D×1e-5`；保护使用`m_P×κ_q×0.03`与`m_P×κ_scale×0.001`，整数与scale共享同一个`m_P`。主编码使用`m_B×κ_B×2e-5`，κ_B按已确认独立对齐规则取得；各活动组倍率均已由前轮从0.5／1／2选出，不在优化器轮再次展开倍率网格，也不拆成整数与scale独立网格。κ沿前述规则固定，仅改变学习率倍率不重新标定。

每轮固定数据、训练组与模块范围、优化器、损失、题目预算、训练步数／日程及评测节点；同条件原值结果直接复用。同轮不同倍率可并行，D轮等待B轮、P轮等待D轮选优，未活动组跳过。原值可复用时，每个活动组通常新增2份训练及对应节点九项评测，三组都活动则新增6份；普通长文不再搜索范围：设g为D／P／B中活动组数，P整数与scale仍共用一个倍率轮，按现有轮次及同条件控制复用通常为4份数据＋2g份新学习率＋1份新优化器，即g=1／2／3时7／9／11份；仅B活动也含两套优化器比较。B学习率按[三档规则](#stage2-code-lr)计费，B的Muon与其它待定设置仍需落实，以实际不同轨迹数N_L核算，不据此封顶或漏掉B。这不是含短文和OPD的全流程预算；普通长文首轮长度／节点按[128步四节点规则](#stage2-long-length)执行，并固定[全任务每次更新8题](#stage2-long-batch)；按题归约按[已确认公式](#stage2-long-reduction)执行，来源间按[已定配额与顺序](#stage2-long-source-quota)执行，同分按[已确认规则](#stage2-long-ties)处理，GPUh仍待核算，不因本次定表自动启动训练。

<a id="stage2-opd-entry"></a>

**OPD进入条件（2026-11-10已确认）：** 普通长文的全部常规搜索及已触发的256步对照完成后，按上述选点／同分规则确定本阶段最好合法checkpoint，包含0步保底。使用该模型与原始BF16在同一九项口径下的未四舍五入均分，计算`Δ9 = BF16九项均分 − 当前模型九项均分`，以百分制分数相减，单位为百分点。

| 完整结果 | 后续动作 |
| --- | --- |
| `Δ9 ≤ 1.0`（含等号） | 结束本轮恢复训练，不进入OPD；转入既有验收、复现与交付流程 |
| `Δ9 > 1.0` | 进入后续有界长文OPD阶段，使用选定checkpoint作为真实父模型；训练组合及优化器／学习率按[已确认搜索顺序](#stage2-opd-optimization)执行，其余训练条件、额度及实际GPUh继续落实 |

例如BF16为70分，当前69.2分则下降0.8个百分点，转入验收；当前68.8分则下降1.2个百分点，进入OPD。此判断只在上述普通长文流程完成后执行，不因中途达标提前结束搜索，也不取消已触发的256步对照。不另加LongBench单项差距门槛。若普通长文最终保留0步，OPD父模型就是该短文阶段成品；仍只沿用数据搜索胜出的长文内部来源比例，不混短文。

达到分数目标不等于位宽、部署或整链复现已经通过，仍遵守平均约2.5bit／logical≤2.6及既有最终验收要求。本条仅确认进入条件，不增加训练候选或批准GPU预算；OPD其它搜索与执行条件继续讨论，不改变既有已批准批次。

<a id="stage2-opd-trainable"></a>

**OPD更新范围（2026-11-10最新确认）：** 固定短文阶段选定的D／P／B活动组合与模块清单，不重新搜索参数组合或模块范围。真实初态权重仍取普通长文阶段最终选定checkpoint（含0步保底），范围配置与模型来源分别记录；即使普通长文回到0步，也不将该模型误记为已按某长文配方训练。

OPD仍只在未达九项目标时进入，使用纯长文、k1教师指导＋语义奖励及已定生成方式。原三种组合或提议的七种组合OPD搜索均不再执行；先在继承范围下按共同参考优化设置比较三份纯长文数据，复用本轮赢家为后续调参控制，再按超参数、优化器顺序搜索。普通长文结果不能作为OPD参考轨迹复用，因为训练目标不同。所有OPD候选从同一父模型独立训练，新建优化器；128步及四次九项评测规则保持。B活动时不得自动冻结B以绕过适配，其设置尚待确定。本次不启动实验。

<a id="stage2-opd-data"></a>

**OPD独立数据搜索（2026-11-10已确认）：** 进入条件性OPD后，重新比较L1／L2／L3三份纯长文配方：Qasper∶NarrativeQA∶HotpotQA分别为2∶0∶6、1∶1∶6、0∶2∶6。固定短文选出的活动参数组和模块清单，三份均从同一个普通长文阶段选定checkpoint独立开始，不搜索更新范围、不混短文，也不直接采用普通长文的数据赢家。

三份共用本轮参考优化设置、k1教师指导与语义奖励、每题4份回答、全任务每次更新8题、128步恒定日程；在32／64／96／128步各测完整九项，跑满后按各自最好已评节点及既定同分规则选择数据配方。活动D／P沿本阶段已定AdamW参考起点；B活动时也用AdamW、共同学习率起点2e-5；其余设置及适配仍待确定，不能默用D／P学习率。后续只给数据赢家搜超参数、优化器，再按全阶段已测合法节点及0步保底选成品。配置继承与权重接续区分：每份调参训练仍从同一个OPD父checkpoint开始，不在数据赢家已训练权重上继续累加。

数据轮共3条训练、384次更新、3072次题目呈现、12288份学生回答及对应教师指导／裁判评分、12次节点完整九项；相比只跑一份数据，新增2条训练、256次更新、2048次题目呈现、8192份回答及对应指导／评分、8次节点九项。数据赢家轨迹在完整条件相同时复用为后续控制，不能再额外计一条“默认恢复”。普通长文蒸馏因目标不同不能抵作OPD对照。每份使用自己的当前学生生成回答，抽样按[来源配额规则](#stage2-opd-sampling)执行；GPUh按实际输入／生成／教师／裁判成本核算，以上不含首次裁判核对、B调参、优化器搜索或条件续训，本次不启动实验。

<a id="stage2-opd-optimization"></a>

**OPD优化器与学习率搜索（2026-11-11顺序确认）：** 保持短文选定的更新范围，不再比较训练组合。数据安排确定后，在共同AdamW条件下按[主编码B→解码器D→保护P](#stage2-lr-order)搜索各组三档学习率，再比较绑定D／P／B的AdamW与Muon；只给当前赢家继续下一项。每轮继承已选设置，未搜索组保持本阶段参考值；未活动组跳过，P整数与scale共用0.5／1／2倍率。Muon使用当前OPD条件的更新量换算并继承已选倍率，不另做回访。B三档为[1e-5／2e-5／4e-5](#stage2-code-lr)，其Muon步长按[独立对齐规则](#stage2-code-muon-lr)确定，其余待定实现不由顺序选择自动解决。只有B活动时仅做B学习率轮再比较两套优化器。数据轮按[已确认三配方比较](#stage2-opd-data)执行。

| 搜索轮 | 候选及固定条件 | 同条件控制可复用时新增训练 |
| --- | --- | --- |
| 数据 | 固定短文活动参数组及模块范围，独立比较L1／L2／L3；普通蒸馏结果不可复用 | 3条，数据赢家可复用为后续参考 |
| 主编码B学习率 | 共同AdamW下比较1e-5／2e-5／4e-5，D／P保持参考值 | B活动时通常2条；原值复用 |
| 解码器D学习率 | 继承已选B设置，D比较0.5／1／2倍，P保持参考值 | D活动时通常2条；原值复用 |
| 保护P学习率 | 继承已选B／D设置，整数与scale共用0.5／1／2倍率 | P活动时通常2条；原值复用 |
| 优化器 | 保留各组已选倍率，比较绑定D／P／B的AdamW／Muon；各组按当前条件独立换算 | 任一组活动通常1条；原AdamW控制复用 |

AdamW下，D三档为`5e-6／1e-5／2e-5`；P的整数／scale三档为`0.015／0.0005`、`0.03／0.001`、`0.06／0.002`。P不拆成整数与scale独立搜索。仅一个参数组活动时，跳过其它未活动组的学习率轮；不重新搜索更新组合或为其它组合补做优化器和学习率搜索，不增加回访或交叉网格。

Muon沿[既有参数分工](#recovery-optimizer-binding)和[scale每投影一行适配](#recovery-scale-muon-row)：解码器矩阵使用Muon，原辅助参数保持AdamW分工；保护整数与scale都真正使用Muon，不将scale悄悄留在AdamW。B按[二阶段绑定规则](#stage2-code-optimizer)一起切换，Muon按[完整编码向量成行](#stage2-code-row-sampling)，实现适配待完成；步长按[独立κ_B规则](#stage2-code-muon-lr)换算。只活动D、P或B时仍比较两种优化器；绑定的是类型，不是各组学习率数值。

Muon起点按[初始更新匹配定义](#recovery-muon-scale)在当前OPD父模型、胜出纯长文数据与活动范围上重算。以当前学生真实采样回答及已定教师／奖励目标产生的同一份OPD初始梯度，在重新初始化的优化器副本上分别计算D矩阵、整数代理、log_delta的未舍入更新范数，取得`κ_D／κ_q／κ_scale`；不使用普通长文参考答案KL的梯度，不照搬前阶段换算值。使用非零参考学习率，不更新真实父模型；未活动组跳过。梯度处理及优化器固定参数按[OPD共同设置](#stage2-opd-optimizer-fixed)执行：完整8题／32份回答累计后仅将D／P联合裁剪至上限1.5，B不做范数裁剪；AdamW权重衰减0等条件相同，再比较两套优化器的更新。

D／P的Muon实际基础学习率为`m_D×κ_D×1e-5`、`m_P×κ_q×0.03`和`m_P×κ_scale×0.001`，活动B另为`m_B×κ_B×2e-5`；D的辅助AdamW参数使用`m_D×1e-5`，不乘κ。`m_D`、`m_P`和活动B的`m_B`均为前轮各自从0.5／1／2选出的倍率，优化器轮不再次展开倍率搜索。同一父、数据、范围、初态及其它优化条件下固定κ；记录实际输入来源、更新范数、κ与学习率，换算开销照计，不增加训练候选。

所有新候选仍从同一个OPD父checkpoint独立训练，重置优化器及本阶段日程；只继承上一轮胜出的设置，不接续其已训练权重。固定数据／已定OPD目标、采样及本轮训练预算／评测条件，按完整九项选优。同轮候选可并行，下一轮须等待本轮选定设置；普通长文结果不能复用为本阶段控制，只有本阶段完整条件相同的结果可复用。

OPD不再产生范围对照费用，数据轮已固定3条。设g为D／P／B中活动组数，P整数与scale共用倍率轮；同条件控制可复用时，通常3份数据＋2g份新学习率＋1份新优化器，即g=1／2／3时6／8／10条。仅B活动也比较两套优化器，比旧固定Adam规则多1条128步训练及4次节点九项；D或P参与时，B绑定不再额外增加独立优化器轮。B学习率按[三档规则](#stage2-code-lr)计费，Muon按完整编码向量成行的实现及其它设置仍待落实，换算按已定独立κ_B规则执行；以实际常规轨迹数N_O核算，不将该条件计数当作最终GPUh额度。每份128步、每次8题／32份回答、四次完整九项，恒定日程及同分规则保持。

<a id="stage2-opd-optimizer-fixed"></a>

**OPD共同固定优化器参数（2026-11-10已确认）：** 首轮128步的本阶段参考／数据、学习率及优化器候选，以及触发后的128→256步续训，共用以下设置；不增加权重衰减、裁剪阈值、betas或Muon内部参数搜索。

| 设置 | 固定值与适用对象 |
| --- | --- |
| AdamW | `betas=(0.9, 0.999)`、`eps=1e-8`、`weight_decay=0`；适用于所有实际使用AdamW的活动参数，包括Muon配方中的D辅助参数 |
| Muon | 沿本项目已确认的NS5、`momentum=0.95`、Nesterov及既有shape scale和内部设置；保留D矩阵分组、P整数与scale同用Muon及scale每投影一行适配 |
| 梯度裁剪 | 累计完整8题／32份回答按既定OPD目标归约后的梯度，仅对活动D／P参数联合做一次全局L2范数裁剪，上限1.5；B不计入该范数，也不另做范数裁剪；随后由各自优化器更新 |

例如累计D／P梯度联合范数为3，先将D／P梯度整体缩至约1.5，B保持未做范数裁剪的梯度，再交给各自优化器，不先按题目、回答、microbatch或D／P组分别裁剪，也不据此认为最终参数改变量必然减半。Muon初始步长换算使用同一份真实OPD初始梯度，D／P按上述联合裁剪处理、B不做范数裁剪，两套新优化器副本共同遵守本条固定参数；各组κ、学习率倍率及权重衰减适用对象仍按已定定义处理。

这里复用普通长文已确认的D／P固定参数，B按[绑定规则](#stage2-code-optimizer)切换AdamW／Muon，其梯度按[不做范数裁剪](#stage2-code-gradient)处理，Muon适配及执行衔接仍待验证；OPD目标、纯长文来源、每题4份回答和无预热恒定日程保持不变；不采用上游AdamW权重衰减0.01／裁剪上限1.0作为本批隐含默认。训练候选与节点评测计数不增加，不宣称这些参数已最优。数值精度、执行适配、裁判核对及实际GPUh仍需落实，本次未修改或运行训练代码。

<a id="stage2-opd-length"></a>

**OPD首轮长度、评测与选点（2026-11-10已确认）：** 本阶段每份不同搜索候选均完整训练128次优化器更新，在32／64／96／128步保存并测完整九项。每题4份回答不当成4次参数更新；每次更新按[已定batch](#stage2-opd-batch)累计8题／32份回答。四个节点属于同一条128步[无预热／恒定学习率轨迹](#stage2-opd-schedule)，不采用此前未选中的32步提案，也不复用普通长文余弦日程或旧500步轨迹前缀。

各候选跑完128步后，以自身完整九项最高的已评节点参与配置比较，不按中途排名提前淘汰。例如0步66.0、64步66.3、128步66.1，应以64步66.3参与比较。各新候选继续从同一OPD父模型独立开始，仅继承已选设置，不在前轮最佳节点权重上累加下一轮搜索。

OPD阶段保留全部已测合法恢复结果，与进入OPD前的共同0步模型比较；若所有OPD恢复节点都严格低于0步，就保留进入OPD前模型。0步同口径完整九项可直接复用，不重复计费。恢复节点彼此同分、不同轨迹同分及与0步同分均按[已确认OPD同分规则](#stage2-opd-ties)处理；与0步同分取恢复。

| 通常适用情况 | 不同训练轨迹 | 参数更新总数 | 节点完整九项评测 |
| --- | --- | --- | --- |
| 实际不同常规候选（含最终确定的数据及B搜索） | N_O条 | 128N_O次 | 4N_O次 |

实际按空组／等价配置去重及同条件结果复用核算；以上不含已确认的[条件续训到256步](#stage2-opd-extension)，也不是GPUh或不同题目数。每份四次九项包含对应模型完整八项及完整LongBench21，不能将另一节点的LongBench拼入。128步只是已选首轮预算，不证明已充分恢复；每步题数按[8题／32份回答](#stage2-opd-batch)执行，日程按[恒定学习率规则](#stage2-opd-schedule)执行，是否延长按[条件续训规则](#stage2-opd-extension)判断，同分按[OPD规则](#stage2-opd-ties)处理，实际费用继续核算。本次只修订规范，未启动训练，不改变已有已批准批次。

<a id="stage2-opd-ties"></a>

**OPD精确同分规则（2026-11-10已确认）：** 使用未四舍五入的完整九项均分比较；仅原始成绩精确相同时应用，不将显示小数相同或近分当成同分。

1. 同一训练轨迹的最高分节点并列时，取步数较晚者。128→256步续训仍属原轨迹，例如128与224步都精确为66.3，且没有更高节点，则取224步。
2. 不同配置或不同训练轨迹的最佳节点并列时，优先保留本轮开始前的已有赢家；它不在并列集合或本轮尚无赢家时，按预先固定的配置ID、再按轨迹ID升序选择，不按训练／评测完成先后决定，也不跨轨迹直接比较步数大小。
3. 最佳恢复结果与共同0步同分时，保留恢复结果；0步只在严格高于全部合法已测恢复节点时入选。

首轮选优及条件续训后的成品选择均执行本规则，不增加复测或费用。续训触发仍要求128步严格高于自身前三节点和0步，并且当前最佳仍未达九项目标；例如96与128步同分虽选128步，也不能因此触发续训。普通长文的256步是从共同父重新训练的另一条轨迹，其跨轨迹规则保持，不与本OPD连续续训混用。

<a id="stage2-opd-schedule"></a>

**OPD共同学习率日程（2026-11-10已确认）：** 首轮128步全部采用无预热、恒定学习率。每个活动参数组从第一次实际更新起，就使用本候选已确定的基础学习率；全程日程倍率为1，不在前两步爬升，不随更新次数下降，也不在128步终点自动降为0。比如D基础学习率为1e-5，则第1至第128次更新均使用1e-5；这不表示每次参数改变量相等。

D、保护整数、scale及活动B各用自己的基础学习率；B按[主编码日程](#stage2-code-schedule)保持恒定。D／P的Muon先按已定初始更新匹配取得各组κ，再乘本候选的0.5／1／2搜索倍率，128步内保持该实际学习率；D辅助AdamW参数保持既有分工，B按[独立κ_B规则](#stage2-code-muon-lr)换算，选定学习率在OPD中同样恒定。各候选仍从同一OPD父重新初始化优化器，正常中断续跑恢复该候选完整训练状态，不因评测或重载而重置优化器。

采用固定版本[QAOPD数学入口](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/scripts/opd/run_math.sh)的零预热设置及其固定verl基线[优化器配置](https://github.com/verl-project/verl/blob/bdfedd4617931e35f05c17c2c4954489efe68054/verl/trainer/config/optim/fsdp.yaml)中的`lr_scheduler_type=constant`；不因此照搬上游其它未确认训练参数。普通长文的2步预热／余弦下降不用于本OPD阶段。本轮固定一种日程，不新增日程候选，128步、每次8题／32份回答及四次完整九项评测计数保持。128步后仅在[已确认条件](#stage2-opd-extension)满足时，沿同一恒定日程续到256步一次；本次未启动训练。

<a id="stage2-opd-batch"></a>

**OPD有效batch与更新节奏（2026-11-10已确认）：** 全训练任务每次参数更新累计8道长文题，每题由更新前的当前学生真实采样4份回答，共32份回答；每份接受教师指导及一次完整原文的BF16裁判评分。8题是全任务合计，不是每张GPU各8题。沿已确认上游核心目标处理每题四份回答的组内比较与归约，完整批次梯度累计后只更新一次参数；不把每题／每份回答分别更新，不额外对同一批回答训练多轮。

可分批生成、计算并累计梯度，也可在授权资源内分卡处理，不要求32篇长输入同时驻留显存。拆分须保持同一更新前学生、每题四份回答的分组及既定损失系数，不能因microbatch、GPU数或累积次数改变有效batch和目标。下一批回答使用更新后的当前学生，不拿旧候选或旧时刻的回答代替。来源抽题与跨来源组织按[已确认OPD配额、洗牌及接续规则](#stage2-opd-sampling)执行。

| 统计范围 | 参数更新 | 题目呈现 | 学生回答／教师指导／裁判评分（各自） |
| --- | --- | --- | --- |
| 一份128步OPD候选 | 128次 | 128×8＝1024次 | 1024×4＝4096份／次 |
| 实际N_O条常规候选 | 128N_O次 | 1024N_O次 | 4096N_O份／次 |

题目呈现不等于不同题目或文档数；同一题再次被抽到时，仍由该时刻学生重新采样。以上是首轮候选的计划工作量，实际按去重及结果复用核算，另记有效输入／回答／教师监督／裁判token与耗时；初始化Muon换算、必要适配验证不冒充已包含其中；触发[条件续训](#stage2-opd-extension)时按该节另计新增量。32／64／96／128节点的完整九项评测数量保持，不新增batch搜索。8题及每题4份参考固定版本的[QAOPD数学入口](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/scripts/opd/run_math.sh)，长文与全文语义裁判的费用不能照搬其数学任务耗时。实际GPUh、显存及其余执行条件继续核算，本次未启动训练。

<a id="stage2-opd-sampling"></a>

**OPD抽题、来源配额与续训接续（2026-11-10已确认）：** 使用既定OPD合法train题池及完整上下文长度条件；数据轮分别按L1／L2／L3配额执行，选优后固定OPD自己的数据赢家，不增加来源或比例网格。每个128步段共1024次题目呈现，先固定各来源名额，再用固定种子打乱来源标签；依次每8个位置组成一次参数更新，不要求每一步都恰好达到全段比例。

| 已选长文配方 | 每128步段Qasper | 每128步段NarrativeQA | 每128步段HotpotQA | 合计 |
| --- | ---: | ---: | ---: | ---: |
| L1：2／0／6 | 256 | 0 | 768 | 1024 |
| L2：1／1／6 | 128 | 128 | 768 | 1024 |
| L3：0／2／6 | 0 | 256 | 768 | 1024 |

上表定义已确认的三份OPD数据候选。数据轮分别使用对应行的配额，后续超参数／优化器及续训只使用本OPD阶段胜出行；不把普通长文的数据名次代作本轮结果。遇到某来源标签时，从该来源已用固定种子洗牌的题池中取下一道题；题池用尽前不重复同一题目ID，用尽后再洗牌进入下一轮。每个问答算一道题，同一文章的不同问题仍分别计数，不另改成按文章均衡抽样。同条件候选从相同题序起点开始，使用相同来源标签与题目序列；题序随机状态与学生回答生成分开管理，避免回答长度／采样差异改变后续抽题。每份回答仍由该候选当时的学生重新生成，不跨候选共用回答。

触发128→256步续训时，只给新增的1024次呈现按同一配方安排同样数量的来源名额，用保存的来源随机状态继续洗牌新增标签，再从各来源上次未用完的位置继续取题；题池本轮用完才再洗牌。保留前128步的来源顺序和消费进度，不按2048总量重新排列前缀，不从各题池开头重取。例如L2前段已取128道论文题，若该轮论文题池尚未用完，后段从该洗牌题序的第129道继续；后半段仍为128／128／768次，整条256步轨迹合计256／256／1536次。

来源标签、各来源洗牌轮次／题序游标及相应随机状态随完整训练checkpoint保存，续训与同一候选中断恢复均沿这些状态接续。记录题池版本、种子、题目／文档ID、呈现次数与实际重复情况；不把1024次呈现称为1024道不同题目。来源配额只控制抽题，既定OPD损失与来源权重保持，不在抽样后额外重复乘权。本条不增加训练或评测候选，不改变每题4份回答、每次8题及实际费用口径，未修改或运行采样实现。

<a id="stage2-opd-extension"></a>

**OPD条件续训到256步（2026-11-10已确认）：** 所有常规128步搜索完成、确定最终赢家后，只有同时满足以下条件，才延长赢家的这条OPD轨迹：当前最佳九项相对同模型BF16仍下降超过1个百分点；该配方128步九项严格高于自身32／64／96步及共同0步。按未四舍五入的同口径九项比较，任一所比节点同分即不触发；不要求前三节点彼此单调提高。已经达标则不追加，每个模型在OPD阶段最多续训一次，到256步结束，不因末点仍最好自动继续到512步。

从赢家第128次更新完成后的完整训练checkpoint继续第129至256次更新，恢复模型、优化器／动量、恒定日程计数、随机状态及抽题进度，保留原κ和实际学习率。固定数据配方、活动参数组／模块范围、损失、采样及其它已选设置，每次仍8题／32份当前学生回答；沿同一轨迹继续，不重跑前128步，也不重置优化器、重算κ或重排已经消费的数据。新增部分按[已确认OPD抽题规则](#stage2-opd-sampling)安排来源配额并接续原题序。

在160／192／224／256步保存并评完整九项，前128步已有四节点结果直接复用。原有全部已测合法结果与0步继续参与成品选择；新增节点更差就保留旧赢家，同分按[OPD规则](#stage2-opd-ties)处理：本次是同一轨迹续训，并列时取较晚节点。仍可能成为最终赢家的128步完整训练状态保留到是否续训的判断完成，不能仅留下无法恢复优化器与抽题进度的推理导出；确定无后继用途后按既有产物清理规则处理。

| 计费范围 | 参数更新 | 题目呈现 | 学生回答／教师指导／裁判评分（各自） | 节点完整九项评测 |
| --- | --- | --- | --- | --- |
| 一次续训的新增量 | 128次 | 1024次 | 4096份／次 | 4次 |
| 实际N_O条常规轨迹，触发后合计 | 128N_O＋128次 | 1024N_O＋1024次 | 4096N_O＋4096份／次 | 4N_O＋4次 |

续训只是其中一条轨迹变为256步，不同配方仍为N_O份，不增加一份从0开始的对照。费用按新增128步及四节点核算，实际GPUh另计；这与普通长文重新训练256步／改变余弦日程的费用口径分开。规则确认不代表现有实现已验证完整恢复能力，本次未启动训练或扩大已有已批准批次预算。

<a id="stage2-opd-reference"></a>

**长文OPD与实现依据（2026-11-09已确认，仅适用于后续条件性OPD阶段）：** 按[进入条件](#stage2-opd-entry)确定进入该阶段后，由当前压缩学生先生成回答，再由原始BF16教师沿同一回答前缀提供逐token指导。用户进一步确认采用“教师指导＋答题奖励”，启用上游任务奖励分支（`use_task_rewards=True`）；用户最新确认由冻结的原始BF16模型结合合法train参考答案作语义裁判，按正确性和完整性给0／0.5／1三档奖励，替代此前文字完全匹配；裁判已确认读取完整原文、问题、train参考答案和学生回答，长文内部教师指导与答题奖励的损失系数均已确认固定为1。这与沿参考答案逐词训练的CE监督不同，首版仍不额外加入该CE损失。这些方法参数先保留，不据此新增训练候选或启动OPD；已确认每道长文题生成4份回答，额外生成／教师评分／奖励计算及训练成本需另核，不能沿用旧纯蒸馏耗时估算。不能复用另一学生或另一训练时刻的生成回答，冒充当前学生的在线生成。

用户指定参考[QAOPD](https://github.com/MingZwhy/QAOPD)，尽可能原样复用其逻辑和核心代码，仅轻量适配当前框架，不自行重设计OPD。2026-11-10进一步明确：OPD阶段只使用长文数据，不混入通用指令、知识题或其它短任务保持数据，不添加短文蒸馏损失；既定长文k1教师指导与答题奖励方式保持。本次审阅固定版本为`9a64cdb8d56ff69d7643bdee44060d0f42c9d40a`；其实际实现包含[固定的verl／EdgeRazor基线及补丁](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/third_party/UPSTREAM_BASELINES.md)，不能只复制启动脚本或忽略补丁。后续复用须标记原文件／版本，保留原版权与Apache-2.0许可要求，并列明必要适配处。

适配集中在VAELLM原生压缩模型及可训练参数接入、已确认数据／tokenizer接口、当前学生生成权重同步、保存加载与九项评测接口；保持所选上游分支的生成—教师打分—更新关系，以及损失、答案位置掩码、概率处理和归约语义。保留SC-CAT既定S2／BSQ表示、保护格式、数据与验收口径，不因引用上游就改用EdgeRazor量化、迁移其数学／代码数据或重跑上游QAD；上游的verl／Ray／vLLM整套运行环境也不等于已决定引入的依赖。必要适配若改变算法含义，须先说明具体差异再讨论；实现时以相同输入下的损失／梯度及真实模型生成后回训验证相关差异，不把源码审阅写成运行通过。

**上游分支已确认（2026-11-09）：** 首版采用论文主方法对应的[数学入口](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/scripts/opd/run_math.sh)分支：`loss_mode=k1`、`use_policy_gradient=True`、`use_task_rewards=True`。对学生实际生成的token计算师生对数概率差，沿上游采样反向KL的策略梯度实现更新，并保留任务奖励的组内相对优势更新；复用上游核心计算，不把该信号换成直接反传的全词表／top-k前向KL。另一[代码入口](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/scripts/opd/run_code.sh)的top-64直接分布蒸馏不列入首版额外对照，不自动增加分支搜索；新渐进方案的阶段候选数与费用另定。长文奖励已确认冻结BF16语义评分0／0.5／1，裁判已确认读取完整原文，每题已固定4份回答，学生回答上限按下文固定；裁判已确认输出分数及一句依据、合计最多128个新token；学生随机采样设置按下文固定；裁判已确认关闭随机采样、每份回答评分一次；长文内部两项损失系数均已确认固定为1；评分提示按[已确认统一模板](#stage2-opd-judge-prompt)执行，实际预算仍待确定。选择分支不等于照搬数学数据或全部训练超参。上游数学／代码的答案校验器不直接适用于Qasper／NarrativeQA／HotpotQA，不能将未匹配任务默认返回0当作已接入长文奖励。仓库旧学生greedy／全词表前向KL的恢复证据只说明旧条件，不能称为上述上游配方已在当前框架验证。本轮仅固化实现来源及适配边界，未复制训练代码、安装依赖或启动实验。


**OPD内部损失系数已确认（2026-11-09）：** 后续OPD阶段固定`distillation_loss_coef=1.0`、`task_policy_loss_coef=1.0`，分别作用于上游k1教师指导项和答题奖励的策略梯度项，沿用原有组内优势计算、掩码与归约。参考所固定版本的[数学入口](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/scripts/opd/run_math.sh)及[verl补丁](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/third_party/patches/verl-qaopd.patch)中的默认系数；例如一题4份回答得1／0.5／0／0，仍按上游方法形成奖励更新，同时加入系数为1的教师指导。系数相同不代表实际梯度贡献各半，也不改变知识题的半教师半标准答案目标；同阶段多来源按上述题目占比合并，OPD来源份额按[已选配方与固定配额](#stage2-opd-sampling)执行，实际预算另核。所有OPD训练候选共用此起点，不增加权重搜索或训练候选，不宣称它在本长文语义裁判条件下最优。

**同题回答数量已确认（2026-11-09）：** 每次抽到一道长文train题，从当前压缩学生真实采样4份回答（`ROLLOUT_N=4`，允许自然重复），分别接受k1教师指导和一次完整原文的BF16裁判评分，再沿上游方法比较该题四份回答的相对奖励。首版不把2／4／8加入额外搜索，随机采样规则按下文固定，不用复制同一条生成结果代替四次采样。

例如100次长文题目呈现对应400份学生回答、400份教师指导和400次裁判评分，不是400道不同训练题。OPD题目曝光按抽到的题目计，另记实际生成／监督tokens和裁判费用；题目预算相同不代表与无长文控制等算力，也不将4份回答自动当作4次optimizer更新。各数据候选共用这一规则，训练与归约设置随后确认。

**学生回答上限已确认（2026-11-09）：** 沿用现有恢复设置，Qasper／NarrativeQA／HotpotQA的`max_new_tokens`分别固定为128／128／32，均指每份回答最多新生成的token数，不是文章输入长度。遇到结束标记可提前停止，达到上限则停止生成；每题4份回答各自遵守同一上限，所有长文候选共用，不新增长度搜索。来源为`experiments/cat_aligned_protection_20261028/bindings.py`的`LIMITS`；复用长度设置不代表沿用旧greedy生成方式，也不证明这些上限在本次4份采样＋语义裁判方案下最优。学生随机采样及裁判输出要求见下文。

<a id="stage2-opd-judge-handling"></a>

**核对结果与异常处理（沿用项目现有规则）：** 以下落实[项目规范](../AGENTS.md)的错误处理、阶段结果汇报和重要修改先讨论要求，不新增裁判一致率门槛或训练授权。

- 输出无法得到唯一合法分数（0／0.5／1），或缺少必需判分依据时，保留原始输入与输出，报错并停止受影响的评分及依赖训练；不得默认填0或0.5、静默丢题或自行增加重复判分。正常空白和等价数字写法由解析器按同一含义处理。
- 语义评分分歧作为核对证据记录，不等同于格式错误，也不要求BF16与执行LLM逐条一致。报告实际覆盖、分数分布、分歧及原文依据、费用和局限；明确判错时提出具体提示修改及受影响复核范围，按既定阶段讨论规则确认后再改。执行LLM的意见不自动成为正确标签，不自行优化多套提示或改写训练奖励。
- 首次核对尚未执行；如后续需修订提示或追加复核，先报告原因、拟改正文与新增费用，不默认重复整批核对。下一批执行仍依当前计划和已有授权，不由本条追加审批或放宽启动条件。

同一BF16模型可承担逐token教师与整段答案裁判，两者均冻结，但输入与计算用途不同，裁判评分需单独核算推理费用，不将已有token概率视为语义判分。用户已确认裁判同时读取学生看到的完整原文，不用仅参考答案的短输入替代；参考答案只用于裁判评分，不拼入学生生成输入。裁判模板、完整原文、问题、参考答案、学生回答及预留评分输出均须计入上下文窗口，保持既定32K封顶及模型现有支持长度约束，不截短原文以凑入窗口。学生生成与裁判两种输入都需可容纳；学生回答按已确认的128／128／32预留，裁判输出另预留128个新token，按目标模型tokenizer核算可用池及费用。裁判评分提示使用[已确认统一模板](#stage2-opd-judge-prompt)；不得将该评分说成QAOPD原有数学校验器已支持的长文功能。语义裁判通过奖励接口接入，复用上游k1及奖励更新逻辑；三档评分是已确认的长文适配，不改变九项正式评测计分。

**原仓库评分事实：** 固定版本[数学评分器](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/opd/rewards/math_mixed_reward.py)提取`####`后的数值或最后一个`\boxed{...}`，先比较数值，再尝试规范化后的字符串／符号等价；[数学正式入口](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/scripts/opd/run_math.sh)还要求答案标记，正确无标记及仅格式正确均为0。入口默认额外惩罚不正确、没有有效答案标记且超过3000字符的回答，得−0.5；因此上游数学原始奖励不总是0／1。[代码评分器](https://github.com/MingZwhy/QAOPD/blob/9a64cdb8d56ff69d7643bdee44060d0f42c9d40a/opd/rewards/mbpp_execution_reward.py)执行测试，公开代码入口启用全部测试通过才得1、否则0。所审上游奖励路由没有三种长文来源的现成评分；其数学等价比较不是通用自然语言答案匹配。上述格式要求和超长惩罚仅记录来源，不自动加入本标准已选的语义三档奖励；长文评分适配保留上游奖励接口与更新逻辑。

**论文依据与迁移边界：** 用户指定的[《Train Where the Quantized Model Goes: On-Policy Distillation for Low-Bit Reasoning》v1](https://arxiv.org/html/2609.26708v1#S4)§4.1–4.2采用量化学生自身轨迹、采样反向KL教师指导和同题多回答的相对奖励，论文教师指导系数β固定为1；这与上游数学`k1`分支对应，不能将代码阶段的top-64前向KL直接反传称为论文主公式的相同实现。§6比较完整OPD配方与继续teacher-forced QAD，支持其所测数学／代码条件下的整体恢复收益，未单独证明奖励开关的增益，也未验证本标准长文三来源。每题4份回答及长文内部教师／奖励系数各1已由用户单独确认，其余论文参数仍作参考，尚不据此冻结其它参数或实际预算；论文与所固定代码版本有不同的训练配方，后续记录须明确采用哪一份，避免拼接默认值。本地[长文评分器](../experiments/longbench_v1/scoring.py)的三来源词重叠F1继续用于既定评测；用户最新选择训练奖励为冻结BF16语义三档评分，替代文字完全匹配，不使用F1作为训练奖励。训练奖励选择不改变完整九项的现有计分，也无本条件奖励训练收益证据。

4. **费用与边界。** 仍只安排至多两份live拟合及对应恢复；基准落选不额外做第三份live对照。固定CAT参考链仍沿原预算／复用规则，不与本类基准强制入围混为一谈。本次VAE候选替换不增加两份live名额；配置宽度等变化会改变实际耗时，须用入围配方重新核算费用。新增蒸馏搜索另按设计估算成本后讨论额度，不将旧3C+2自动定为新搜索上限，也不视为已获扩额；既有授权不足时报告缺口，不自动扩额或用低排名配置替换来冒充Top 2完成。

例如基准A为68.0、配置B为69.0、配置C为68.8，均为同条件的完整八项，则正式候选为B／C，A的配置与成绩继续留作对照。该规则只选择已测离线范围内的前两名，不保证它们在真实接续模型和恢复后仍领先；不据单个历史恢复反例另加基准保留门槛。

每类按离线raw完整八项最高者计算d_c=S8(BF16)−S8(only_compress_c)，保留符号；按(d_c,统一train教师KL,稳定类别ID)升序排序。S8用未舍入值；离线搜索冠军按§5保留最后当前配置；精确同分按费用及保留当前规则处理。第二名的确定按上面的全轮次规则执行。不得用不同类归一化VAE训练loss、W NMSE或stage末残差排序，也不把独立下降量相加预测全压质量。顺序只计算一次，live恢复期间不动态重排。

易→难目前只是启发式：可能减少早期输入扰动，却把困难类放到未来dense LoRA最少、prefix decoder后续恢复机会最少的位置。严格单主链下可以预先固定这条规则，不另开整链顺序对照；最后完整验收成功只支持联合流程，不能单独归因排序。若将来做A→B／B→A顺序对照，必须含真实KD和第二类自身live重拟合；仅按不同顺序安装两个固定bank会得到同一模型。

正式链迁移离线前两名的完整超参到online CAT：每类在同一live父上分别重拟合两份入围，二者都先完成同一默认配方的恢复比较，按§6只给默认恢复赢家继续搜索参数，不能只按live raw成绩保留一份。没有第二份合法不同配置时按上述覆盖规则处理。基准若未入围，仅凭基准身份不能补进正式链；已批准旧批次仍保留其原基准／非基准配对。未来dense LoRA保留原恢复方式，融合后下一类读取自己的live权重。

20离线＋最多2 live拟合是每类最多22次，码率粗查最多3次另列；不能称总共20。首类或目标权重／统计／数据／初始化合同均完全一致时可受控复用bank和适用指标；未来dense LoRA已改变权重时不可借BF16 bank充当live后继。两份live raw各自做完整八项作为0步诊断及§7保底候选，离线成绩不能代替它；最多另计2次raw八项／类。只迁移入围超参，不选择“先全压再逐类恢复”分支。

**基线复核与结构边界：** 上述anchor不能称为`catlora_simple2.sh`原配置。脚本显式`symmetric`、`channel_protect_mode=none`、固定S2；本候选流程允许asymmetric及已选保护搜索。`vae_args.resolve_autoencoder_arch_spec`在symmetric下将decoder宽度／块数绑定encoder，因此脚本虽写`decoder_num_res_blocks=1`，实际仍随encoder的0；asymmetric才读取两侧独立参数。同宽同块数时构造共用相同网络分支，但消费者的fused资格仍可能因decoder_type变化，不能只按参数形状宣布部署路径相同。依据：[参数解析](../litebsq/vae_args.py)、[网络构造](../litebsq/autoencoder.py)、[消费者资格](../litebsq/fused_multistage_decoder.py)。独立宽度比较用共同asymmetric基底，原脚本参考与定制基线的总体差另报；适用已有控制证据可复用，新增对照须另列实际费用，不占用逐层混合名额。实际执行须记录原始控制、已定保护起点及其它固定字段的解析值，不据脚本的5000恢复步数覆盖已选500／1000规则。

保护设置继承的是目标比例和选择规则，旋转／D变化时必须重新推导合法count并重算实际费用；输入保护轴不因transpose而交换。取消保护须真实count全0，不把映射后的正count称为取消；该几何不支持0时记录不适用。重复的完整配置可复用，数学非法或超类别预算记录未覆盖，不替换成新的未列参数。

<a id="protection-alignment"></a>

**通道保护数量的硬约束（用户2026-11-05明确）：** 每个目标投影的实际保护通道数量必须是该投影权重向量长度的整数倍，即`C_protect = n × D`，`D = codebook_dim`，`n`为非负整数；等价检查为`C_protect % D == 0`。0明确表示实际无保护，正保护数量至少为D。本标准固定S2且同类各stage使用相同D；转置与不转置均执行此约束，不将K／`codebook_bits`作为对齐单位。

- 例如D=32时，32、64、96满足整倍数要求，70不满足。该条件必要但不充分：还须保留非空主矩阵、能划成完整D维向量，且满足当前旋转与实际消费者约束；不能仅因矩阵总元素数可整除D就放过不对齐的保护数量。
- 保护比例只是目标。生成候选时，先求同时满足D对齐、剩余矩阵及旋转条件的合法数量，再按既定规则取最接近`p × 输入通道数`者，同距取较小值；不能直接将目标比例四舍五入成任意整数，也不能用补零绕过约束。
- 搜索D时重新计算各层保护数量和实际费用。例如原目标数量为96、D=32时可取96；改D=64后不能沿用96，若64和128都合法且等距则按既定规则取64。旋转或转置变化也重新核对当前几何，不交换输入保护轴。
- 在候选明细及最终配方中记录D、目标比例、逐层实际保护数量、实际比例及对应整数n。profile、离线、live拟合、导出验收和BF16重放均保持该约束；非法显式数量应报明原因，不能在运行中悄悄改成另一配置。

源码依据：[配方D与codebook_dim映射](../experiments/cat_auto_protocol_cmcc_20261104/fit_adapter.py)、[合法数量生成与整除检查](../experiments/cat_auto_protocol_cmcc_20261104/geometry.py)、[checkpoint费用审计](../train_utils/checkpoint_bpw.py)。现有生成器已经按D的倍数枚举；本次明确规范与记录要求，不修改在途运行代码或声称完成新GPU验证。

## 4. 全局位宽：先规划类别预算，禁止前类耗尽后类额度

已确认的选型要求：

1. 联合候选使用完整inventory的真实费用，工作目标约2.5、硬顶2.6 logical bpw；不可按nominal bits或漏项账本判断。硬顶下无可行方案则停止相关流程，不提高上限。CPU可枚举合法rate向量，但“枚举”不等于每个向量都进入实测。
2. **每个实际提名的联合方案**同时安装自身全部类别bank，保存真实部署来源并完成同协议八项。按未舍入`(-S8,logical_bits,packed_bits,稳定rate向量)`选择赢家；KL只诊断，不用Σ单类KL、Σ单类八项下降或局部误差代替实际联合分数。
3. 若分轮提名，后轮必须等待前轮已宣布合法提案的完整八项齐备，再以实际八项赢家为父生成；与已有赢家一起比较，不被迫采用更差新点。尚未完成／失败的评测按依赖失败规则处理，不能记零或用KL补位。
4. 类别预算固定后不允许前类透支后类额度。真正锁定B_c的证据须包含入选联合artifact、全部已提案的完整八项、共同协议及实际费用；旧KL-only证书不能直接升级为v0.2证书。

**已确认的两轮提案及预算算法：** 类别按稳定语义ID排列，rate向量及bank digest共同确定proposal ID。以下提名／去重先在CPU冻结，再分发；不因完成先后、低分或重复另开第三轮。

1. 由已有合法profile枚举rate向量v，令F(v)=Σb_c(r_c)，W=⌊2.5N⌋、H=⌊2.6N⌋。V_H为F≤H的完整向量集合；空集则退出为硬预算不可行，不增加码率取值或提高上限。若V_W={v∈V_H:F≤W}非空，两轮共同使用V_W；否则共同使用V_H并记录2.5工作目标不可行。第二轮不能单独放宽到H。
2. 定义有符号单类下降d_c(r)=S8(BF16)−S8(only_c,r)，提名启发s(v)=Σd_c(r_c)，不裁剪负值、不再乘N_c/N。s仅用于选择待测组合，不代表联合质量或恢复后表现。
3. 首轮依次提名A／B／C／D。A最小化Σ(N_c/N)(r_c−2.5)²，同分先取|F−2.5N|较小、再稳定rate向量；B最小化s，同分按较低logical／packed费用、稳定向量。A／B相同则复用并记录两个提名来源，不补造另一个B。C从未选集合中最大化到已选向量的最小类别Hamming距离（rate不同的类别数），同分取固定hash较小者；D从剩余集合取固定hash最小者。hash绑定搜索seed及稳定rate向量，同分再按向量字典序。集合不足则空置，每轮至多4个不同提案。
4. 首轮全部合法提案的实际部署／费用／完整八项齐备后，以真实joint八项赢家为父；枚举两个不同类别，一个r上调0.5、另一个下调0.5，均须仍在{2,2.5,3}。保留属于第1项共同集合、尚未测过的向量，按(s,logical费用,packed费用,稳定向量)取前4。它不是等费用交换；不足4或无邻点则少做／空置，不改为两升一降等新变更类型。
5. 最终将两轮所有不同已测提案一起按(-实际joint S8,logical费用,packed费用,稳定向量)选择，保留首轮赢家资格。联合实际账本须与安装bank来源及提名前费用合同闭合；不一致先查费用／安装问题，不在测完后静默更换工作集合。
6. 入选联合模型中，本类实际费用记a_c；余量R=H−Σa_c。先给各类q_c=⌊R·N_c/N⌋，剩余R−Σq_c个bits按稳定类别ID升序各加1，得到B_c=a_c+q_c。ΣB_c=H，各类独立锁定，不跨类借额。它只分配剩余费用，不保证每种高保护／加宽组合可行；超B_c记录费用未覆盖，不称质量负例。

所有已宣布提案的完整八项、共同集合身份、bank／账本来源、提名来源及上述分配一起进入cap证据。若使用现有独立`selection`接口，先完成无allocation的真实joint选择，再按第6项计算并显式绑定allocation、复核同一完整评测集合；不重训／重评、不提前猜赢家来填cap。控制器必须落实分轮及共同费用集合，不能仅调用旧`round_two`的≤2.6邻点行为。

**保护／容量费用覆盖审计：** joint提名前先用真实inventory及resolved几何计算费用覆盖，锁定B_c前再更新一次。列出各类profile实际count／费用、候选count变化、剩余额度及因费用未覆盖的保护／容量取值。INT8保护与主码的净费用约为N_c·Δp·(8−r)，另计索引／scale／decoder等；Δp须来自实际count，不能直接用请求比例差。即使joint≤2.5，按参数量分到约0.1bpw余量，也不保证不同旋转／D取整后的保护邻点可行。超cap是费用未覆盖，不是质量负例；审计提供事实，不额外引入未确认质量门槛或自动借额。

实际不同联合提案数记Q≤8，每轮≤4，逐个计完整八项费用；去重复用真实适用证据，不将已有赢家重复收费或为凑数扩大候选类型。旧mix_bit漏费及加性代理失效记录只提供规避依据，不是质量求解器。正式CAT仍须在各自live父上重新拟合。

## 5. 逐参数搜索、统一选优与结束条件

输入为同一原始BF16、共同数据／评测、该类已经冻结的码率与费用预算、统一anchor和[已确认搜索表](#sequential-search)。离线只压该类全部层，其余类别保持原dense，不进行类别恢复。下面是新标准算法；另行批准的19点批次仍按自身冻结条件执行。

1. **建立起点。** 完成或按完整身份复用anchor的S2两stage各10K拟合、真实部署、完整八项和实际费用，将其设为当前配置。来自profile的bank只有父、数据、初始化、代码、完整resolved配置等都适用时才能复用，不能仅凭名字相同。
2. **冻结本轮候选。** 按表依次处理保护、转置、旋转、D、encoder宽度、decoder宽度、optimizer、学习率；以当前配置为基底，只改该项及其已定义联动项。保留当前配置作为对照，先列出全部候选、合法性、实际费用预算及可复用证据，再分发。非法／超预算点记录原因，不补其它变量。全类转置阶段先冻结A／B及§8的C生成规则，A／B逐层读出完成后才确定至多1个逐层混合候选。
3. **完整拟合与评测。** 各新候选都从同一原BF16目标fresh拟合，S2每stage完整10K并做完整八项。继承超参，不续训上一候选VAE来增加本候选曝光；2K／5K只观察，不提前淘汰。同轮候选及不同类别可并行，本类下一参数必须等本轮所有应比较结果齐备。
4. **统一选优。** 当前配置与本轮所有合法完整结果一起按未舍入八项均分取最高，任何正提高都更新。精确同分先选较低logical费用，再较低packed费用；仍相同且当前配置在并列集合中则保留当前，否则按稳定配置ID取唯一者。这是配置搜索规则，不覆盖KD节点的同分规则。不自动换训练随机种子复验近分，不设置额外最小收益门槛。
5. **继承并继续。** 当前参数无改善仍进入下一参数；仅记录当前配置未更新，不提前终止整类搜索。转置阶段按§8完成两种全类配置和逐层混合配置的八项取舍后，再生成旋转候选；该类不等待其它类别的逐层统计。后续旋转／D继承已选映射并重新核合法性与费用。
6. **关闭本类。** 完成全部八项参数后结束，最多19个基础配置加1个逐层混合，不加第二轮回访或其它变量。最后当前配置就是本条顺序搜索的冠军；记录所有已评配置与未覆盖原因。按§2.1从全轮次结果确定第一名和第二名供正式链，另保留基准配置及指标记录；基准只有按成绩入围时才参与本类正式恢复。全类结束后才冻结类别顺序；其它类别可在此之前独立推进自己的参数搜索。

配置搜索的比较键可写为`(-S8, logical_bits, packed_bits, 非当前配置标记, stable_config_id)`，其中当前配置标记只在前三项精确相同时生效。不能把GPU先完成者当赢家、把失败／未评结果写为低分，或用KL替代完整八项；失败及中断按执行规范处理，仍有未完成依赖的本轮不能关闭。数学非法／费用不覆盖与技术失败分开记录。

初始化及采样各用按模型／类别／stage／用途派生的独立随机流；同形状配对共享相应种子，结构变化不声称初态逐值相同。VAE init／shuffle、LoRA init、KD dropout／数据流不依赖评测顺序、候选并行顺序或上一类跑满上限后的全局RNG；固定recipe重放沿相同派生规则。

每个实际有效配置保留真实来源、完整参数、未舍入八项、logical／packed费用和实际GPUh；辅助记录原有权重／输出误差及固定train读出，仅用于诊断和§8提名。相同完整身份复用，不重复拟合或评测。搜索输出称为已评范围内的最好配方，不声称全局最优、恢复后的最优或九项最优。所有部署及未来阶段仍按自己的真实父和完整评测验收。

旧7＋2联合几何、仅容量段叠加、第20槽交互兜底及全类别层组等待已归入[旧稿](experience/history/w25_transfer/2026-11-05_cat_static_slots.md)。执行步骤、输入与完成状态见[离线执行规范](sc_cat_execution.md#5-搜索推进的状态机)。

## 6. 两份live配方的恢复比较与有界交互核查

<a id="recovery-search-handoff"></a>

**新标准已确认：两份先做默认恢复，只给赢家继续调参（2026-11-08）。** 正式轮到本类时，两份离线入围配置仍在同一真实父模型上重拟合。各自从本份raw起点运行一次同样的默认恢复，沿用已定500步日程及125／250／375／500完整八项；两条完整比较结束后，按已有恢复节点选优／同分规则确定唯一继续搜索的VAE配方。第一轮默认恢复参数沿用§7起点，不根据离线名次给两份不同待遇。只有一份合法入围时不重复制造对照。

后续只为该赢家搜索恢复超参数：继承已选超参数，每个新对照从赢家同一raw起点重新训练；其默认恢复结果直接复用，不再重复训练。另一份不再追加参数搜索，也不在新搜索之外自动叠加旧额外镜像核查。默认两条可并行；同一赢家逐参数搜索的下一轮等待本轮比较完成，下一类别仍等待本类最终接续节点。主体候选见下表；250步保留两名及每模型首个适用类别逐项校准已确认，Muon按实际活动组分别对齐初始更新后搜三档，P整数与scale共用搜索倍率；学习率按decoder→P→LoRA依次搜索，1000步检查按下文已确认条件追加，所有已测合法节点与raw0比较选优；总GPUh仍待估算与确认，不把本条写成已具备可运行的完整新搜索。

| 粗查组合 | 实际训练内容 |
| --- | --- |
| D | 仅decoder |
| P | 仅保护INT8数值与scale联合QAT |

**第二轮只细查获胜组合的类别范围。** 对其中启用的D、P，各比较“仅当前类别／全部已压缩类别”；两者同时启用时共最多四种范围组合，只有一者时最多两种，只用L时跳过。已有同条件点复用，其余从同一raw fresh训练，不能直接接粗查赢家权重。选出一份后继续rank、alpha、dropout、优化器和学习率搜索，不给七种组合各开一套完整搜索。此为有界顺序搜索；未测的落选组合×其它类别范围仍可能更好，不声称覆盖全部交互。

例如K、O已压、刚压Q，D＋P胜出后比较：Q解码器＋Q保护、Q解码器＋K/O/Q保护、K/O/Q解码器＋Q保护、K/O/Q解码器＋K/O/Q保护。L始终指未压缩类别，不按当前／全部已压缩范围切换。首类相同范围、末类无未来LoRA、目标中没有保护通道等按实际参数清单去重；空组合不训练，仍沿既有raw0保底规则选择。原两种decoder＋LoRA范围以及此前未采用的五种并列提案均不在新组合搜索外重复追加。

两轮分别沿既有逐项短筛／校准规则记录：有至少三份合法不同候选时，在新模型首个适用类别完整500校准该轮的250保留两名；通过后才启用，只有一／两份候选均完整500。粗查通过不替范围细查宣告通过。后续只搜索活动组的参数：没有L时跳过rank／alpha／dropout／LoRA学习率；没有D时跳过decoder学习率；优化器按“D与P绑定的一侧／L一侧”仅保留活动侧的不同配置；只有P而没有D时仍搜索绑定侧的两种优化器。D／L原初始更新对齐规则保持；P整数与scale已确认分别计算κ_q、κ_scale，再共用一个搜索倍率，不直接复制D的κ。

**保护统一为INT8数值与scale联合QAT，已确认（2026-11-08）。** 每个含P的组合同时训练同一目标通道的整数代理与scale，两者属于一个P组并共用类别范围；不再分成scale-only／q-only两种候选，七种粗查不扩成十一份。保持已有保护数量、索引及INT8部署格式；训练用浮点代理参与梯度更新，前向按INT8舍入／截断和实际scale还原保护权重，最终保存实际INT8值及scale。其含义不是将保护改为BF16权重部署，也不是开放主BSQ码训练。需沿已有signed-INT8硬前向／STE与正scale参数化适配联合路径，同时保存两个活动部分、优化状态并在选点／原生导出时一起还原；未经适配验证不称现成CAT已支持。P优化器已确认与D固定绑定，整数与scale同选AdamW或同选真正的Muon，见下文绑定规则。整数代理与scale已确认共用0.5／1／2搜索倍率，二者一起减半或加倍；AdamW参考起点已确认整数0.03、scale 0.001，Muon已确认分别对齐整数与scale的初始更新量；本轮在decoder学习率之后、LoRA学习率之前。共用倍率不等于两个初始数值相同；起点来源与三档见下文保护学习率规则。

[已有保护训练经验](experience/lessons/kd_and_data.md#教师保护scale和整数qat的条件证据)提供有条件的正反例：旧低位宽D＋INT8保护QAT32相对同预算D-only32的九项提高约0.11165pp；[S4同父128步](../experiments/s4_scope_objective_20261107/README.md#完整结果与本轮结论)的decoder＋scale／INT8分别提高八项约0.20030／0.94420pp。它们没有同时训练整数与scale；S4、数据和目标也不同且该S4对照未跑LongBench，不能当作本S2／约2.5bit联合QAT已验证收益。不凭局部结果把保护单训等未测组合判为无前景。

**保护学习率已确认：整数与scale绑定倍率搜索（2026-11-08）。** AdamW参考起点固定为整数代理η_q=0.03、scale的可训练log_delta参数η_scale=0.001；沿用既有正scale参数化，不将0.001解释为直接向部署scale加值。两部分共用一个搜索倍率m_P∈{0.5,1,2}，对应整数／scale三档0.015／0.0005、0.03／0.001、0.06／0.002。在同一优化器／参数基底下两部分一起减半、保持原值或加倍，D和L的学习率及其它设置保持当前赢家值。进入P学习率轮之前，含P的候选使用参考倍率1；两份VAE的原默认恢复仍不启用P。Muon已确认按下文初始更新对齐规则分别取得κ_q、κ_scale；其两部分基础LR为κ_q×0.03×m_P与κ_scale×0.001×m_P，再乘原日程因子。两个κ固定后仍只搜索一个m_P，不增加候选；不复制D／L的κ或将绑定优化器解释为与D共用学习率倍率。

这两个起点取自[已有分别训练保护的实验](../experiments/cat_aligned_protection_20261028/README.md)，仅复用数值作为本轮搜索参照。旧实验分别训练整数或scale，数据、其它学习率和优化器条件也不同；不能据此宣称联合QAT下最优，不自动带入旧实验的其它参数。

本轮从选中VAE的同一raw fresh训练各配置，继承前轮超参数；适用原值直接复用，通常仅新增两条恢复，不再分别为q／scale各跑一轮或展开九种组合。若两条均满500，新增1000次更新及八次节点八项；已校准短筛时按实际训练／评测计费。三档比较沿既有每模型首个适用类别逐项校准规则，P未启用时跳过。本轮在decoder学习率之后、LoRA学习率之前，继承此前完整赢家设置；绑定倍率是有界搜索选择，未覆盖一边增大、另一边减小的组合。

LoRA容量按四档比较，本轮全部既有future dense LoRA目标共用所试rank及对应alpha。选定rank后再固定rank比较alpha=1／2／4倍rank，不将四档rank与全部alpha／学习率做全组合。每个容量对照复用已选VAE的同一raw，不重新拟合VAE；rank12也只有完整基底一致时才能复用旧指标。没有未来LoRA目标或获选组合未启用L时记录本项不适用，不重复跑四份相同配置，也不为了搜索给已压缩类别新增部署LoRA。

**LoRA dropout两档已确认（2026-11-08）：** 放在rank／alpha之后、优化器与学习率之前，比较0与0.1。例如Q当前采用rank24、alpha48，就固定这两项，只比较LoRA输入不随机屏蔽或随机屏蔽10%。两份配置从同一VAE raw fresh开始，使用既定独立初始化／数据随机流；按四个恢复节点的完整八项及原同分规则选优，后续继承选中的dropout。只有两个候选，均完成原500日程，不在250淘汰，也不为本项增加短筛校准。相同完整条件的0.1轨迹直接复用，通常只新增一条500步训练和四次节点八项；未启用L时本项跳过。该项不新增VAE拟合，不影响旧已批准批次的固定dropout。

<a id="recovery-scale-muon-row"></a>

**scale-Muon已确认：每个投影独立视为一行（2026-11-08）。** 例如Q第5层有64个实际保护scale，就将该投影的scale可训练向量及对应梯度／动量在Muon运算中视为1×64矩阵，使用现有矩阵Muon方向计算，再按原通道顺序还原为长度64的更新；其它层各自按自身N独立执行1×N，不跨层／跨类别拼接。此处“每层”对应实际投影，不将同一Transformer层的Q／K／V等不同投影合成一行；没有保护通道的投影按原不适用规则跳过。

适配只改变Muon计算时的视图，保持已有正scale参数化、可训练量和实际scale的对应关系，以及原生INT8保护／scale序列化格式。沿用当前Muon的NS5、momentum0.95、Nesterov及按1×N形状计算的scale，不引入新的向量专用优化器或本轮搜索项。保存／恢复仍须保留该投影原可训练向量、动量及全部必要状态，方向还原必须与原通道顺序一致；scale的AdamW参考LR已定为0.001，已确认按独立κ_scale对齐其Muon初始步长；κ_scale汇总实际活动scale组计算，不逐投影各算一个。该规则是用户确认的新扩展，不将矩阵Muon的既有证据当成其效果或续训路径已经验证。

本轮固定其它设置、同raw比较，本轮候选可并行，全部规定比较完成后选一套进入后项；适用已有控制复用，最多四种时通常新增三条恢复。不为四种搭配分别展开rank／alpha／学习率全搜索。两份VAE的默认恢复仍沿原AdamW起点；后续D／L的Muon按原独立初始更新参照，P的整数与scale也分别换算，P两部分仍共用搜索倍率。保存状态须覆盖实际活动组、真实优化器及各自参数，联合P、LoRA Muon及scale-Muon适配尚未完成；候选数量不等于已批准GPUh。

<a id="recovery-muon-scale"></a>

**Muon步长参照：各活动参数组分别对齐起始改变量，保护两部分共用搜索倍率。** 沿用仓库现有decoder Muon的初始更新匹配思路；LoRA及P整数／scale的扩展规则已确认，实现与运行验证待完成：

1. 分开统计实际活动的四组：decoder矩阵、未来dense LoRA的A／B矩阵、P整数代理矩阵、P的scale可训练log_delta。启用Muon的组各有一个κ_decoder、κ_LoRA、κ_q或κ_scale，不合并P两部分，也不复制其它组的κ。decoder保留原stage语义，scale按每个投影1×N计算Muon方向；原decoder辅助偏置／归一化仍用AdamW，P的scale真正用Muon。沿用原NS5、momentum0.95、Nesterov及shape scale，不增加内部参数搜索。
2. 对同一真实已裁剪初始梯度，在克隆参数／状态上计算两种fresh优化器的候选更新：原AdamW（原betas、eps、WD）与未标定Muon。按各组非零参考基础LR计算：decoder为1e-5、LoRA为1e-4、整数代理为0.03、scale的log_delta为0.001，此时搜索倍率取1。实际训练仍保留原warmup，不能因第一步调度LR为0而把两边都算成0；测量不提前更新真实参数、梯度、optimizer状态或随机流。
3. 对每个活动Muon组g计算 `κ_g = ||ΔAdamW_g||F / ||ΔMuon_g||F`，范数汇总该组全部实际参数的未舍入更新候选，不逐投影各定κ、不跨组混算。P整数测浮点代理更新，scale测log_delta更新；不使用硬INT8翻转数、部署scale差值或LLM输出变化代替此范数。LoRA初始A零梯度可正常贡献0，保留原A随机／B零初始化；只有组整体无法得到有限、非零比值时才报告原因并停止该受影响候选，不伪装成质量淘汰。
4. 令参考基础LR为η_g、原调度因子为s(t)。AdamW实际LR为 `η_g*m_g*s(t)`，Muon实际LR为 `κ_g*η_g*m_g*s(t)`；decoder保留AdamW的辅助参数不乘κ。D、L各自搜索m_D、m_L，P整数与scale共用同一个m_P，均取0.5／1／2。例如相同参考LR下，整数Muon更新量是AdamW的5倍、scale是2倍，则κ_q=0.2、κ_scale=0.5，换算后P起点为0.006／0.0005；之后两者一起减半或加倍。κ在同一参数基底的倍率对照及整条轨迹中固定，250步续训读取所有已用κ及原训练状态，不重新标定。
5. raw、实际活动组／类别范围、rank／alpha、初始参数／梯度或相关优化器条件改变时重新取得对应κ；同一初始梯度及完整分组条件一致的配对可复用校准记录，不能跨类别或模型照搬κ。记录各组参考LR、两种候选更新范数、κ、所搜倍率及实际调度LR，并随优化状态保存。没有活动P时跳过其两组换算。校准计算计入实际成本，不增加恢复训练候选；对齐只提供起始步长参照，不证明整个恢复过程或模型输出变化等价，取舍仍看完整八项。

默认恢复赢家只决定搜索资源投给谁，不提前决定本类最终节点。两份已有raw0及默认恢复指标保留，新对照完成后沿用已定合法节点／0步保底及末类双端点九项规则选最终接续或成品；末类未继续调参的一份只使用已有合法端点，不为补LongBench追加训练。默认较弱的配方仍可能在其它参数下反超，本方案接受未搜索这部分组合的局限，不声称得到联合全局最优。

例如A、B分别默认恢复，B的最佳合法恢复节点八项更高，就只给B继续调参。若两份VAE均合法、七种更新组合全部有效、最终D／P／L全开且D／P两种范围均不同，不短筛且同条件控制正常复用时，该类最多为2条默认＋6条粗查新增＋3条范围新增＋3条rank＋2条alpha＋1条dropout＋3条优化器＋2条decoder LR＋2条P倍率＋2条LoRA LR＝26条500步恢复。首类范围相同、末类无未来LoRA、获选组合未启用某组等情况减少实际运行。另有最多两类各追加一条1000步检查，计数及成本见§9。P起点、换算和搜索顺序均已确认，接口与必要验证未完成、成本未批准时不能据此启动。旧第三臂、额外2条镜像和3C+2配额不自动叠加。

**新标准候选比较补充：**

**以下两段仅保留旧批准批次合同，不属于新恢复参数搜索。** 旧全模型额外2条排名核查的用途与分配已确认：按冻结类别顺序，给最早两个符合条件的类别各1条。资格是已有两份不同live raw，且§7第三条恢复为实际不同的500步学习率／decoder范围变体。在第三条结果出现前确定本类资格及名额；另一份raw也从自身0步fresh运行同一个变体，沿原500日程及125节点完成八项，两条变体可在资源允许时并行。随后一起选择合法接续节点，不先接下一类再回退。

## 7. 类别恢复配方与自动节点选择

**本节适用边界：** 默认起点、节点比较、0步保底及末类双端点评测沿用已有确认；下面“第三条恢复／3C+2”描述旧批次合同，不是已经确认的新参数搜索表。新搜索的顺序、优化器搭配／步长、短筛、校准及条件追加1000步已见§6；保留已有更好节点及0步保底已确认，总GPUh待确认，既有批次不改。

**两份VAE的默认恢复配方：** 训练全部已压缩类别的decoder与全部未来dense LoRA（D＋L），保护P不训练；末类没有未来dense时只训练D。使用torch AdamW，betas=(.9,.999)、eps=1e-8、WD0；decoder LR1e-5，未来dense LoRA rank12／alpha24／dropout0.1／LR1e-4。可训练decoder／LoRA为FP32、计算为BF16，B4／GAS1、max1024动态padding、clip1.5、cosine500／warmup1%；数据、教师及固定KL目标沿已绑定协议。这里给出本标准的起点，不能用脚本未确认的默认值覆盖。

optimizer／scheduler仅在**同一条恢复轨迹**内连续（含250续至500）；同一类别的不同配置都从选中VAE的同一raw fresh初始化，下一类别也fresh初始化。后续组合、rank／alpha／dropout、优化器与学习率按§6搜索；P启用时其整数代理及scale的log_delta按已定FP32联合QAT路径训练。每次配置变化都记录完整实际参数，不能只记本轮改变的一项而丢失此前赢家设置。

**旧批准批次的第三臂规则：** 每类在原批次两份入围配方的默认KD比较后，选最佳恢复节点所属配方，从其绑定的原raw起点最多增加一个**只改一个变量**的第三条恢复。此时只在已完成的恢复节点中选择触发配方；raw0保底在全部既定对照完成后才判断，不能提前取消第三臂／交互臂：

下列长程及非长程第三臂规则均已确认。触发配方先按两条基准恢复的全部完整八项节点及本节同分规则确定，再读它**自身raw0**；不能用另一配方的raw0替代。八项曲线只用于提名候选，不视为过拟合／步长不足的诊断证明。

0. **长程优先：** 若入选配方500完整八项严格高于其raw0及125／250／375，且全模型两类长程名额尚有剩余，按冻结类别顺序将本槽改为1000总步数对照；从相同raw及配对随机流重新训练，保留自身完整1000日程，每125保存／评八项。总日程改变意味着前500的LR轨迹也改变，不能称旧500的直接续训。该槽替代LR／范围或其它第三臂，不叠加；较长轨迹与原500赢家一起比较，仍仅一节点接下一类。名额已耗尽时继续下列非长程分支，不追加第三类1000。
1. **范围分支：** 若自身raw0完整八项不低于全部四个恢复节点，只改decoder的全prefix／本类范围；非末类未来dense LoRA保持原范围，不能误把`current_decoder`和`remaining_lora_current_decoder`混用。首类范围等价则本槽空置，不顺势转试LR。raw0与最好恢复点同分仍进入此分支。
2. **LR分支：** 否则令早期最佳为125／250／375的最高完整八项；它严格高于500时只将decoder LR改为0.5×（5e-6），500严格高于早期最佳时只改为2×（2e-5），二者同分则本槽空置。不再以固定train KD loss的升降或缺失控制是否生成候选；未来dense LoRA LR不变。
3. 所有非长程新候选都从触发配方的原raw fresh训练完整500，并评125／250／375／500；不能从已选中间节点继续，结果不好即结束。额外核查按§6已确认的资格与分配规则执行，用于最早两个符合条件的类别，每类至多一次；不另开结构／数据／目标臂。

旧方案固定LoRA rank／LR且最多3C+2条包含控制、第三臂和交互核查；新标准已按§6确认逐类参数搜索及条件追加1000步，总GPUh尚待确认。数据／目标替换及其它额外恢复算法仍不因此自动纳入。所有评测计费。第三臂提名规则已确认，但其搜索效率与机制解释仍待实测，不因获确认就称其效果已证实。

非末类在全部既定恢复轨迹完成后，先在所有合法恢复节点中按未舍入完整八项取最大，再与两份live raw中最好的0步比较。**只有最佳raw0严格高于全部恢复节点时才选0步；同分保留恢复节点。** 候选同分时按较低logical／packed费用、稳定候选ID比较；同一轨迹内同分取较晚步，仍完全相同按稳定轨迹ID。0步仍已完成本类VAE压缩，只是不采用本类KD更新；它只避免本阶段八项被迫低于已测raw，不保证后续整链或九项更好。技术失败／评测不完整先按失败规则处理，不以选0绕过未完成依赖。

**末类双端点九项选品：** 全部既定对照完成后，同样先检查两份raw中最佳0步是否严格高于全部恢复节点；只有满足该全局条件的最佳raw0可进入末类候选，同分按上段规则确定唯一raw0，不因“胜过自身配方”放宽资格。分别汇总两份live VAE配方的合法恢复节点，各取自身八项最佳端点；若已有全局合格raw0，则以它替换其所属配方的端点。两个端点先各自完成真实部署导出／finalize／新UUID及必要fresh核证，将已有完整八项按同状态复用规则绑定到对应artifact；发生相关实质差异则先解决并补受影响评测，不能只改metadata冒充核证。随后在这两个已验证artifact上分别完成同协议LongBench21／4750条，按未舍入S9=(8×S8＋LB宏均分)/9选择最终模型；S8、LB统一使用百分制。S9完全同分按较低logical／packed费用、稳定候选ID及稳定轨迹ID破同分，不另给基准身份优先权。选择后直接交付已评的对应artifact，不重新拼装另一模型。仅有一份合法不同配方时只评一份并披露覆盖不足；已有适用LB可复用。此处LB参与开发选品，不称盲测；只在两份八项入围端点间择优，不覆盖其余节点的九项排名，不增加第二主链。

每条恢复轨迹绑定自己的schedule_max=T∈{500,1000}：

```text
两份live raw0完整八项（诊断及保底）
  → 同一连续maxT轨迹，在125,250,…,T保存完整mutable
  → 每个节点独立部署导出及完整八项；评测不改变训练状态

    旧批次：完成两份控制、已触发第三臂及合格交互臂
  → 全类八项最佳恢复节点与最佳raw0比较，严格更好才赋予最佳raw0资格
  → 非末类：选全类八项最佳合法节点 → 重建完整状态／finalize／新UUID
           → 下一类的live拟合
     末类：各配方八项最佳合法端点 → 各自部署边界／fresh核证
           → 在这两份artifact上完成LB → 按九项选择并直接交付对应artifact
```

保存必须包含该轮全部可训练字段。以轨迹绑定的完整round_base重建模型，覆盖该节点实际mutable manifest（全部实际训练decoder、保护q／scale、future dense LoRA及启用辅助项）；未训练字段从round_base保留，再全部finalize／融合、绑定真实runtime／progress及新UUID。不能只换新类别decoder，也不要求current范围mutable含未训练prefix。记录实际schedule_max=T、selected_step及轨迹设置；例如T500选250，不把它记成只训练250。读出／导出不改live master、optimizer、mode或训练RNG，待选节点不被save_total_limit提前删掉。训练态必须保存实际T日程的optimizer／scheduler／RNG，部署边界不冒充训练exact-resume。

选中0步时，从该配方已验证的live raw原样建立类别边界，不覆盖任何已放弃轨迹的KD mutable；记录`selected_step=0`、raw来源、基准`schedule_max=500`及本类实际完成的对照，不伪造0次更新后的optimizer／scheduler恢复状态。仍须走真实finalize／progress／新UUID，下一类fresh optimizer。该路径及末类零恢复成品必须补最小验证，不能只改metadata宣告完成。

这先实现预算内实测选点，不默认节省本类训练计算。125间隔只保证所评网格内最好；1000对照仍沿每125八点评测。更密网格、真正patience早停、因raw0领先而提前跳过既定恢复，或超出已确认两类／1000的追加均不自动开启。若1000仍末点最好，记录上限未封闭，不无限延长；不能将500或1000称所有模型最优上限。

## 8. 逐层转置选择与严格单主链

**用户已确认的办法（2026-11-05）：** 在本类转置步骤比较三种配置：A全类不转置、B全类转置、C逐层混合。C的每层方向只根据A／B在同一批固定train输入上的该层输出误差选择，取误差较小者；权重误差仅记录，不参与选方向。A／B／C各自完成完整八项，再按统一规则选出本轮配置后进入旋转。这里改变的是转置，不是旋转；旧浅／中／深分组和“两半样本偏好必须一致”的条件由本条替代。

两份全类完整拟合提供所有层的方向比较，不是每层各训练两次。若生成了新的合法混合配置，再增加一份完整拟合；混合映射与A或B相同则直接复用。每类至多1份额外逐层混合配置，仍计入20配置总上限，未用名额不转给其它参数；既有单独批准的19点实验不自动追加本步骤。

1. **完成匹配的A／B。** 固定本轮同一BF16父、保护设置与实际通道、旋转、D／K／S、网络、优化器、数据、种子规则和类别预算，仅改变全类转置方向。两份均为S2、每stage完整10K；完整身份适用的当前配置直接复用，其余fresh拟合。真实投影清单决定层数，不按固定层号或浅／中／深分组。
2. **使用同一批层输入。** 沿用本协议冻结的512条train读出及其样本／token清单，不为本步骤另选语料或从正式测试集抽样。由原始BF16模型产生每个目标投影的输入；A／B在每一层都使用该层完全相同的输入，与原始投影输出比较。压缩输出使用逆变换、保护回填后的真实部署路径；不使用各候选自身已受压缩影响的前缀输入，不比较VAE内部loss。沿既定部署计算精度前向，误差以FP32归约，仅统计相同有效token和输出元素。
3. **逐层取输出误差较小的方向。** 对每层和每方向，在全部512条样本上累计输出平方误差SSE，除以有效输出元素总数，得到该层输出MSE。只比较同一层的A／B，不跨层排序，不额外乘KL的prompt权重或VAE损失系数。精确同分时沿用进入转置步骤时该层的方向，不用八项或权重误差打破逐层同分。逐层权重MSE也在逆变换、保护回填后的原坐标下记录，仅供分析。必要输出／有效计数缺失或非有限时按读出未完成处理，不能冒充同分或零误差。
4. **生成唯一C映射。** 例如Q第4层A误差更小便不转置，第5层B误差更小便转置，其余层同样决定。不再按两半样本的一致性筛层，也不根据A／B的八项成绩改变某层方向。C与已测配置相同则记录复用；C不合法、超类别预算或消费者不支持时记录未覆盖原因，不修改方向凑预算或另猜一份模板。配对结果尚未完成则保留未完成状态；明确不适用的情况按既有覆盖规则记录。
5. **完整拟合C并比较三份八项。** 新的合法C从同一BF16父重新拟合该类别全部层，保持S2、每stage完整10K、全类别M及原BSQ聚合语义；不得从A／B拼接已拟合bank，或改为逐层独立训练来替代。A／B／C各自部署并测完整八项，重复配置只测一次，按§5统一规则选出本轮赢家。八项同分时的“当前配置”仍指进入本轮前的配置，不随评测完成顺序改变。C完成后不重新按其误差迭代生成第二份映射；下一步旋转、D及后续搜索继承完整赢家配方。

**并行与记录：** A／B可并行；其完整拟合和逐层读出齐备后即可生成C，C拟合可与A／B的八项评测并行，生成方向不等待八项成绩。下一参数须等本轮应比较的完整八项全部齐备；各类别仍独立推进。保留每层ID、A／B来源、固定数据身份、两方向输出SSE／元素数／MSE、仅供参考的权重MSE、选择方向、C映射及复用／未覆盖原因，再关联三份候选八项结果；字段与展示见[执行规范§8.2](sc_cat_execution.md#82-候选明细表每种设置的效果都能查到)。读出计入实际成本，但不另计VAE拟合配置。

固定输入保证配对可比和复现，不保证消除校准数据偏向；局部输出误差只负责生成C，不能代替完整八项取舍。相关经验见[局部误差与整模型结果的边界](experience/lessons/output_losses.md#局部误差改善与整模型跨任务退化)。本条是已确认的选择规则，不是逐层转置收益的实测结论。旧`offline.layer_group_nominations`的分组／稳定性／regret规则不能直接作为本条实现；首版仍不开放层级D／K、网络宽度或优化器异构，现有逐ref字段不等于真实混合路径已验证。

第四轮已确认首版严格单主链：非末类只让一个已选完整节点进入下一类，不保留第二前缀，不预留整链修订名额；末类仅复用同父已有两份配方的端点按§7九项选品，不延伸两个后缀。未达到目标时，先汇报证据再讨论下一批，不自动追加组合链。固定参考、入选recipe的BF16重放及跨模型验证是另列的必要比较／验收，不冒充额外候选质量修订，也不能把不同历史donor拼成未经验证的链。

## 9. 时间预算、缓存与调度标准

按本模型计费：F_off,c／F_live,c为该类相应阶段完整拟合＋编码／导出／fresh／诊断成本上界，R_c(T)为T步恢复及必要保存导出，E_off,c／E_live,c为一次相应完整八项，E_profile,c(r)为该类实际码率profile的一次完整八项，E_joint,p为实际联合提案p的一次完整八项，J为完整九项，L为一次完整LongBench21。正式预算逐候选相加；宽网络／保护累积／不同恢复范围不能用anchor单价，CPU、教师缓存、失败及其它共享开销另计。不只统计训练loop；逐层混合未触发不产生该候选拟合／评测费用。

新标准预算按实际任务图核算。令A_c为本类实际不同500步恢复配置集合（含默认对照），U为触发1000步检查的类别集合、|U|≤2；R_c,j(T)和E_c,j分别使用该恢复设置的实测训练／保存成本及一次节点八项成本，不把不同rank／范围／优化器都按默认单价计费。下列满程估算不预扣尚未经校准的短筛节省：

离线与live身份不同，拟合和raw0八项分别计费；恢复参数搜索、长程检查及0步保底的raw0来自已评两份live raw，直接复用。0步保底不取消搜索时已定恢复成本；新增逐层混合已计入20配置上限，实际触发时完整拟合和八项费用照计，不因预留名额而记成0。

```text
离线rate profile拟合      ≤ 3ΣF_off,c
离线rate profile八项      Σ_{c,r∈实际profile} E_profile,c(r)；最多3C个
实际联合码率方案八项      Σ_{p∈实际提案} E_joint,p；两轮各≤4，Q≤8
离线类别VAE搜索           ≤ 20ΣF_off,c；19基础＋1逐层混合，全部固定S2
离线raw完整八项           ≤ 20ΣE_off,c
live配方拟合／raw0        ≤ 2ΣF_live,c + 2ΣE_live,c
恢复参数搜索（含默认）     Σ_c Σ_{j∈A_c} R_c,j(500)；实际短筛按已完成步数计费
条件1000恢复新增          Σ_{c∈U} R_c,selected(1000)；fresh全额另计，不减去500成本
恢复节点完整八项          4Σ_c Σ_{j∈A_c} E_c,j + 8Σ_{c∈U} E_c,selected；已评同身份结果复用
固定CAT参考链             Σ(F_ref,c+R_ref,c+E_ref,c)，已有适用参考证据可扣除
固定recipe的BF16重放      Σ(F_selected,c+R_selected,c+E_selected,c)，不重做离线搜索／节点选择
最终九项                 至少搜索成品、固定参考、BF16重放各1次J；BF16基线另计／复用
末类两端点选品增量        相对上述搜索成品1次J，最多再1次L；两端点八项复用已有分数
逐层混合转置             已含于上述20配置上限；未触发不运行，不转用；首版无整链修订预算
```

当前规则的结构数量上界：C=7且各类均生成1个新的合法混合VAE候选时，离线≤140次拟合／八项，live≤14次拟合，码率粗查≤21次拟合另列，未扣复用拟合合计≤175次；HPO八项≤140、profile八项≤21、joint八项≤8，前置搜索八项合计≤169次，live raw0另≤14次。两份VAE均合法、各类D／P和未来L目标有效、最终选择最大活动组合、已有控制正常复用且不短筛时，首类23条500（范围等价）、中间五类各26条、末类12条（无未来L，粗查仅D／P／D＋P），合计165条500；最多再加2条1000，共167条、84,500次日程更新、676次恢复节点八项。七种组合有适用完整默认控制，原值及范围全开点只计一次；P倍率共享三档通常新增两条，不按整数／scale两轮多计。

以上是已确认候选结构的推算，替代扩展前101条500的估算；P的AdamW参考起点已定为整数0.03／scale 0.001；Muon分别换算及decoder→P→LoRA学习率顺序已确认，GPUh仍待核算与确定。未含失败重跑、必要技术验证、参考链／BF16重放及最终LongBench，不能把更新数当GPUh。未启用组、非法、等价目标和适用结果复用会减少实际运行，不能转用空余名额。旧批准批次的≤23条恢复／≤100次节点八项仅适用于原3C+2和长程替换；另行批准的19点VAE批次也保持自己的上限，不追溯扩额。

<a id="recovery-budget-batches"></a>

**正式恢复预算已确认分两批核算（2026-11-08）：先首类，再按实测讨论其余类别。** 此规则用于新模型正式CAT／恢复搜索，不改变前置profile、joint与离线VAE的既定预算，也不改变已批准旧批次。具体GPUh、资源及期限按本模型另行确认，本文不直接批准实验。

| 批次／交接 | 包含的工作与预算边界 |
| --- | --- |
| 第一批：冻结顺序中的首类 | 先确认首类额度，覆盖至多两份live拟合／raw0八项、两份默认恢复、赢家全部适用参数搜索及每125步的节点八项、触发时的一次1000步检查、必要保存导出和所选接续边界；新路径必要验证一并列费。适用短筛校准按§6完整跑500，不另外增加一套首类训练 |
| 首类完成后的交付 | 汇报完整候选／节点成绩、最终配方与接续checkpoint、各项短筛校准状态、长程名额使用情况，以及拟合、训练、保存导出、评测和必要验证的分项实际GPUh；给出剩余类别预计成本与费用上限建议，再讨论第二批 |
| 第二批：剩余类别与验收 | 确认其额度后，从首类已选真实边界继续严格单主链，完成剩余类别规定搜索及条件长程、末类双端点九项选品、固定参考与BF16重放的必要依赖。已有适用结果复用，不因分批重复首类搜索；最终BF16重放仍独立从原模型开始 |

首类校准只覆盖该类实际适用、至少三份不同候选的搜索项。例如首类的“当前／全部已压缩类别”范围相同，范围轮未发生比较，就保持未校准；后续首次适用时仍按§6全跑500校准，计入第二批，不借用其它轮通过状态。第二批预算结合首类分项实测与后续类别的压缩范围累积、LoRA目标／rank、保护数量、优化器及保存评测差异估算，不能将首类总时长直接乘剩余类别数。未测配置的费用标为估计及其依据，未校准项目不预扣短筛节省。

首类完成后保留具体接续所需checkpoint及其完整状态、来源和结果，按项目规则结束本批；第二批未确认前不派发下一类别。接续继承短筛校准结果、已用的最多两类1000步名额和累计费用，不能因换批或重启清零。上述7类最大活动例中，首类最多23条500及触发时1条1000，即至多12,500次更新／100次恢复节点八项，另计至多两份raw0；剩余六类至多142条500，1000名额按首类实际使用扣除。这是原整链数量的分批拆分，不增加候选；仅有一个类别的模型无第二类别批次，末类验收随首批计入。

每批启动前锁定该批GPUh；第二批预算先预留剩余类别两份入围的默认恢复、末类两端点LB、参考九项及BF16重放费用。已有完整八项不重复计入J的执行成本，按实际缺失依赖收费。剩余预算不足以完成一个候选全部依赖时，不启动该候选；保留已验证控制，记录覆盖不足并讨论下一批，不把预算到期当质量负例，也不自动删减已确认搜索项。


固定参考使用来源／配方／数据／终点明确的原流程，适用已有完整结果可复用；若与新流程同时改变HPO、类别顺序和选点，差值只归于整套流程，不单独归因排序或某项超参。单类账本以完整投影inventory为共同分母，同时报本类费用及含其余dense的partial费用，不能因CLI只选一类就换分母。

缓存键至少绑定模型／父UUID与权重身份、完整resolved配置、数据／模板／token与顺序、种子／初始化、代码及消费者版本。仅同一适用身份复用；上游变化后不可借旧live后缀或旧父相关输入。独立候选并行，同一链先后依赖严格顺序；用既有tmux/nohup记录，不建守护／自动重试体系。

## 11. 验证顺序与完成条件

1. **规范审定／实现**：冻结候选库、生成顺序、数据、预算和指标；完成配置、账本、候选缓存、best-node接续。本文不等于这些代码已完成。
2. **最小真实pilot**：复用稳定父，只在一类验证几何／optimizer筛选及真实保存回训／完整导出。与当前已确认批次分别计预算，不自动扩大。
3. **接续与恢复搜索适配**：确认离线→live配方迁移、两份raw默认恢复选唯一调参对象、§6活动参数搜索与节点完整状态导出、首类到第二批的自身live接续；补0步严格胜出／同分留恢复的选择逻辑及真实零恢复边界。不引入第三VAE拟合或双后缀质量链。不声称离线召回或易→难贪心已证最优。
4. **完整新模型搜索**：执行冻结的逐参数表、20配置上限及逐层混合；正式链按§9先首类、后剩余类别两批推进，按恢复参数搜索、已校准短筛及条件长程检查选点接续，末类双端点完成LongBench九项选品，交付配置、完整九项及账本。预算／覆盖不足如实标记。
5. **固定recipe从BF16重放**：冻结搜索所得每类超参、原schedule_max及selected_step，不重做HPO／重新挑节点；从BF16重建全部依赖，不使用历史donor。保持原日程时域，在预定selected_step停止并导出，省去搜索时已舍弃的尾段；不能把max改成selected_step重缩LR日程。选中0时仍做本类live VAE拟合／压缩，跳过KD更新后建立§7真实类别边界，R_selected,c仅含必要边界／导出成本。各用途独立随机流保证下一类不依赖被省略尾段的RNG。R_selected,c按实际选中步点计费、不超过该轨迹完整上限费用；新增停止／导出及零恢复路径需补对应最小验证。只重放已选成品，不为末类再训练两份或重新按LB选品。复现入口与模型身份绑定，正常浮点差异按既有规则处理。它验证配方可重现，不替代另一模型重新运行搜索规则的迁移验证。
6. **跨系列迁移**：选择另一实际支持且已确认用于验证的模型，重算inventory、tokenizer／模板映射、合法几何、输入统计、真实owner／κ及预算；标准不把8B或某个系列写成必要条件。参数取值可变，搜索规则／候选数量／选点指标保持；变更规则必须注明新版本，不能称原算法直接迁移成功。

每批结束汇报结果、成本、取舍与剩余未决项，再讨论下一批。单seed结果只支持当前条件下的比较；本标准直接按完整八项选优，不自动增加近分种子复验，也不把固定recipe重放扩成搜索复验网格。

交付记录至少包含：协议版本、模型／tokenizer／数据／代码身份、完整resolved候选与覆盖状态、实际GPUh、每类基准对照记录及离线第一／第二名的配置与来源、d_c／KL及冻结顺序、live父与两份raw、每条KD设置／schedule_max／节点原始指标、selected_step及完整mutable或raw来源、finalize后边界、末类两端点S8／LB／S9及选择依据、最终九项与三种存储口径、固定recipe重放入口。不新建重复流水或以计划状态代替实验结果。
