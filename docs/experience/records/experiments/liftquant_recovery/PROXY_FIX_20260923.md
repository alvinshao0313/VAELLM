# 编码代理冻结问题的修复

目标是解除原先“在完整训练预算内不可能翻码”的结构性限制，保持原初始化硬码、VAE decoder、位宽和 checkpoint 格式不变。解除限制不等于已经证明下游恢复有效。

## 方法

对每个已有压缩 Linear，从真实码中固定等距抽取256行，逐个翻转全部64个 bit，使用原生 BF16 packed decoder 测量输出变化。将所有行、bit 和输出维度的均方变化开方，得到一个正尺度 s；训练过程中固定 s。

训练代理和硬码定义为：

\[
p_0=s(b_0-\tfrac12),\qquad
b(p)=\operatorname{clamp}(\operatorname{round}(p/s+\tfrac12),0,1).
\]

初始化时 p 为 −s/2 或 +s/2，硬码与原 checkpoint 完全相同。反向使用 round STE 加 clamp 的饱和门控，并明确乘以链式因子1/s。所有代理和 Adam 状态仍为 FP32。学习率规则为 min(2e-5, actual_proxy.std()/50)，取实际优化变量的 std。

从优化角度看，这是依据 decoder 敏感度重新设定码空间的相对学习率：在 Adam 归一化后，码坐标中的有效步长约为 lr_p/s。它是明确的 VAE 适配，不是“换个写法就免费改善”，也不是官方 FWT 的严格等价变换。

仅放大梯度往往被 Adam 的归一化抵消；仅将0/1平移到−0.5/+0.5也不改变到阈值的距离。这里同时定义坐标、硬前向和反向，使实际相对步长发生可记录的改变。

尺度只存在于训练 runtime 和审计日志，不是新增可学习 scale，不改变模型推理结构或额外 checkpoint payload。代码没有强制翻转配额、随机翻码、稀疏选 bit 或新增训练损失。

## 已完成的验证

在 GPU4、bitvae 环境，对 block9/10 共14个真实 Linear 完成小规模 CUDA 检查：

- 初始 packed bits 和 decoder 输出严格不变。
- 含1/s及饱和门控的第一层 STE 与独立 dense autograd 比较通过，包括边界和 round-to-even 规则。
- 完整 decoder 的前向与独立参考逐元素相同，全部编码梯度逐元素相同。
- decoder 参数梯度最大相对L2误差约1.47e-8。
- s 实测约0.00456–0.00613，因此初始距阈值约0.00228–0.00306；对应码空间有效学习率约0.00326–0.00439。原来为2e-5。
- 使用样本代理std得到的学习率均为2e-5；真实 block 训练会重新用完整代理计算std并记录预算界。
- 量化器的标量回归中，固定同一优化目标、AdamW和3968步调度：旧0/1配置始终不翻码，新尺度对应约115–154步首次翻码。该测试只证明机制具有可达性，不是实际语言模型的恢复成绩。
