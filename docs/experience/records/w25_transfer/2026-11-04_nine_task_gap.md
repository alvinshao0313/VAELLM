# 当前四个完整端点的九项缺口分解

本记录只分析已闭合的Qwen3-8B结果，不是新增训练／评测批次。问题是当前压缩流程离九项目标还差多少，单独修复MMLU／LongBench是否足以覆盖损失，以及综合增益包含哪些任务取舍。由Astra/ultra只读核证，root归并；执行仍以[唯一计划](current_plan.md)为准。

## 范围与复算方法

- C0、D16与D32 VAE-Muon后接原Adam500属于同C0家族；D16与MuV是两个配方，不能把二者差拆成单一机制。C1 full_teacher来自另一压缩父，只作独立候选质量参照，不把其对C0的差归因于一个变量。它们不是全部历史模型的排行榜。
- 四份原件均为各自同一最终UUID的完整八项64叶／24742题和LongBench v1完整21项／4750条，0-shot／limitNone、同BF16与原任务指标；已有独立fresh／终态闭合证据有效。D16采用成功的CPU技术闭合，原评测父超时事实保留。
- 使用原下游小数及21项未舍入LB分数做Fraction算术，四份`mean_drop_points_exact`均完全一致；九项显示值重算最大差为7.1e−15。未重扫预测、重验源码pins或运行评分／GPU验证。
- 正式验收为九项未舍入均分严格大于67.14714491790848，即对同协议BF16的68.04714491790848下降严格小于0.9pp；logical≤2.6，MMLU无单独门槛。本组rank0是候选条件，不升为总目标限制。
- 记每项`drop=BF16−候选`，其九项净损失贡献为`drop/9`。正负项全部保留，LB分值为21任务宏均，不称统一准确率。以下表格的舍入仅用于展示，计算使用原件。
