# Qwen3 8B 极低比特压缩达到八任务均分 69 的方案与实验证据

只想了解改了什么和最快复现步骤，可先读[简版说明](2026-10-04_qwen3_8b_69_quickstart.md)或[简版HTML](2026-10-04_qwen3_8b_69_quickstart.html)。

本材料面向第一次接触 VAELLM 项目的读者，说明模型压缩了什么、每个模块怎样设置、如何训练恢复精度、平均位宽如何计算，以及哪些尝试确实改善了指标、哪些在已测条件下没有改善。整理日期为 2026-10-04，讨论范围是已完成的原“投影权重平均位宽不超过 2.5 bit、八任务均分达到 69%”目标。

**已验证的交付结果为：Qwen3-8B 在完整八任务、0-shot 评测下，均分 69.3129801840%，被压缩投影权重的实际存储为 2.4569887908 bit/weight，成品无外置 LoRA。** 模型来自最后一轮训练的第 1200 步。该轮后来完成 2000 步，但 1600 和 2000 步的结果都更低，因此交付的是独立保留的第 1200 步模型。

### 实际评测条件

使用本机 `lm-eval 0.4.8`，全部任务为 0-shot、无 `limit`，总计 24742 题。评测采用标准题目及候选答案的因果语言模型似然，不套聊天模板，不运行思考链生成。`acc` 按候选答案似然判断；本机版本的 `acc_norm` 将候选的对数似然按候选字符串字符数归一化后判断。它们是不同指标，表中固定采用的指标不能随候选更换。

实际 batch 为 MMLU 64、其余任务 32。使用 fast tokenizer，类名为 `Qwen2TokenizerFast`；模型通过 v6 strict 路径独立加载，按 group size 8 将全部 252 个投影预热为 BF16 解码缓存。未启用 HiFloat4 激活量化。这些 batch 数是独立评测进程的实测值，不是训练脚本里 `eval_batch_size=auto` 的字面值。

该成品跳过了 PPL 评测，因此没有本成品的困惑度结论，也没有由此次验收证明的长上下文、生成质量或吞吐提升。后续 MMLU≥65%、均分≥69.5% 及 LongBench 是另一个阶段，见[新阶段记录](../w25_transfer/2026-10-04_mmlu65_llama31.md)。

## 模型结构和需要压缩的对象

原模型为本地 `/home/star/models/Qwen/Qwen3-8B`，对应 `Qwen/Qwen3-8B` 固定 revision `b968826d9c46dd6066d109eabc6255188de91218`。五个 safetensors 分片已在实验输入准备时校验官方权重哈希，证据见[模型来源](../../../../result/qwen3_8b_w25_20260930/model_source.json)。

模型有 36 个 Transformer 层，隐藏维度 4096，MLP 中间维度 12288，32 个 query heads 和 8 个 key/value heads。每层有七个主要线性投影，共 36×7=252 个压缩目标。输入输出矩阵的形状以下表的“输出维度×输入维度”为准。

| 类别 | 单矩阵形状 | 36层原始权重数 | 主码bit | INT8保护输入列 | 实际类别bpw |
| --- | --- | ---: | ---: | ---: | ---: |
| `q_proj` | 4096×4096 | 603,979,776 | 2 | 64 | 2.114349365 |
| `k_proj` | 1024×4096 | 150,994,944 | 2 | 64 | 2.170288086 |
| `v_proj` | 1024×4096 | 150,994,944 | 2 | 64 | 2.170288086 |
| `o_proj` | 4096×4096 | 603,979,776 | 3 | 64 | 3.102630615 |
| `gate_proj` | 12288×4096 | 1,811,939,328 | 2 | 64 | 2.101918538 |
| `up_proj` | 12288×4096 | 1,811,939,328 | 2 | 64 | 2.101918538 |
| `down_proj` | 4096×12288 | 1,811,939,328 | 3 | 256 | 3.113911947 |
| **合计** | **252个投影** | **6,945,767,424** | 按权重数加权 | 共117,964,800个保护权重 | **2.456988791** |

注意力的 q/k/v 将输入转换成 query、key、value；o 将注意力输出映射回隐藏空间。MLP 的 gate/up 将隐藏表示扩展，经过门控后由 down 投影回 4096 维。down 的输入维度较大，因此本方案给它更多保护通道。

embedding 将词编号转换成向量，lm_head 将最后的向量转换成词表分数。这两大矩阵保留 BF16，模型内原有的 RMSNorm 等参数也保留。压缩范围不包括 KV cache 或激活值量化。

本材料中的BF16是16位浮点数，FP32是32位浮点数，INT8是8位整数；bit/weight（简称bpw）表示每个原始权重平均需要多少存储位。一个byte等于8 bit，GiB按2的30次方字节计算，GB按10的9次方字节计算。参数保存精度、训练计算精度、运行时缓存精度可以不同。

## 压缩模块怎样表示权重

### 用二进制编码和小网络保存一组权重

CAT 是本项目的逐类别压缩流程。每次选一类投影，例如所有层的 q_proj，为各矩阵分别训练权重自编码器。训练时将一组权重输入 encoder，得到二进制编码，再由一个小 decoder 重建这组权重；部署时只保存打包编码和 decoder，encoder 不进入成品。

这里代码中虽然使用 VAE 命名，当前配置的核心是 BSQ 二值球面量化和权重重构。本文不会把模型级教师蒸馏的 KL 损失误称为传统高斯 VAE 的潜变量 KL 正则。

关键变量的含义如下。

| 参数 | 含义 | 达标成品 |
| --- | --- | --- |
| D，即 `codebook_dim` | 一个向量中要重建的权重个数 | 所有类别 32 |
| K，即 `codebook_bits` | 每个向量、每个残差 stage 的二进制位数 | 普通类别 32；o/down 为 48 |
| S，即 `residual_stages` | 逐次拟合残差的级数 | 所有类别 2 |
| H，即 `base_ch` | 小 decoder 的隐藏宽度 | 128 |
| R，即 `num_res_blocks` | decoder 内部额外残差块数 | 0 |
| decoder 类型 | `symmetric`，采用对应自编码器结构 | K→128→32 |
| 归一化与激活 | decoder 内部 LayerNorm 和 Swish | 全部相同 |
| 成品 decoder 精度 | 实际落盘的数据类型 | BF16，每参数 16 bit |

单个 stage 的 decoder 执行 `Linear(K,128) → LayerNorm(128) → Swish → Linear(128,32)`。两 stage 各有独立参数；所有层、所有投影也各有独立参数。`linear_group_size=36` 表示把 36 个独立自编码器放在一个训练组内并行计算，不表示 36 层共享一个 decoder。

两级残差重构可简写为：第一级拟合向量 v，第二级拟合 `v−第一级输出`，最终相加。每个 32 维向量使用两组 K 位，所以主编码名义码率为 `S×K/D`。K=32 时为 2 bit/weight，K=48 时为 3 bit/weight。这里不是每个标量直接在 4 个或 8 个固定数值中选一个，而是一个 32 维向量联合用二进制串和小网络表示；也不保存一个具有 2^K 项的显式巨大查找表。

BSQ 训练使用连续潜变量、符号量化和直通梯度；部署把符号转换成 0/1，并按 8 位打包到 uint8。BSQ 的归一化符号尺度在部署 decoder 第一层中融合，因此后续代码读取的 0/1 与训练时的正负符号表示对应。

### 重要输入通道保护和权重旋转

保护通道指对每个矩阵选出少量重要输入列，不让它们进入极低比特主编码，而用 INT8 保存。本成品每层每类独立选通道，普通投影保护 64 个输入通道，down 保护 256 个；它们分别为 D 的 2 倍和 8 倍。

排序指标是 `channel_weight_actmean_abs`：输入列j的分数为 `mean(|x_j|) × sqrt(sum_i W_ij²)`，同时考虑激活平均绝对值和该列权重的L2范数。激活统计来自 Alpaca 连续打包的512个块，每块256 token，总计131072 token，seed31；不是512篇各自截断的独立文档。采用 `channel_scope=layer`、`channel_axis=input`、`channel_mlp_rank_metric=none`，不做跨 MLP 的联合通道排序；`channel_refresh_after_category=false`，类别间不重新刷新保护统计。

保护数据包含 INT8 权重、BF16 scale 和 int64 原输入通道索引；这些全部计入位宽。存储容器可能显示 uint8，但数值语义为有符号 INT8。该方案没有另外保存一份逐通道 zero-point 张量。

非保护部分使用 block size 32 的双侧 Hadamard 权重旋转，并保存两侧随机正负符号。旋转用于改变权重表示坐标，降低极端分布对编码的压力；反向变换恢复到线性层原始坐标。Hadamard 矩阵由规则生成，不完整保存稠密旋转矩阵。这里借用了旋转这一思路，不能称为完整复现其他论文的整套算法。

权重归一化、通道抽取、转置和旋转的实际顺序及元数据处理见后面的位宽细节；最终推理重建时会恢复相应结构。达标方案沿用 block32，并没有采用其他纯 CAT 对照中得分更高的 D16/block64 结构。

## 从原模型到达标模型的训练过程

### 第一阶段 逐类别压缩并在每类后恢复

类别顺序固定为 `q_proj → k_proj → v_proj → o_proj → gate_proj → up_proj → down_proj`。每类覆盖 36 层，每个残差 stage 重构训练 10000 步，采用每个独立自编码器8192个权重向量的batch、AdamW、学习率0.003、weight decay0、线性学习率衰减、无warmup，seed/data_seed为31。36个模型分组时输入约为`[8192,36,32]`，不能把8192理解为36层合计的向量数。

重构损失采用 MSE。`l1_weight=1` 是历史参数名，不意味着本次使用 L1 重构；另有 `lfq_weight=2.5`、commitment 权重 0.25、entropy 权重 0.01，`gamma0=gamma=zeta=1`、`inv_temperature=100`。这些约束用于训练二进制表示，不是最终八任务评价函数。

按本次36模型组的实现，实际标量目标可写为 `36×[MSE+2.5×(0.25×commitment+0.01/100×(H_sample−H_batch))]`。commitment约束连续表示接近硬符号，熵项兼顾单样本确定性与整个batch的编码利用率。日志中的`train/commitment_loss`包含这部分完整辅助项，不能只按名称把它理解成纯commitment。这里涉及的BSQ潜变量归一化，与权重残差标准化、decoder LayerNorm、保护INT8 scale各有用途，不是同一个scale。

每压缩完一类，运行 500 步模型级蒸馏恢复：已经压缩的前缀类别训练 decoder，尚未压缩的 dense 类别训练临时 LoRA。临时 LoRA 为 rank12、alpha24、dropout0.1，学习率 1e-4；decoder 学习率 1e-5。随后将 LoRA 融入尚未压缩的 dense 权重，再继续压缩下一类别。因此“成品无外置 LoRA”与“训练中曾使用 LoRA”同时成立。最后 down 压缩完已无剩余 dense 类别，仍执行前缀 decoder 恢复。

LoRA是一种用两个较小的低秩矩阵表示权重修正量的方法。rank12限制修正的中间维度，alpha控制缩放；融合是把该修正量直接加回原权重。此处它用于压缩过程的临时补偿，之后权重还会进入压缩，不意味着成品额外保存rank12分支。蒸馏中的教师始终是原模型，学生是正在压缩恢复的模型。

该阶段每类恢复 batch4、累积1、最大长度1024、SFT、BF16计算、FP32可训练 decoder/LoRA、AdamW、cosine、warmup1%、梯度裁剪1.5。损失为教师 Top100 mass-KL，温度1，prompt权重0.3，不加 hidden 或 pre-MLP hidden 辅助损失。七类各500步，合计3500步模型级恢复；它与自编码器的“每stage10000步”是两个不同的训练循环。

训练数据按样本来源抽样：`ii_7M 34.1% + ii_gen 6.7% + tulu 2.8% + am 6.4% + 任务数据50%`。这是抽源概率，不是 token 数或梯度贡献比例。该阶段固定64/32复评得到 **66.5762388504%**，见[原始验收](../../../../result/qwen3_8b_w25_20260930/remaining_prefix_block32_s500/eval_batch64_32/acceptance.json)。历史16/16评测曾得66.54992965%，不能把换batch后的差值算成训练收益。

完整配置见[实际 CAT 解析配置](../../../../result/qwen3_8b_w25_20260930/remaining_prefix_block32_s500/home_star_models_Qwen_Qwen3-8B_20261001_143107/normalized_cat_runtime_args.json)；[CAT 脚本](../../../../scripts/cat_w25_remaining.sh)为可读入口。应读取 `resolved_category_runtime` 的最终类别值，不能将配置模板里的默认 K/D/S 当作实际类别参数。

### 第二阶段 全模型 decoder 恢复并选取不同类别

从上面的同一成品分别训练两条 2000 步 decoder-only 分支，硬编码保持不变，其他模型权重冻结。

| 分支 | 损失和数据 | 末步完整均分 | 对最终模型的作用 |
| --- | --- | ---: | --- |
| CE10 | 0.1×CE + 0.9×mass-KL；task50；prompt0.3 | 66.44208228% | 提供 MLP 三类 decoder |
| CE50 | 0.5×CE + 0.5×mass-KL；task100；prompt0 | 66.89468320% | 提供 attention 四类 decoder |

### 第三阶段 提取注意力恢复和第一层 down 的互补结果

从67.13033275%的共同起点并行产生两条来源。

其一进行全模型 decoder-only 恢复：task50、纯mass-KL、prompt0.3，2000步，所有硬码冻结。整模型终点为67.03170248%，低于起点；但只取其144个attention投影、保留起点MLP，组合得67.64180413%。这说明“整模型训练分支没有净增益”不等于其中所有类别都无用。

## 损失函数和码位更新的含义

教师蒸馏要求压缩模型在同样输入上尽量接近原模型的下一个token分布。CE则要求压缩模型给训练答案较高概率。最后一轮把二者结合：

代码中的`alpha`是KL项权重，通式为`L=(1−alpha)×CE+alpha×KL_mass`。因此CE10设alpha0.9，CE50设alpha0.5；它与临时LoRA的alpha24是不同参数。

```text
L = 0.5 × CE(response) + 0.5 × KL_mass(response)

KL_mass = Σ[top100] p_teacher(i) log[p_teacher(i)/p_student(i)]
          + p_teacher(other) log[p_teacher(other)/p_student(other)]
```

Top100按教师分布选取，保留它们相对于完整词表的概率质量；剩余词的总质量合成一个桶。它与只对Top100重新归一化后计算KL不同。prompt和padding不参与最后一轮的有效损失，response token在整个micro-batch内按有效token数归一化，不是先对每道题求均值再平均。系数0.5也不表示CE和KL贡献了相同大小的梯度。实现见[模型级损失](../../../../train_utils/distill_loss_core.py)。

离散0/1不能直接像普通浮点参数一样微分，训练为每个位维护连续score，用score的正负决定硬码，反向使用直通估计获得更新方向；推理仍保存并使用打包硬码。`decoder_sensitivity`通过抽取码向量、逐位翻转并测量decoder输出变化，给每个码库确定一个训练坐标尺度。它不增加成品参数，score和Adam状态不属于部署模型。实现见[敏感度校准](../../../../litebsq/bit_sensitivity.py)、[训练坐标](../../../../sparse_bit_tuning/coordinates.py)和[码位管理](../../../../sparse_bit_tuning/manager.py)。

换轮会将当前硬码提交到持久存储，并重新建立连续score与优化器状态；512是本轮配置的最大轮长，不能简单当成“每512步重新压缩模型”。第1200步审计记录为round2、轮内step176，与两次完整512步边界相符。

## 平均位宽的完整计算

### 主编码码率和实际平均位宽不同

主码“2 bit或3 bit”只描述未保护权重的编码量。真正部署还要保存decoder、保护列和辅助张量。最终验收按这些张量的实际存储字节计数，再除以全部原始目标投影权重数。

```text
原始投影参数数N
= 36 × (4096×4096 + 1024×4096 + 1024×4096 + 4096×4096
        + 12288×4096 + 12288×4096 + 4096×12288)
= 6,945,767,424

平均位宽 = 252个投影的全部必要部署存储bit之和 / N
```

保护权重仍属于原始权重，不能从分母剔除；各矩阵按原始参数量加权，不能对七类模块的位宽直接算简单平均。MLP矩阵比k/v大得多，其位宽对模型平均的影响也更大。

### 从单个矩阵推导六项开销

设矩阵输出维度O、输入维度I，保护C个输入列，向量长D、码长K、stage数S、decoder隐藏宽H。本成品D=32、S=2、H=128。

```text
主码bit          = O×(I−C)×S×K/D
decoder bit      = 16×S×[H×(K+D+3)+D]
INT8保护权重bit  = 8×O×C
INT64通道索引bit = 64×C
BF16保护scalebit = 16×C
INT8旋转符号bit  = 8×[O+(I−C)]

该矩阵bpw = 上述六项之和 / (O×I)
```

decoder参数公式包括第一线性层 `KH+H`、LayerNorm的`2H`、第二线性层`HD+D`。K32时每stage8608参数；K48时每stage10656参数。所有504个stage decoder共4633344参数，即74133504 bit。成品把每个投影的两个stage按相同字段并行存储，共1512个decoder张量；张量合并不代表stage共享参数。

以一层down_proj为例：O4096、I12288、C256，非保护权重49283072个。六项分别为147849216、340992、8388608、16384、4096、129024 bit，总计156728320 bit；除以原50331648个权重，得到 **3.1139119466 bpw**。down单类超过2.5 bit与全体加权平均低于2.5 bit并不矛盾。

### scale 旋转与标准化是否漏算

实际处理顺序为：在原始坐标选保护输入列并抽出 → 对剩余矩阵做双侧block32 Hadamard → 按类别转置并切成32维向量 → 逐stage标准化及残差重构。转置类别是q/v/o/down；k/gate/up不转置。转置改变向量里相邻权重的分组方向，不改变保护的输入轴。

每个stage对该投影当前残差整体计算均值μ和`σ=max(std,1e-6)`，并训练`(残差−μ)/σ`。部署时将σ和μ融合进decoder最后线性层；符号到0/1的尺度融合进第一线性层。因此主码不另存逐向量scale或zero-point，它们的相应数值作用已经由decoder参数体现。

INT8保护列则确实单独保存scale：每输入列`scale=BF16(max(abs(该列))/127)`，全零列使用1；按该scale舍入并裁剪后保存INT8值，zero-point隐式为0。保护scale及原通道索引已在账本中单列。随机旋转符号虽只有±1两个值，当前实现实际使用int8，每个占8 bit，也已按实际开销计入。

推理时两个stage解码结果相加，重排并撤销转置、逆旋转，再把INT8保护列放回原索引位置。实现依据见[保护通道量化](../../../../litebsq/protected_channel_quant.py)、[CAT训练流程](../../../../train_utils/cat_train_pipeline.py)、[权重旋转](../../../../rotation/weight_preprocess.py)和[VAELinear重建](../../../../litebsq/vae_linear.py)。

## 有效果和没有效果的对照实验

这些实验回答的是“在什么条件下有用”，而不是给某类算法永久贴上有效或无效的标签。下表的分数均指八任务等权平均准确率，单位为百分数；变化量使用**百分点**，例如 63%→64% 是提高 1 个百分点。展示值保留六位小数，计算和验收使用原始未舍入值。除明确标注为历史结果、局部诊断或未完成观察外，表中结果均来自完整 24,742 题的独立成品评估，没有用训练损失或少量题目代替完整指标。

为便于阅读，先说明本节缩写。`D` 是每个被编码权重向量的维度，`K` 是每个向量、每个残差阶段的编码位数，`S` 是残差阶段数，因此名义主码位宽为 `S×K/D`；`H` 是小型权重解码器的隐藏宽度。这里的 **decoder** 是重建压缩权重的小网络，不是整个语言模型的 Transformer 解码层。`q/k/v/o` 是注意力的四类投影，`gate/up/down` 是前馈网络（MLP）的三类投影；`L0` 是编号从 0 开始的第一个 Transformer 层。MSE 是均方误差，KL 是学生与教师输出分布的差异，CE 是对真实答案的交叉熵，KD 指知识蒸馏。**MSE/KL 更低只说明相应训练目标改善，不能直接换算成八任务准确率更高。**

## 可直接用于口头汇报的说明

我们的目标是在Qwen3-8B的主要Transformer投影上，把实际权重存储控制在平均2.5 bit以内，同时让固定八项下游任务平均分超过69%。最终达到的是69.313%，投影存储2.457 bit，完整模型权重文件约4.625 GB。

压缩表示有三部分：大多数权重以两级二进制向量编码保存，小型BF16 decoder负责重建；少量重要输入通道保留INT8；再保存恢复旋转所需的符号和索引等辅助信息。q/k/v/gate/up主编码是2 bit，o/down是3 bit，但我们报告的2.457已经计入decoder和保护开销。

精度恢复经历了多级训练。先按七类逐次压缩，每次用教师蒸馏更新已压缩decoder，并临时补偿尚未压缩的dense层；临时LoRA会融合，不留在成品里。再从不同损失配方中组合较好的attention与MLP类别。最后从67.805%的组合模型出发，只训练第一层down的decoder和二进制码，在1200步达到69.313%。

比较实验说明，增加位宽、加宽decoder、延长训练或训练更多码位都不保证提升。有些改动改善了局部重构误差，却降低了完整下游均分；有些整模型分支略退步，但取其中attention类别反而有价值。因此本次结论依赖实际保存模型的完整评测，而不是只看训练loss。69.313%是这条组合路线的实测成绩；各部分独立贡献仍有尚未完成的严格消融，尤其不能把最后1.508个百分点全部说成码位翻转的单独贡献。
