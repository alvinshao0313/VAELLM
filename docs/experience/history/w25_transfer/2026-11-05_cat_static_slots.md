# CAT固定槽搜索旧稿：来源与替代关系

归档日期：2026-11-05。来源是主协议原§3.2、§5及离线执行规范原§5。它们曾描述7＋2几何、仅容量／保护叠加、BSQ替槽、全类别等待后再提名层组等安排，现已被用户确认的逐参数标准取代；文中“已确认”“当前”“待审”仅保留当时语境，不能用来启动新标准实验。

当前规则以[主协议](../../../sc_cat_protocol.md#sequential-search)和[执行规范](../../../sc_cat_execution.md#5-搜索推进的状态机)为准：保护→转置及条件分层→旋转→D→encoder→decoder→优化器→学习率，每类最多20个配置，全部固定S2、完整八项选优。另一批已单独批准的19点顺序实验不是本旧槽图，仍按[当前计划](../../records/w25_transfer/current_plan.md)记录的冻结条件执行，归档不改变其预算、源码或运行状态。

以下保留原文以追溯旧提案和实现对应关系，不升级其确认或证据状态。

## 原主协议的条件参数安排

### 3.2 条件参数库：保留4槽编号、1槽空置，另1槽确认交互

原条件四槽编号16–19保持：第16槽因固定S2而空置；第17槽encoder256；第18槽默认decoder256，触发已审定BSQ规则时由一次BSQ对照替换；第19槽保留保护比例比较，最多3个新增配置。先做真实几何／费用检查；非法项空置，不占第16槽、不临时换成其它变量。**BSQ阈值及系数增减方向仍是待审草案；替换decoder加宽并保留保护比较已确认**，不能因此提前执行未审触发器。

| 变量 | 候选范围 | 确定性生成／触发规则 |
| --- | --- | --- |
| residual stages | 固定S2 | 第16槽空置，不生成拟合／八项任务，不按非法或复用假装已测；替代用途须另行讨论 |
| encoder宽度 | 128→256，decoder固定 | 第17槽；只改一侧，实际网络须为支持独立宽度的asymmetric |
| decoder宽度 | 128→256，encoder固定 | 第18槽默认；无BSQ触发时执行，不因encoder胜出就取消；被BSQ替换时记本轮未覆盖，不称加宽无益 |
| 保护数量 | 输入INT8；起点目标p=1/64，先试p=1/32，费用不容纳时改试0 | 第19槽独立保留。正比例按联合合法count中最接近p×轴宽者、同距取较小者映射；拟合前预测超B_c才转0，仍只拟合一个不同配置。取消保护须真实count全0；若该几何不支持0则不适用，不映射成正count冒充取消。增加点重复则复用／空置，不因质量较差或拟合后超cap追加0比例第二臂 |
| BSQ有效系数 | 已选先将过强项减半；无过强迹象才考虑码分布项加倍；具体字段／判据待审 | 占第18槽并替换decoder256，绑定当时已接受基底诊断。强分支检查在弱分支之前，不因偏码而加倍commitment。旧10／0.1、偏置bit>10%及commitment优先等条件未确认，不自动运行；保留原训练归约，不同时搜lfq与其内乘系数，不改训练梯度／RNG |

旧稿的“BSQ占保护槽、输出保护轴再替换另槽”不再作为本轮队列。首版仍按输入保护执行；输出轴没有本轮名额，记录未覆盖，若另行研究再讨论预算与配方。

保护误差分解不能直接推断数量的收益；因此v0采用预定邻点探索，最终实际拟合并做联合读出，不人工看图决定是否开臂。

**诊断来源已确认：** 入容量段冻结判定规则，到第18槽时从当前已接受配置的真实诊断生成BSQ提案。若第17槽encoder加宽被接受，使用新基底自身诊断；否则继续绑定原基底。记录诊断候选ID、resolved配置及原统计引用，不能沿用加宽前统计冒充当前基底。必需诊断缺失先按执行规范补证据／处理依赖，不自动复用别的结构、不新加诊断拟合或借第16空槽；读取已有正式候选诊断不增加拟合名额。具体阈值、系数方向仍待确认，不预先固定字段／方向。

**一次对照的单位：** 每个类别最多新增一套BSQ配置，在同一BF16父上fresh完成S2两stage各10K、部署及完整八项，再与当前基底比较；不代表只训练一步或全模型只给一次。减半／加倍是可提名方向，不在同一类别把所有系数和两个方向全展开；不因一套效果差再追加另一套。此为有界名额安排，不保证BSQ最优。

**BSQ诊断语义待审：** 现`observe_bsq`的偏码指标来自跨层pool的软概率，其温度／K缩放和层间抵消可能掩盖实际硬码恒定；不能称为各层部署码利用率。另`entropy_loss_weight`会同时放大单样本熵和全批熵两项，只增强码分布均衡对应`gamma`；两种提案不能互换。方向策略已确认，具体统计口径及增强字段须说明后再选，不以旧源码默认替用户决定。

第20槽优先按§8作层组组合；未提名时按§5用另一保留几何核查已接受条件组合，无条件赢家也保留optimizer／倍率交互兜底。无适用合法候选则空置，重复配置复用。normalize_weight、内部norm、R1／activation替换、FP8保护等固定为后续独立结构研究；数值非有限先修实现／输入，不靠切换算法掩盖。INT4保护、双轴保护、异D原生bank、LFQ不属于现成候选。

初轮固定：重构MSE、quantizer BSQ、new_quant、VAE betas／WD／warmup／日程、内部norm／activation、INT8格式、数据／教师／KL目标、top100／T1／prompt.3、未来dense LoRA rank12／alpha24／dropout.1／LR1e-4，以及norm/head／额外残差分支关闭。它们仍在记录中，不是被搜索后证明最优。


## 原主协议的固定槽搜索

## 5. 已确认的均衡联合20槽分配

本节沿用20槽编号，实际最多19个候选，均以原始BF16为根、只压当前类别；因全局identity变化而分叉时使用显式受控fork，不伪称exact resume。生成顺序、非法／受阻原因、重复复用、已完成及未覆盖都落记录。正式链只从此库迁移最多2个配方，按§2.1在live重拟合。

下面沿用第三轮确认的20槽编号，并合入最新固定S2选择：第16槽空置，当前实际配置上限19。旧窄范围的7个几何单变量槽，宽化后需要11个才能逐水平比较，因此改为覆盖式联合搜索；水平出现不等于全部交互被覆盖。

| 槽 | 已确认用途 | 最大新增数 |
| --- | --- | ---: |
| 1–7 | anchor＋6个预定均衡联合几何，优先覆盖合法rotation／D水平及两个transpose方向 | 7 |
| 8–9 | 两个局部几何组合确认，预先定义选择规则；不是看单改都赢才开放 | 2 |
| 10–11 | 保留两个不同几何，各比较另一VAE optimizer | 2 |
| 12–15 | 围绕当前最佳几何／optimizer，比较.25／.5／2／4实际更新倍率 | 4 |
| 16 | 固定S2，原S4槽空置；不自动分配给其它变量 | 0 |
| 17–19 | 按条件表优先顺序，最多3个配置；只在此段逐项采纳并叠加 | 3 |
| 20 | 层组提名优先；否则当前配置×另一保留几何，包含无容量赢家时的optimizer／倍率交互兜底 | 1 |

以下分段质量选择现按已确认v0.2使用完整八项；候选生成的未审细节仍须按§0确认。每段后继等该段已宣布合法候选八项齐备才生成，不按GPU先完成者提前晋级；不同类别可独立推进：

1. 枚举合法的transpose×rotation×D，先区分数学非法与实现受阻，再按类别cap过滤；候选ID由父身份及canonical配置生成。固定枚举为False/True、none/32/64/128/256/full、D升序，hash绑定搜索seed／类别／配置，不依赖运行顺序。
2. 前7覆盖优先已确认，包含anchor，各配置统一原AdamW、1×。覆盖对象是过滤后可运行池中每个T／rotation／D取值；求含anchor且覆盖全部取值的最少几何集合，同样数量按固定hash字典序取一解。少于7时按到已选集合的最小几何Hamming距离最大、各轴取值出现次数平方和最小、固定hash顺序补足；7个不能全覆盖时，在至多7点内最大化覆盖数并显式列遗漏。若不同合法点不足7则只测现有点，不复制填满。多因素同时变动只作配方比较，不作单因素归因。
3. 前7全部八项完成后，固定其八项赢家为两局部点共同基底，按已确认顺序扫描：先唯一T翻转，再D=8/16/32/64/128升序（剔除当前D），最后rotation=none/32/64/128/256/full（剔除当前值）。每点只改一个几何参数，D变化联动K／B；跳过已测／重复／非法／超cap点，取最先可用的两点，分别fresh完整拟合及八项。第9槽不继承第8槽的结果；不足两点则空置，不改扫描顺序、不由KL挑点。
4. 前9中按完整八项选最佳几何及最佳不同几何进入optimizer对照；各自改为Muon，得到第10–11槽，两点均评完整八项。只有一个合法不同几何时仅开一份，另一槽空置，不制造重复对照。前11中按完整八项选几何／optimizer作为倍率基底，第12–15槽各改.25/.5/2/4，1×复用，四个点均评完整八项。
5. 前15中按完整八项选容量段初始基底，已评分数直接复用；第16槽空置，第17 encoder256→第18 decoder256或BSQ→第19保护比例按顺序比较。每项只改当前配置的该项，完整八项严格提高才更新；同分仅logical／packed费用字典序降低时采纳，仍同分保留原配置。第19先试增保护，仅拟合前预算不容纳时改试0；不能因增保护质量不好就再跑0。未获改善则保留配置进入下一项；技术失败按执行规范处理。BSQ触发及系数方向待审，入段冻结规则，到第18槽才用当前基底诊断生成提案；不提前固定方向或按结果无限加候选。
6. 第20槽若入选§8层组条件则使用该组合；否则将完整已接受容量／保护改动集合放到另一保留几何上，沿本段基底optimizer／实际倍率并重推K／batch。没有接受任何容量／保护改动时，仍将前15选中的optimizer／实际倍率放到另一保留几何核查交互，其余条件沿用容量段基底。它是重新拟合的新组合，不拼不同来源decoder权重；配置已测则匹配复用，不新增拟合／八项端点，冲突、超cap或无另一几何时空置。无容量赢家不再单独构成空置理由。

上述质量排序统一按`(-S8,logical费用,packed费用,候选ID)`，使用未舍入完整八项；第20槽“另一几何”也沿同一八项排序，从已保留且不同于条件基底者中选，不留隐藏KL分支。初始化及采样各用按模型／类别／stage／用途派生的独立随机流；同形状配对共享相应种子，结构变更不声称逐位初态相同。VAE init／shuffle、LoRA init、KD dropout／数据流均不依赖评测、候选并行顺序或上一类跑满500后的全局RNG，固定recipe重放沿同一派生规则。

两个保留几何须不同；全部候选固定S2，两stage各完整10K，不再有S4额外曝光。2K／5K只顺带记录，不作硬淘汰依据，不需要没有通用状态的VAE中途续跑。

每个完整拟合候选均完成真实部署／fresh及完整八项，另记录W误差、对应父上的输入输出误差、固定512 KL、分域／分层变化、存储和GPUh。离线父为BF16，正式确认父为P_c；KL按原抽样与总有效token权重归约作诊断，不重复乘源权重，不以它或局部MSE提前筛除候选。完整执行与结果映射按[执行规范S0–S13](../../../sc_cat_execution.md#5-搜索推进的状态机)。

**v0.2完整覆盖：** 每类所有已入列且完整拟合有效的不同配置均评八项，含anchor、前15、条件17–19及实际第20槽，最多19个端点；第16槽按用户固定S2明确空置，不产生虚拟分数。相同完整身份复用，不重复评测。旧“容量5＋终端6−共享1≤10”和末端覆盖抽样退出，此前两份关键复核不额外叠加。评测失败／不完整不能当低分或改用KL晋级，按失败规则补依赖／讨论预算。最终从全部有效端点中按未舍入八项选冠军。各类相对同一BF16评分用于§2.1排序；live raw属于不同前缀，只在同父内比较。

只在容量／保护段叠加，不采用全面分块回访。每个候选绑定该阶段的同一父并fresh完整拟合；继承超参设置，不把赢家多训10K的收益算成新超参效果。几何或宽度叠加后重新检查合法性、峰值资源与类别bits cap，S始终为2；按最终resolved配置计费，不沿用独立单变量单价。重复／非法点不转成任意新变量，按已分配槽或预算上限结束，第16保持空置，不临时加回访轮。

## 5. 搜索推进的状态机

以下S0–S13槽图保留旧实现映射，须按已确认标准顺序和20配置上限改写，不能直接作为新标准的完整执行表。已有19端点检查属于其已验实现范围，不因文档增额就宣称已支持条件分层。

下表是控制器必须实现的逻辑状态，不把现有worker的`completed`改名或解释为整阶段完成。每次决策都将输入证据／生成参数／槽ID／结果引用／实际费用写回同一持久槽表；生成完先冻结，再分发，不能根据不同GPU完成先后重抽候选。

S0–S13是执行状态编号，与残差阶数S=2分开。20槽是原搜索编号，第16槽已按用户固定S2选择关闭且无拟合／评测任务；当前最多19个实际候选，不因保留第20槽名称就宣称执行了20份拟合。

每次晋级在**同一状态记录内**保留下列内容，不另建一份决定日志。字段是控制器的逻辑要求，不冒充现有CLI的输出schema：

| 决策内容 | 代理必须能回答的问题 |
| --- | --- |
| 规则及输入快照 | 本次属于哪个S状态／类别，采用哪条已确认规则、哪个父／cap／共同评测身份；仍待确认的规则不能填作默认值 |

| 比较计算 | 原精度S8及logical／packed费用、实际破同分键；容量段同时记录改动前后完整配置与采纳／不采纳原因，不由模型文字判断代替计算 |
