## BlockLDLQ的完整输出、缓存与全模型结果

原专题：[输出损失：先校准数值尺度，保留真实目标](../output_losses.md#blockldlq的完整输出缓存与全模型结果)。

2026-10-03，用户批准的新有限邻域BlockLDLQ在固定4b6的L27/down（非转置D16K24/S2/H128、block64、input INT8保护256）通过真实完整单层验证。只改硬码，每向量当前+两个stage各24个单bit邻居，共49候选；两stage联合解码，完整训练Hessian、保护固定误差交叉补偿、相对阻尼.01、752块逆序反馈。512 Alpaca训练文档/64已用于选择的公共dev（74773/9183 tokens，max256）上，反馈off/on的原生BF16输出dev MSE相对初值分别降低14.0523%/26.6265%；保持decoder/保护/旋转固定、完整3423张量保存fresh及2.455285114bpw。初始和选中码的stage隔离oracle对生产联合decoder全层实测一致。它支持按原协议扩展36down，不证明下游收益或普遍优于STE；这是49邻域近似，并非QuIP#的精确E8P最近点量化/理论保证。核心CPU反例明确表明每块候选分数下降不保证完整H目标单调，必须同时报告完整proxy、原生train/dev和最终八任务。写packed banks后须重建parallel grouped bank；只清decoded cache会继续解码旧码。[提案、单层完整证据和后续全模型状态](../../history/qwen3_w25/2026-09-30_10-04_research_log.md)的19:40记录及block_ldlq_l27。

同日扩36down后，两臂36/36层公共dev原生误差均改善，off/on逐层after/before比例平均.8472/.6813；完整固定64/32八任务却仅63.83972757/63.83909699%，低于同源4b6的64.14388457%，实际位宽不变。72码bank以外3351张量冻结、全部3423保存/fresh以及完整64叶24742题均核验，不能把该负结果推给未保存新码或缩减评测。只支持本次有限邻域、原HF前缀输入分布与一次更新未形成下游增益，未识别具体因果；暂不将更低局部输出损失作为继续扩展的充分理由。首轮漏带已验证allocator环境导致OOM，恢复`expandable_segments:True`后保持同batch完整通过，失败日志另留，不伪装成首轮成功。[双臂原始指标及恢复环境的记录](../../history/qwen3_w25/2026-09-30_10-04_research_log.md)的20:15记录。

## 适配后选码：排名反转不等于选择规则更好（2026-10-09核实）

原专题：[编码恢复：先验证阈值可达性和真实数值路径](../liftquant_recovery.md#适配后选码排名反转不等于选择规则更好2026-10-09核实)。

**证据。** 完整顺序6dad、固定中点L18 gate、相同BF16部署路径，在原码及三个合法硬码候选上各从同一decoder适配8步。即时dev排名选λ0.25，适配后选λ0；确认集两者KL差仅+0.00004961，配对文档bootstrap区间跨0。10月9日补齐原码连续32步控制，与四臂合计更新次数及token曝光相同；两组新码D8相对原码D32的确认KL仍低约0.00209/0.00214，文档配对区间不跨0，但NLL点值略差且区间跨0。原码D32也优于原码D8。因此不能把局部KL收益全归为额外更新预算，同时仍不支持新的适配后排序优于即时排序，不能推论九项提升。连续Adam与四次fresh Adam不同，整体耗时亦不同，不称等墙钟对照。

**动作与边界。** 候选要从相同完整父状态、optimizer初态及批序出发，原码也接受等量适配；选择与确认分开。比较选码算法需计入所有候选内层更新及提案/评分成本，不能仅比较最终选中臂与原码同T步。确认集看过后不得再称新盲测；单个结构中点不是“已发现敏感层”。码与decoder须成对保存/验证，局部pair重载不等于完整v6成品；诊断收尾后按具体用途决定是否保留权重。四臂与原码T32控制的配置、置信区间和终态见[唯一结果记录](../../history/w25_transfer/2026-10-04_29_research_log.md#10月9日中断后终态核实与完整九项收束)。

## 固定码拟合、STE与真实离散邻居

原专题：[编码恢复：先验证阈值可达性和真实数值路径](../liftquant_recovery.md#固定码拟合ste与真实离散邻居)。

2026-10-05补充纯权重目标的隔离短测：两模型L0 gate/down在原生每stage2000步后，固定硬码追加500步双stage共同拟合，FP32 decoder/Adam与BF16计算均真实更新。原坐标权重NMSE相对仅改善约.025%–.038%，而gate留出MLP输出误差约改善4.15%/4.24%，down仅.25%/.12%。权重与非线性输出误差的变化幅度不同，不能只看权重loss判定局部输出完全无益，也不能由局部输出改善认定完整下游受益。该结果是额外预算、L0、单seed、固定码原型，未正式接入；下一项完整权重目标的decoder/全码联合配对须保持同计算路径和预算。[实际语义、四例结果及原件](../../history/w25_transfer/2026-10-04_29_research_log.md#固定码的双级decoder联合权重重建短测)。

紧接着，在两模型L0 gate的完整权重、无文本随机batch目标下，matched decoder-only与100%码位联合各500步对照仍出现退化：joint原坐标权重NMSE为控制的约1.647/1.690倍，留出MLP误差约2.331/2.517倍。两组初值相同，首翻前loss及完整decoder梯度exact；首翻更新101/51，之后累计约28.07亿/41.08亿次翻转，均无换轮。原生packed更新/commit和保存契约通过，故不能只用文本梯度噪声、下游代理不一致或round重置解释这一条件的失败。它没有确定LR或STE的唯一因果，也不否定之前其他来源的正结果。下一步应对比离散单bit邻居的真实损失差与代理方向，避免仅靠加步数或净XOR来判断。[完整目标、配对轨迹及局部边界](../../history/w25_transfer/2026-10-04_29_research_log.md#完整权重目标的冻结码与全码位配对)。

同日两模型相同L0 gate初值的精确64邻居诊断显示，约48.88%/49.52%的D32块存在真正改善权重SSE的单bit翻转。全部有益候选的初始STE预测为负，但负预测中只有约2.02%/2.06%实际有益；每块直接选最负预测时约74.3%真实变差。因此局部导数可指向下降而完整离散步仍过大，不能把预测负向、跨阈值或更多翻码直接当作收益，也不能据此认定梯度实现反向。接受真实改善的一次翻转后，两模型权重误差约降2.3%、留出linear误差下降，但gate的SiLU×up→down误差分别增加2.51%/3.67%，64个测量文档均变差。单层权重目标和非线性输出目标仍需分开；此次仅隔离原型，没有正式集成依据。[完整有限邻域、数值路径及保存复算](../../history/w25_transfer/2026-10-04_29_research_log.md#单bit真实邻域与代理梯度的配对诊断)。

进一步用真实有限解码位移分解SSE变化后，两模型约98.2%的“STE负预测但实际变差”候选仍有负交叉项，只是位移平方项更大；按每块最负STE所选的有害候选全部如此。该只读测量的旧符号计数完全复现，FP64与旧FP32残差的符号分歧为0。这支持有限步代价是本邻域的主要障碍，但真实有限位移并非decoder Jacobian，不能由它单独判定非线性或优化器的唯一因果。四节点观测还显示，改码后的SiLU输出仍改善，首次退化出现在乘固定原up后；增量约98%来自逐通道中心化误差，而非均值项。因此不能把本例简化成SiLU本身或遗漏bias的问题，也不能用真实权重SSE下降替代输出验收。原始分解与三臂正控仍见同一结果小节。

## 旋转支持集、BF16评分与输出接受

原专题：[编码恢复：先验证阈值可达性和真实数值路径](../liftquant_recovery.md#旋转支持集bf16评分与输出接受)。

同日L18局部支持集核验：D32/block32双侧旋转下，单个压缩向量通常影响32个原输出通道和32个未保护输入列，保护列补集须映射回原坐标。未舍入逆旋转的rank1扰动，在两BF16端点分别恢复后相减不再保证rank1；因此输出评分不能只更新单输出通道，或把inverse(delta)直接加到旧舍入权重。局部Gram公式对未舍入down线性输出成立，但原生BF16 gate/down重算可能改变微小损失差的符号。CPU反例确认这些边界，不证明既有质量退化由舍入导致；纯FP64下不同up通道权重也足以反转“权重改善→MLP改善”。[实际坐标、公式验证及后续隔离诊断](../../history/w25_transfer/2026-10-04_29_research_log.md#l18离散改码的输出目标与局部支持集)。

实际GPU16个预定旧MSE赢家补充：16项权重误差都改善，完整BF16 MLP仅9项改善、7项变差。局部Gram代理符号14/16、排序96/120，换成完整native deltaA仍未修复排序；局部BF16 gate加完整形状down在该样本符号/排序全对，但数值非exact。故有原生重算条件时，应以实际输出损失接受改码，不能把公式代数正确等同于BF16评分准确，或用16项一致性宣称通用可靠。该诊断无训练、码位逐项恢复，也未证明完整下游收益。另SSE差的展开必须与已有指标使用同样的两端FP32残差定义：先分别减目标再升double，不能混用直接输出差；本次已修正这一诊断计算错误，未放宽容限。[真实16项及失败修正证据](../../history/w25_transfer/2026-10-04_29_research_log.md#l18离散改码的输出目标与局部支持集)。

后续384个固定输出块顺序短测仅以完整train32 BF16 MLP SSE严格下降接受旧权重赢家的分组提案，保留201组/710919bit；训练误差下降约1.04%，已有heldout/replay分别下降约.74%/.62%，两者31/32文档改善。它的权重误差仍高于全体权重赢家，但三组输出均更好，支持输出目标不匹配的局部解释。训练单调由接受规则保证，复验集已被看过；这既不证明通用泛化，也不等于全模型下游提升。新码后续与原码采用同500步decoder拟合预算，须额外计入搜索/接受成本；新算法未正式集成。[384组完整结果、保存及边界](../../history/w25_transfer/2026-10-04_29_research_log.md#l18离散改码的输出目标与局部支持集)。

## 选码后的decoder适配与跨层反例

原专题：[编码恢复：先验证阈值可达性和真实数值路径](../liftquant_recovery.md#选码后的decoder适配与跨层反例)。

随后的匹配500步decoder拟合又给出了正面边界：从同初始decoder开始，固定exact64新码而非原码，Qwen/Llama L0 gate留出MLP误差比原码decoder500降低3.90%/2.53%，均32/32文档改善；原权重NMSE各改善约2.35%/2.37%，训练码位完全冻结、保存状态核验通过。码位选择与decoder适配应合起来验收，不能用“刚改码时MLP更差”否定后续拟合，也不能用本首层正结果跳过跨层、新文档和完整任务确认。双方decoder更新预算相同，候选额外有一次邻域搜索成本；仅隔离原型，未证明一般最优或正式下游收益。完整两臂与三种参照仍见同一结果小节。

预定中层及新32文档随后补充了实际反例：L0两模型MLP收益在新文档仍为4.21%/2.69%，Llama L16为2.96%，但Qwen L18的MLP误差增加1.86%，旧32训练/32留出同向恶化；所有层的weight/linear指标仍改善，原始中层基线完全复现。不能由首层正结果将同一纯权重选码+拟合方案推广所有gate，也不能将差异只归因确认文档变化。中层四节点复核显示，SiLU仍改善，首次恶化仍在乘原up；损害先出现在搜索，decoder500对各自初值的四节点都改善，只是新码臂未补完。下一步应区分拟合预算与权重目标不匹配输出目标两种解释；短测并未证明全量下游收益。此前新32已参与此后的诊断，继续使用时应明确是已看过的复验集。证据仍见上述同一结果小节。

匹配fresh2000线性时域的后续对照已完成：Qwen L18新码/原码的旧heldout与复验MLP比分别1.02534/1.02169，原坐标权重比.97699，增加预算并未补回输出损失。它从同native2k重新训练，前500的学习率也变化，不能称旧500精确续训；只否定此具体加长配方，不将其外推为所有decoder预算已充分。原码与新码各自相对旧500的复验误差仅约−.16%/+.14%，继续纯加步数缺少此处实证支持。保存/冻结与缓存复核通过，完整数值及复现入口仍见同一结果小节。

## 条件MLP目标与完整已恢复背景

原专题：[编码恢复：先验证阈值可达性和真实数值路径](../liftquant_recovery.md#条件mlp目标与完整已恢复背景)。

## 枚举空间、真实KL接受与固定权重精度参照

原专题：[编码恢复：先验证阈值可达性和真实数值路径](../liftquant_recovery.md#枚举空间真实kl接受与固定权重精度参照)。
