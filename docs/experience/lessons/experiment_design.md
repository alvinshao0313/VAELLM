# 对照设计：先对齐条件，再解释增益

## 问题与证据

- 残差 LoRA 对照曾误选 40 步、limit16 的 smoke_B，其损失、dropout 和预热也不同；后改为用户指定的普通 LoRA 基线。有效八任务对照在 step2000 仅 +0.1152 个百分点，不能据此宣布达到 69+ 或稳定显著提升。[记录](../records/docs/exp_results/residual_lora_ab_20260923.md)
- 独立 down_proj 的蒸馏前基线为 67.93%，全类压缩基线为 54.51%，两者不是同一模型状态。早期前缀/独立类别比较还混有 rank、steps、训练对象和数据比例差异，不能把全部分差归因于一个开关。[down_proj](../records/docs/down_proj_recovery_experiments.md)、[前缀对照](../records/docs/cat_distill_prefix_vs_independent.md)

## 下次怎么做

1. 实验前固定初始 checkpoint/版本、压缩与训练范围、数据与 token 预算、seed、实际 LR 序列、精度、任务集、shot、limit、metric 和聚合方式；只改变研究变量。
2. 复用口径匹配的历史基线，不用冒烟替代正式基线。若历史运行存在恢复、不同种子或非确定性，写清局限。
3. 修改 max_steps 时检查实际 LR，而非只看参数名。本组用2001步取得step2000评测，同时保留原5000步余弦前段；这是特定回调行为，不是所有训练都该用2001步。
4. 新增 hidden loss 后分量分别记录，总 loss 不再和旧总 loss 直接比较。
5. 先报告最终部署状态/全压状态的指标，再解释中间单类指标。分数百分比与差值百分点分别标注。
6. 方案里列明已查经验、避免重犯的方法和不一致条件；再次尝试失败路线要有新变量或待检验机制。

## 边界

上述记录是单次或有限配置实验。独立类别的历史失败提供风险信号，不证明该方法在所有联合恢复策略下必然失败；统计显著性也不能由一次小幅均分上涨替代。本次整理没有重跑基线或验证当前代码的回调行为。
