# 动态RVQ与INT8通道＋稀疏残差的同预算对照

用户希望比较vector自适应残差与当前INT8重要通道＋稀疏残差保护的精度。此前L0原型只与固定两阶＋INT8对照，不能回答这个问题；本实验直接比较三种附加补偿方案，限定单层局部误差，尚不代表完整模型下游准确率。

## 公平条件

- 同一fresh-HF Qwen3-8B L0 down固定两阶源，原完整文件19,607,424 B，D32／K48／H128／R0、transpose、双侧block32、256个INT8保护列。保留同一原始HF目标、保护值、索引、scale和几何。
- `sparse_abs005`完整保留fixed2，在HF与实际部署BF16权重的差值上使用原生abs0.5%选择；保护列先设为相同。实际选251,659元素、768个256²块，使用两个UINT8局部坐标、UINT8值、UINT16块号、INT32指针及FP32 scale／zero，先解码为BF16再按原生顺序累加。
- `unweighted_dynamic3`与`weighted_dynamic3`使用同一既有真实第三阶码本，允许向量在1–3阶重分配；不再训练。加权臂只用前64篇train文档估计激活二阶矩；后64篇只读出。全部128篇此前已见，不称盲测。
- 共同上限为`fixed2完整bytes + 稀疏实际payload bytes`。稀疏实际payload为765,733 B，完整cap为 **20,373,157 B**。三臂均计16 KiB头、全部持久字段和实际载荷；动态只计实际三个decoder，不虚列不存在的第四decoder。最多四轮预算更新，取最后可行轮，不作质量网格。
- 每臂披露实际bytes和未用预算，以相同上限比较，不把少量剩余字节称为逐字节相等。第三阶已有额外训练历史，不能称等训练算力。

真实bestabs成品已恢复，其INT8值、scale及主码／decoder和fresh原型不同，因此不直接用本次局部结果与其九项排名。完整模型优势需要相同完整模型起点、相同恢复数据／范围／预算和完整九项评测。

三个完整文件的该Linear实测平均位宽分别为3.238226096／3.238156954／3.238225460 bit，包含头部、码、decoder、保护、标签或稀疏索引／scale等全部字段。它不是全模型平均位宽；未来完整模型仍须单独审计≤2.6。两动态臂不是等训练量比较，因为复用了额外训练的第三阶；三臂均沿预定选择规则，未根据读出择优。未加权四轮中第4轮超预算11 B，选第3轮；加权第4轮可行且后续预算不变，选第4轮。

共同fixed2源、native稀疏语义、所有持久字段／路由／保护值、同路径BF16前缀及源哈希均已通过。这给出了当前fresh L0、这一codec和共同存储上限下的局部正例；尚无完整模型MMLU、LongBench或九项优势证据，也不能直接与恢复后的bestabs模型排名。
