## 问题、目标与证据边界

在同一个全压缩四阶S4模型上，比较全部投影decoder恢复与仅attention decoder恢复。已有两轮累计链中v／o后恢复偏正、gate／down后偏负，但每段更新整个已压缩前缀，父状态、步数和数据曝光亦不同，不能据此认定某类权重本身无法恢复。本批固定父、数据及优化条件，只改变恢复参数范围；经验和原结果见[同父恢复经验](../../docs/experience/lessons/kd_and_data.md#同父恢复须同时看完整净收益与能力代价2026-10-30)、[此前同父诊断](../s4_down_recovery_diagnosis_20261104/README.md)。

首批固定两条64步，末点评完整八项，随后退出并汇报讨论；不自动延长128、不运行LongBench、不启动MLP-only、alpha、自适应KL或数据权重网格。64步八项仅作本配方筛选，不能认定恢复上限或最终质量达标。

第一阶段最终目标保持：同协议BF16九项68.04714491790848%、MMLU10251／14042；候选九项必须严格大于67.64714491790848%、MMLU至少10111／14042。此S4约4bit研究不采用另一条SC-CAT／S2／约2.5bit标准的验收门槛。最终入选完整流程须从原BF16重放，局部恢复收益不能拼成整链结论。

## 隔离实现与验证要求

仅修改本包及本批必要测试，不修改仍被其它正式实验依赖的旧包／CLI。沿用原生加载、packed decoder、冻结权重物化、数据和评测消费者；新增本包需要的范围、终止步数和显式续训状态配置。本批正式请求固定64步，没有自动研究后继、重试、监控或占卡。

attention臂只在物化冻结MLP权重时使用普通`no_grad`；MLP实际前向不能被`no_grad`或`inference_mode`包住，否则会截断早层attention的梯度。范围切换初始数值差异须量化，正常BF16／归约差异不扩大为全链逐位一致要求。

保存64步FP32 masters、Adam moments／step、CPU／CUDA RNG、参数名称和稳定顺序、数据游标、父及数据／源码绑定。`next_group_index=64`；后续只有讨论确认后才显式恢复，不重置Adam或日程。训练进程退出后，由新进程从原父及持久化状态重建、导出BF16模型，再fresh读回及完整八项；不是只保存旧实现中的评测快照。

必要验证与停止边界：

1. CPU核实际父、同输入／目标／顺序、范围集合、实际64组曝光、配置64停止和无LongBench后继。

3. 检查早／中／晚attention梯度及FP32、BF16更新；冻结MLP、packed codes及完整冻结补集精确不变。
